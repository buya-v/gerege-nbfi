The guard ADMITTED a shell that then produced the fabricated "no Go toolchain" diagnosis
and EXIT 2 — the exact defect class T81 was dispatched to close.

Mechanism, isolated:
  $ cat rprobe.sh
    if ! ( eval "…< <(printf %s \"\")" ) >/dev/null 2>&1; then echo GUARD-WOULD-FIRE; else echo GUARD-ADMITS; fi
  $ /bin/bash -r rprobe.sh
    rprobe.sh: line 1: /dev/null: restricted: cannot redirect output
    GUARD-ADMITS
The `>/dev/null` redirection is refused, so the inner command NEVER RUNS, yet the
compound's status is 0 and `! 0` is false. The probe is a negative test ("no error
occurred"), so an environment that prevents the probe from executing reads as success.

A POSITIVE-EVIDENCE probe closes it, but it is NOT a one-liner to get right — my first
attempt falsely refused plain bash because `printf %s ok` emits no trailing newline and
`while read` therefore never runs the loop body. The corrected form, measured:

  elif [ "$( ( eval 'while read -r _p; do printf %s "$_p"; done < <(printf "conformance-psub-ok\n")' ) 2>/dev/null )" \
         != "conformance-psub-ok" ]; then
