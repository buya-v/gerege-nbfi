A CORRECTION TO MY OWN FIRST HYPOTHESIS, recorded because it changes what the repair must be.

I first predicted that a glob character ALONE would defeat both tests, on the reasoning that
`[1]` as a wildmatch pattern matches the single character `1` and therefore cannot match the
literal filename `zz-t384e[1].sh`, leaving `member_stat` EMPTY -- which would skip the symlink
refusal (`member_mode` != 120000) AND the blob test (guarded by `[ -n "$member_blob" ]`).

THAT PREDICTION IS WRONG, AND ARM E IS THE ARM THAT SAYS SO. git's pathspec matcher tries
EXACT LITERAL EQUALITY BEFORE it tries wildmatch, so a glob-named path always matches itself:

  arm E  member `zz-t384e[1].sh`, witness a COPY of it   -> exit 2, BYTE-IDENTICAL   REFUSED
  arm F  member `zz-t384f[1].sh` IS a symlink            -> exit 2, IS A SYMLINK     REFUSED
                                                            symlink-members=1

So one glob character is NOT enough. The reachable construction is the one T375's own
disclosure names: make the pathspec match MORE THAN ONE tracked path, and the first line wins.
Arms E and F are kept as the controls that establish that -- without them the finding would be
"a glob character breaks it", which is false.
