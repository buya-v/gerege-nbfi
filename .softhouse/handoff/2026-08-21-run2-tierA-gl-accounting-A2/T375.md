### 4. FU-T358-1 / C-T364-4 — the bar now records a wall-clock cost per guard, with a ceiling that REFUSES

`run_guards` routes **every** guard through a new `timed_guard`, and a new `guard_cost_census`

**THE INSTRUMENT'S FIRST TWO RUNS ALREADY FOUND TWO WRONG COST CLAIMS** [VERIFIED: my own runs,
`evidence/01-after-edits-run1.txt` and `evidence/02-bar-AFTER-git-add.txt`]:

* `guard_reconciler_ownership` measures **41 s** and **31 s** on two back-to-back runs, against
  the **30.3 s** its comment had claimed since T323;
* `guard_pnumber_citations` measures **21 s** and **19 s** and **had no cost claim at all** — it
  is the second most expensive guard in the function and no reader of this file could have known.

**WHAT IS PINNED AND WHAT IS NOT — this is the flakiness constraint T358 raised, taken as the
first design constraint rather than as an afterthought.** The elapsed seconds are **RECORDED and
NEVER PINNED**: a wall-clock figure is a statement about the host as much as the tree, and a bar
that reddens because somebody else's build was running is a bar that gets bypassed — the same
failure the ceiling exists to prevent. What is pinned, **by NAME, the way every other frontier in
this file is pinned**:

* every guard run through `run_guards` **has a ceiling row** — an unbudgeted guard REFUSES;
* every ceiling row **was actually timed** — a stale row REFUSES, the same shape the DECLARATION
  TABLE already refuses for a subject that has left the population;
* **at least one guard was timed** — an empty census passes everything.

**Ceilings derived by a stated rule, not chosen:** `budget = max(60, 10 × measured)`, rounded up.
Ten times because the defect class is an **unbounded spin** (583 s against an advertised 0.23 s, a
factor of ~2500), not a 30 % regression; a floor of 60 s because every sub-second guard would
otherwise have a budget inside the clock's resolution. `guard_ledger_invariants` is the one
exception and it is disclosed: it measures 2 s on a **warm** Go build cache, so its ceiling is set
for the cold case.

**THE HONEST LIMIT, STATED IN THE INSTRUMENT ITSELF AND NOT ONLY HERE.** It does **not** interrupt
a running guard. A guard is a shell function that must run in *this* shell — `timeout`, a
background subshell or a command substitution would break the `exit` that
`guard_graded_root_is_this_tree` takes and would discard every `failed=1` the others set — so
elapsed time is read **after** the guard returns. **A guard that never returns still hangs the bar
forever. What changes is that a spin which DOES return is now a named refusal with a measured cost
instead of a silent PASS that only a watching human ever caught.** Bounding a non-returning guard
needs a subprocess architecture this function does not have; it is a follow-up below, not smuggled
in here.

**Resolution is one second**, from bash's `SECONDS`. `EPOCHREALTIME` is bash 5 only (this host's
`/bin/bash` is 3.2) and its value carries a decimal point that would have to be taken apart in a
file whose no-float guards read every line. A `0` means "under one second" and the census says so.
