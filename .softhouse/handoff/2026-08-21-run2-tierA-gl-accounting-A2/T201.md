### 2.3 The design decision, and the alternative rejected

**DECIDED: refuse outright, exit 2, before any other guard runs.**

The decisive fact — established here, not assumed — is that under this script the override can
**never** be legitimate. `build_binary` compiles `CMD_PKG` from `$NEXUS_DIR = $REPO_ROOT/nexus`
(line 973) with **no `-trimpath`**, so `runtime.Caller`'s anchor always lands inside `$REPO_ROOT`.
Measured on the clean baseline report:

```
    repo root       /Users/buv/…/agent-af79e99b661a45f86
                    resolved from the BUILD ANCHOR — the tree this binary was compiled from
                    anchor: /Users/buv/…/agent-af79e99b661a45f86/nexus/internal/apps/…/reporoot.go
```

Anchor == `$REPO_ROOT`, always. So the env var's **only** available effect under this harness is to
point grading away from the tree the guards just inspected. **Refusing it forfeits no capability**:
an operator who wants another tree graded runs *that tree's* `.softhouse/conformance.sh`, which then
guards what it grades.

**REJECTED ALTERNATIVE — accept-and-report with a non-zero exit.** Rejected on three counts:

1. **There is no honest exit code for it.** `1` is this file's GRADED FAIL — "a mismatch or a
   violated property invariant, a definite reproducible defect". An automation reading `1` would
   open a defect against the *Go port* when the fault is the *invocation*. `2` is what a failed HARD
   guard already returns and does mean "no verdict available" — but "grade it anyway, then exit 2"
   still emits a full `parity vectors PASS 43` table over a foreign tree, and **T165 already proved
   empirically that a banner standing next to those numbers does not stop them being read as parity
   evidence.** Repeating a failed remedy at a different exit code is not a fix.
2. **It mixes evidence from two trees.** `run_guards` inspects `$REPO_ROOT`'s vectors, capture rigs,
   Java sources and Go sources; the binary would grade the *other* checkout's corpus and contract.
   No reader can afterwards attribute a cell to a tree.
3. **The stated test — what an automation that reads only the exit code learns.** On refusal it
   learns *"this run produced nothing"*, which is true. On accept-and-report it learns *"43 vectors
   were compared and something was wrong"* — **false in both halves**: 43 vectors of a tree nobody
   asked about were compared, and what was "wrong" was not a vector.

**Secondary decision: SHORT-CIRCUIT rather than joining the `failed=1` tally.** Driven red first:
with the guard merely tallying, the refusal was measured printing **first** but then buried under
eleven lines of green guard output and census figures — the same "true statement present, summary
taken instead" shape T165 lost to. `run_guards` now exits immediately, so a diverged run prints
**eleven lines and nothing else**. The tally style exists so one bad guard cannot hide another;
here the divergence subsumes every downstream result, so there is nothing to hide.

**Exit 2 cannot be misread as an oracle outage.** The guard runs *before* `probe_oracle`, so the
`reference oracle (…) probe = up|down` line is **ABSENT**, not `down`. Measured:

```
$ LC_ALL=C /usr/bin/grep -ac 'probe = ' /tmp/T201-A-red2.txt   -> 0
```

The driver parks only on `exit 2` **AND** a probe line **present and reading `down`**. This is the
fifth member of the pre-probe exit-2 family already documented at lines 745-747, and it is
documented as such in the guard's header.

**`--prove` is guarded too.** `prove()` does not call `run_guards`, but it does `build_binary` and
then runs that binary, which resolves its root from the same env var. Guarding only `main_grade`
would have converted a known hole into a hidden one — the exact mistake the census block at line
780 records ("fixing only the census one would have converted a known hole into a hidden one").

**No DEC-1 or `contract.go` change was needed.** The fix is entirely in `.softhouse/conformance.sh`;
`reporoot.go` is untouched — its precedence is arguably right *for a general-purpose binary*, and the
harness is the layer that knows the override can never be legitimate. No `user` gate is raised.

## 3. (B) The greedy census extraction — polarity established first

### 3.1 The shipped expression

`.softhouse/conformance.sh:853` (pre-fix), quoted by extraction:

```sh
ins_all="$(printf '%s\n' "$out" | LC_ALL=C sed -n 's/^CENSUS .*inspected \([0-9][0-9]*\).*$/\1/p')"
```

The leading `.*` is greedy: it runs to end-of-line and backtracks, so the capture lands on the
**LAST** `inspected N` on the line, not the first.

### 3.2 POLARITY — ESTABLISHED BEFORE THE FIX, AS REQUIRED

T197 recorded the polarity as **unknown**. It is now measured. Six synthetic lines, `printf`-fed,
one per line, through `LC_ALL=C /usr/bin/sed -n` (BSD sed):

| # | line | subject count | OLD reads | direction |
|---|---|---|---|---|
| 1 | `CENSUS wire-float … inspected 320 request bodies / 3976 numeric tokens across 6 capture rigs / 10 req directories under /x/…` (**live line**) | 320 | 320 | correct — latent |
| 2 | `CENSUS narrow-catch — inspected 57 .java files across 20 directories under /x …` (**live line**) | 57 | 57 | correct — latent |
| 3 | `CENSUS ascending — inspected 7 rigs / inspected 320 tokens` | **7** | **320** | **FAIL-OPEN** |
| 4 | `CENSUS descending — inspected 320 bodies / inspected 7 rigs` | **320** | **7** | FAIL-CLOSED |
| 5 | `CENSUS pathword — inspected 57 .java files under /x/inspected 0 fixtures/repo (recursive)` | **57** | **0** | FAIL-CLOSED |
| 6 | `CENSUS no-figure — nothing was counted here` | none | (nothing) | correct |

**Written statement of the polarity.** The figure feeds `[ "$inspected" -lt "$floor" ]`,
refuse-if-below. The direction is therefore decided by **which of the two figures on the line is
bigger**, and both directions are reachable:

- **Trailing figure LARGER → FAIL-OPEN, SILENT PASS.** Case 3. A guard that opened 7 of 320 files
  clears a floor of 320 because an unrelated `320` sits later on the same line. The census — the
  machinery built by T173/T184/T194 specifically to refuse a guard that inspected nothing — hands
  back a number that is not the subject count and the run reports **VERDICT: PASS**. **This is the
  direction that matters.**
- **Trailing figure SMALLER → FAIL-CLOSED, cry wolf, exit 2 over a clean tree.** Cases 4 and 5.
  Loud, and case 5 needs **no code change at all** to fire: the census line interpolates an absolute
  path today (`… under /Users/buv/gerege-nbfi/.claude/worktrees/agent-af79e99b661a45f86 …`), so a
  checkout directory containing the token `inspected 0` is sufficient.

**So the honest answer to "which way does it fail" is: both, and the choice is made by the PROSE of
a census line that no test constrains.** The fail-open direction is one appended sub-count away —
rewording the live wire-float line to `inspected 320 request bodies / inspected 3976 numeric tokens`
would make a stub census reading `inspected 0 request bodies / inspected 3976 tokens` clear a floor
of 320. It is latent today only because every census line currently carries exactly **one**
`inspected N`; both live figures (320, 57) are read correctly by the old expression, which is
precisely why it survived.

### 3.3 The fix

Extraction factored out of `_run_capture_guard` into `census_inspected()` so it can be driven from
`--prove`; an extraction buried inside a guard is an extraction nothing can falsify.

```sh
census_inspected() {
  LC_ALL=C sed -n '/^CENSUS .*inspected [0-9]/{
s/inspected \([0-9][0-9]*\).*$/\1/
s/^.*[^0-9]//
p
}'
}
```

**Why it is first-wins.** `s///` without `g` rewrites the **leftmost** match, and dropping the
leading `.*` leaves nothing to backtrack over: the pattern must begin at an `inspected ` that is
actually followed by a digit, and the leftmost such position is the first one. `.*$` then eats the
rest of the line; `s/^.*[^0-9]//` (greedy, to the last **non**-digit) strips the surviving prefix —
`[^0-9]` rather than a space so a prefix like `…/inspected` with no trailing space still resolves.
The address keeps a CENSUS line carrying no `inspected N` producing **nothing** (not `0`, which
would be P-35's vacuous pass arriving through the front door).

P-57: `sed` consumes all of stdin and never exits early — not a member of the `| grep -q` / `| head`
EPIPE family. P-58: `LC_ALL=C` retained so byte semantics hold under any locale.
