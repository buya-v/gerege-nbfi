### 1. `50-failopen-lint.py` — four widenings, every one STRICTLY ADDITIVE

Additivity is the property that makes this safe to merge, and it is proved by running the shipped
linter and the widened one over the same tree and diffing every detection, normalised to
`(file, condition, line, message)`: **20 detections → 22, LOST = none**
[VERIFIED: `instruments/30-additivity.sh`, `transcripts/30-additivity.txt`, verdict line
`ADDITIVE -- zero detections lost; the frontier differs only by ADDED rows.`].

* **C1 — the root allow-list is gone, replaced by a LOCATION-POSITION rule.**
  `C1 = (legacy 4-root expression, byte-for-byte unchanged) ∪ (any absolute path of ≥2 segments that
  does not exist now, in a position that READS a location)`. "Location position" = operand of
  `cd`/`pushd`/`source`/`.`/`ls`/`cat`/`stat`/`git -C`/`-C`/`--git-dir=`/`--work-tree=`/`test -d`/
  `[ -d`, or the RHS of a variable assignment. Keeping the legacy expression in the union is what
  makes "additive" a structural fact rather than a hope.
  Three filters, **each one bought by a measured false positive**, not by taste:
  - a literal containing `XXX` is a `mktemp` TEMPLATE (removed 5 false hits in t238's own rigs);
  - a path the file itself creates or deletes (`>`/`>>`/`rm`/`mkdir`/`touch`/`tee`/`mktemp`) is
    scratch, not corpus (removed an unearned TIER2→TIER1 promotion of `t239/50-red-drive.sh` on
    `/tmp/t239-red-index` and `/tmp/x.tar`);
  - a path reached ONLY inside an `echo`/`printf` argument is being displayed, not visited — applied
    to the T248 half of the union and **never** to the legacy half, which is what keeps additivity
    exact (removed an unearned TIER2→TIER1 promotion of `t239/51-run-r11-verbatim.sh`, which QUOTES
    r11's broken line in order to explain it).
  Without the location-position narrowing, `conformance.sh` itself was flagged three times — on the
  grep PATTERN `"/contract/contract.go$"` and two `CENSUS` fixture strings containing `/x/…`
  [VERIFIED: `transcripts/20-rule-candidates.txt`, final section].

* **C2b — a new condition: an UNCONDITIONAL reassuring print after a swallowed `cd`.**
  Fires when a `cd` whose failure does not terminate the script (`|| exit`, `|| return`, `|| die`,
  `|| {` are fatal and exempt) is followed, within three code lines and with only prints or the
  search itself in between, by an unconditional `echo`/`printf` whose text **claims an absence or a
  completed search**. Line continuations are joined first, so `cd … && \` + `git grep …` is one
  construct and the sentence after it is the next line — reading physical lines is how the shipped
  C2 could look straight at `r11-hygiene.sh:77` and see nothing following it.

* **C2a-continued — the legacy arm, with the `||` on a backslash continuation.**
  Found by red drive (shape R5), not by design.

* **`RE_REPOWIDE` — the CORPUS SELECTOR was itself blind.** The shipped expression required the
  literal `git grep` / `git ls-files`, so `git -C /nonexistent/… grep … || echo "(no hits)"` — a
  dead path AND a reassuring arm, **both conditions the linter already had** — was not merely
  misclassified, the file **never entered the inspected set**. Found by red drive (shape R4). This is
  P-76 in its sharpest form: a rule's blind spots are not only in its conditions, they are in how it
  chose the population to apply them to.

**The reassurance vocabulary was TIGHTENED by its own red drive.** The first draft carried bare
`\bzero\b`, `\babove\b` and `\bempty\b`; once shape R2 widened the window, those bare words reached
`a2-34-review-a2-15/rederive-provenance.sh:28`, a **section header** reading *"CALIBRATION (P-72):
instrument must show non-zero recall AND a true zero"*. A heading that DISCUSSES zeros is not a
sentence CLAIMING one, and promoting a file to TIER 1 on it would have been this linter asserting
something it had not established. Every alternative is now a claim shape, not a word.

**The rule I rejected, and why — measured, so it can be re-opened on evidence.** Variant **V4** also
treats a pipelined search (`git grep … | sed …`, where the searcher's exit status is discarded) as a
swallowing construct. It adds two frontier entries — `t239/21-crosscheck.sh` and
`a2-33-dec2-rev5/sweep.sh` — whose reassurance is real narration, and buys no true positive that
C1+C2a does not already catch [VERIFIED: `transcripts/20-rule-candidates.txt`, V4: frontier 12 vs
V3's 10]. Recorded as the next widening, not as a thing nobody thought of.

## Sweep discipline actually applied (P-75)

`type grep` reports a **shell function**; `rg` has **no binary**. So: no `grep` and no `rg` anywhere
in my instruments. Engines used — `/usr/bin/grep` by absolute path (BSD grep 2.6.0-FreeBSD, version
printed in the transcript), `python3 re`, and `subprocess` list-argv with **no shell and no pipe**, so
no verdict is ever carried by a pipeline (P-57). `set -euo pipefail` in the one `.sh` instrument.
Calibration is on a known **positive AND a known negative** in every rig, and each rig **aborts with
exit 2** if either fails — "I got hits, so my rig works" is not calibration. Matching is
**multi-line**: logical-line joining in the linter and in the candidate-rule measurement, which is
what made R1 and R5 detectable at all. `git commit -F` with a heredoc, never `-m` with a backtick
(P-74). The linter's JSON output was diverted to scratch on every invocation, so the tracked
`t238-failopen/evidence/lint.json` is untouched.

**One defect in my own rig, found and fixed rather than worked around.** The first
`30-additivity.sh` compared the linter's PRINTED lines — and the printed lines carry the filename in
the Tier-3 section but not in Tier-1/2. So when a file was promoted Tier3→Tier1 its one unchanged
detection appeared as a LOSS and a GAIN at once, and the instrument reported **"NOT ADDITIVE — this
is a WEAKENING"** about a widening that had lost nothing. It now normalises to
`(file, condition, line, message)`. The false alarm is left on the record in the instrument's own
comment because it is the reason the code looks the way it does.
