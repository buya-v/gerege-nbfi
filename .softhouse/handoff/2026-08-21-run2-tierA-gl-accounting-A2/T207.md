### May a float-derived predicate legitimately gate there? **YES — and here it MUST.**

Four load-bearing steps, each with its citation:

**(1) Zone A already gates on a float-derived predicate, by ratified decision.** T186 rule A1 is
*"Every numeric token in every request body must satisfy `repr(float(tok)) == tok`. **This is already
implemented and wired**"* — a predicate that cannot be evaluated without constructing the binary
double. It is live at **`conformance.sh:997`** [VERIFIED this fire; T186 cites `:784`, which has
drifted — re-derived, not quoted]. So the general question is not open: it is answered *yes*, today,
on every conformance run. Answering *no* for `t44` would be an unlicensed reversal of A1.

**(2) The guard that does it states the principle in the exact terms adopted here.**

> **THE ONE DELIBERATE `float()` (P-25)** — The line marked SIMULATE calls `float()` on purpose: it
> **SIMULATES THE DEFECT, which is the only way to measure it.** No money conclusion is drawn from
> it — the comparison is between two STRINGS.
> [VERIFIED: `.softhouse/capture/lib/check_wire_float_roundtrip.py`, module docstring]

**(3) The non-negotiable bans floats from CARRYING VALUE, not from BEING MEASURED.** Every noun in
*"no floating-point in any monetary code path, struct field, schema column, API field, or test
fixture — including intermediate calculation"* names a place a float would **hold an amount**. In
`v3` the parse hook returns `Decimal(s)`, the text predicate compares two **strings**, the value
predicate compares two **`Decimal`s**, the residue is `Decimal − Decimal`, and the only thing any
`float()` yields is a **`bool`**. The opposite reading is self-defeating: forbid the detector and the
first non-negotiable becomes enforceable only by assertion — P-22 one level up. **The reading that
forbids the detector protects the defect.**

**(4) WHICH predicate gates: P3 (value), not P2 (bytes).** On the response leg P2 has legitimate
failures — this corpus has **41** [VERIFIED: `t44_float_roundtrip-output.txt:6`; re-measured 41 of
245 by `v3`]. T186 §6.3 measured all 245 corpus-wide P2 failures as *"trailing-zero decimal forms …
scale-6 emissions by Fineract itself on the RESPONSE leg … The value is intact in every one"*, and
rule A4 says *"`1200000.000000` is not a typo for `1200000.0`; the scale witnesses `DECIMAL(19,6)`"*.
Gating on P2 here would refuse the oracle's own correct output — the error rule A2 forbids. P3
remains, and **P3 failure strictly implies P2 failure**, so it is the narrower, stronger event.

### The counter-argument, answered rather than omitted

T186 §6.4: *"it is also why **P3 should not be adopted as the guard property**: it would pass a corpus
that had already drifted badly, and it will keep passing right up until it doesn't."*

P3 *instead of* P2 would be a downgrade. On the response leg P2 is unavailable, so the choice T186
rejected does not arise. And **"too weak to be the only alarm" is not "must be silent when it
rings"**: no reading of §6.4 makes `detect → print PASS → exit 0` correct. Wiring it costs nothing
while green (`0 of 245`), which is T186's own G-C1 argument.

> **[T207's reading, marked as inference — not T186's words.]** T186 ruled on the request-body guard
> and did **not** rule on the response leg. If a later reviewer reads §6.4 as a blanket ban on P3 ever
