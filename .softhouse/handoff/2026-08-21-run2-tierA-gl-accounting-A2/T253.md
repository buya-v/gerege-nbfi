## 1. D1 — `mktemp -t NAME`, all TEN sites

### The defect, from primary sources (both captured verbatim in `transcripts/00-primary-sources.txt`)

| | synopsis | what `-t` does |
|---|---|---|
| **GNU coreutils 9.4** | `mktemp [OPTION]... [TEMPLATE]` | `-t` takes **no argument** — a deprecated **flag**. The next word is the `TEMPLATE`, and "TEMPLATE must contain at least 3 consecutive 'X's in last component." |
| **BSD / macOS** | `mktemp [-d] [-p tmpdir] [-q] [-t prefix] [-u] template ...` | `-t` **consumes the next word** as its option-argument `prefix`, then builds its own template from prefix + `TMPDIR`. |

So `mktemp -t conformance-failopen` **succeeds on BSD** (prefix consumed) and **dies on GNU**
(`too few X's in template 'conformance-failopen'`). The first such site sits inside
`guard_no_fail_open_instruments`, so on every Linux host the harness died **there**, before
the probe, with no verdict. **The guard that could not run is the fail-open detector.**

### The fix

One helper pair defined once, next to `say`/`warn`, and called at all ten sites:

```sh
conf_tmpdir()   { local d="${TMPDIR:-/tmp}"; d="${d%/}"; [ -n "$d" ] || d=/; printf '%s' "$d"; }
conf_mktemp()   { mktemp    "$(conf_tmpdir)/$1.XXXXXXXXXX"; }
conf_mktemp_d() { mktemp -d "$(conf_tmpdir)/$1.XXXXXXXXXX"; }
```

`-t` is **dropped entirely**. A single positional template carries the directory and ten
X's, so **neither parser can read the argument as anything but a template** — there is no
option letter in front of it. This is **the form both man pages specify**, not the form that
merely works here: BSD `mktemp(1)` gives the shape as its own worked example
("… for example `/tmp/temp.XXXXXXXXXX`") and GNU documents the same positional `TEMPLATE`
with a minimum of three X's, which ten clears; BSD imposes no minimum.

`TMPDIR` is stripped of a trailing slash because **macOS always sets it with one**
(`/var/folders/…/T/`), which would otherwise put a `//` in every scratch path.

### The ten sites — ENUMERATED, not swept

Rewritten **by line number with the prior content asserted**, because **lines 1938 and 2011
were byte-identical** (`CONF_BIN="$(mktemp -t conformance)" || exit "$EXIT_UNUSABLE"`) — a
unique-string edit could not have distinguished them, and a `replace_all` sweep would have
hidden that there were two.

## 2. D2 — `go-env.sh` hardcoded `/Users/buv/…`

`.softhouse/bin/go-env.sh:12` read `GEREGE_TOOLCHAIN=/Users/buv/gerege-nbfi/.softhouse/toolchain`
and **silently exported `GOROOT=<nonexistent>/go` anyway**. The working `go1.24.7` at
`/usr/local/go/bin/go` then died with `cannot find GOROOT directory: …`, surfacing three
layers away as `ledger-invariants: the guard DID NOT COMPILE … EXIT 2 — NOT a pass`.

**The guard's refusal there is correct and fail-closed. I did not touch it.** The defect was
in `go-env.sh`, which converted *"the pinned toolchain is not installed on this host"* — the
ordinary state of every machine but one — into *"a HARD money guard did not compile"*.

### Resolution, derived not hardcoded

1. `$GEREGE_TOOLCHAIN` if the caller set it — explicit override wins.
2. **the MAIN checkout, via `git rev-parse --git-common-dir`.** This is the load-bearing
   step: the toolchain is **gitignored**, so it exists **only** in the main checkout and
   **never** in an isolated worktree, while *this file is tracked* and is checked out in
   every worktree. **Deriving from the script's own path alone would resolve a worktree's own
   `.softhouse/toolchain`, which is never there.** Relative output is absolutised by `cd`,
   not by string surgery.
3. this checkout — for a plain clone, a tarball, or anything git cannot answer for.

Each candidate is tested for an **executable `go/bin/go`**, not for a directory that exists —
testing `-d` would have recreated the same defect one level down.

Finding the script's own path when **sourced** is impossible in POSIX sh (`$0` is the
caller's). The bash (`${BASH_SOURCE[0]}`) and zsh (`${(%):-%x}`) spellings are each hidden
behind `eval`, because **`/bin/sh` here is dash and dash cannot even PARSE `${BASH_SOURCE[0]}`**
— it aborts with `Bad substitution` (shape 9 negative control proves this).

### THE ENGINEERING DECISION — fall back **loudly**, do not refuse

Classified **ENGINEERING** under CLAUDE.md's *Answering gates*: decided here, recorded here,
not asked. `chosen_by: agent`.

**DECISION: when the pinned toolchain is absent, SUBSTITUTE the `go` already on PATH and SAY
SO, LOUDLY, ON STDERR, naming the binary and its version.**

Reasoning:

1. The pinned toolchain is **gitignored and host-local**, so it is **by construction absent
   everywhere except one Mac**. A hard refusal makes the program's only instrument unrunnable
   in CI, in a cloud sandbox, and on every new machine — the same portability failure as D1.
2. **The fail-closed property that matters already lives in the guards.**
   `check-ledger-invariants.sh` and `conformance.sh:load_toolchain` **both already refuse
   loudly** when there is no compiler. Duplicating that refusal one layer beneath them would
   create a **second source of truth** for one question (P-77's shape).
3. **The real defect was SILENCE, not substitution.** A substitution that is printed is
   auditable evidence in the BAR; a silent one is not. The dangerous case — a green parity BAR
   produced by an unpinned toolchain with nobody noticing — is closed by *printing*, not by
   *refusing*.

**ALTERNATIVE REJECTED: refuse outright, no fallback.** It buys no protection the two guards
do not already provide and would leave the harness unrunnable on every host but one. It is
**rejected as the DEFAULT, not removed** — `GEREGE_GO_STRICT=1` selects it, so the rejected
arm stays reachable without editing the file and **reversing this decision is a config change,
not a patch**. Buyan retains veto.

**What the fallback does NOT license**, stated in the script and printed on every substitution:
it is fine for building and for the source-level guards; it is **not a pinned-toolchain run**,
and **any parity claim must name the toolchain that produced it**. `GEREGE_GO_SOURCE` is
exported (`pinned:…` / `substituted:…` / `refused:strict` / `absent:no-go-on-path`) so any
consumer can report it mechanically.

Neither no-toolchain arm exports `GOROOT` at all — **exporting a GOROOT that does not exist
is the entire defect being replaced.**

## 4. THE THIRD DEFECT — found, diagnosed, PROVED, and DELIBERATELY NOT FIXED

### 4.1 What it is

C1 flags `/tmp/t234_matrix2.txt` in `02-escape-matrix-fix.sh` as a **dead path**. **It is not
one — that instrument CREATES it:** line 6 is `C=/tmp/t234_matrix2.txt`, line 7 is
`{ printf …; } > "$C"`. The linter **already has the right rule** ("A path the instrument
CREATES or DELETES is its own scratch, not the corpus it reads", `RE_OWNED_HEAD`) and the rule
**misses**, because ownership is tested by searching for the **literal** path right after
`>`/`rm`/`mkdir`/`touch`/`tee`/`mktemp`, while the redirect goes through the **variable `$C`**.
The literal never appears in an owned position.

**Why it is green on the Mac and red everywhere else:** `os.path.exists()` is evaluated on the
**running host**. On Buyan's Mac that scratch file is lying around from a previous run of that
same instrument, so the path "exists" and C1 stays silent. **The same commit therefore yields
TIER1 or TIER2 for the same file depending on whether an unrelated instrument happened to be
run recently on the linting machine.** That is **P-69's shape in an instrument rather than in a
document**: a classification that was true when pinned and is **not a property of the file**.

**Direction matters: this false positive is fail-CLOSED.** It over-reports and blocks; it never
licensed anything permissive. It is a **reproducibility** defect, not a safety hole — but it
makes the harness unrunnable on every host but one.
