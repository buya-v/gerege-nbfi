**FINDING 1 — §5's own title is REFUTED. The oracle reconciles by key; it does not
delete-then-recreate.** A generic slot is updated in place (`A2-503`, id 12, `max(id)` unmoved). A
list entry whose key is already present is updated in place (`A2-519`, id 96). A row is deleted only
when its key **leaves** the list (`A2-511`). An update carrying no accounting parameter disturbs no
mapping at all (`A2-509`), so replacement is scoped to the payload, not to the update command.

A port built to §5's title — rebuild the mapping set on every product save — would churn every
`acc_product_mapping.id` on every save and diverge on identity while looking correct in any
projection that omits the key. That is exactly what this capture existed to prevent, and it is the
opposite of what the plan predicted.

**FINDING 2 — `changes` is not a delta.** `A2-516` re-sent a byte-identical body against state that
already satisfied it, and the response **still** reported the field as changed, serialised as a
**JSON string, not a JSON array**. A port returning a true delta, or an array, diverges on the wire
on the ordinary retry path.
