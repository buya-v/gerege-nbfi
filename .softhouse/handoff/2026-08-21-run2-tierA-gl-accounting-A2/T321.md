### 2.4 So: is `repo-state-attest.sh` suitable as an inter-arm reset check? — YES, with two caveats, both driven

**Yes, and it should be used instead of a porcelain assertion**, and it is already in the tree, wired,
and carries a proven false-positive suite. Concretely, the shape a drive should adopt:

```sh
bash .softhouse/guards/repo-state-attest.sh snapshot "$CLONE" "$ROOT/baseline.attest"   # once
# ... arm ...
git -C "$CLONE" reset --hard --quiet "$BASE_SHA"     # A NAMED REF (K10), not bare (K9)
git -C "$CLONE" clean -fdxq                          # -x, or ignored residue carries (K6/K7)
bash .softhouse/guards/repo-state-attest.sh snapshot "$CLONE" "$ROOT/after.attest"
bash .softhouse/guards/repo-state-attest.sh compare "$ROOT/baseline.attest" "$ROOT/after.attest" \
  || { echo "THE INTER-ARM RESET DID NOT RESET"; exit 2; }
```

**Caveat 1 — the writ must be declared, or ordinary drive setup reads as damage.** A drive that
legitimately creates `softhouse/<task>` needs `--allow-new-ref '^refs/heads/softhouse/'`; one that
writes ignored scratch needs `--scratch-prefix`. Both are driven green (L1, L2). Without them this
is the G5 trap again.

**Caveat 2 — `compare` will not BLOCK an ignored-file carry-over** (A4). Use `git clean -fdx`.
`compare` names it; it does not stop it.

**Not suitable: `survey`.** It is single-state by construction and cannot tell a legitimate commit
from a clobber — its own docstring says so. An inter-arm reset check needs the **differential**.

**Cost:** `snapshot` is ~1 s on this repo (7.5k tracked files, T325's measurement, reproduced here);
in the small scratch repos a drive actually uses it is milliseconds.
