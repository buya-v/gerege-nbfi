### F2 — `casualty-sweep.sh` no longer emits a negative it never measured

`casualty-sweep.sh:39` discarded `git grep`'s exit status. Rewritten in T238 `sweeplib.sh`'s shape:

- exit status read; `>=2` prints `*** SELECTOR DID NOT RUN (git grep rc=N). THIS IS NOT "ZERO HITS"`
  and folds the engine's own stderr in rather than discarding it; `1` prints `MEASURED ZERO` **with the
  corpus size it ran over**;
- a **positive** calibration (P-72) and an **anti**-calibration, because T238 measured `git grep -E`
  *fabricating* a hit on this host — so "I got hits, therefore my rig works" is not a calibration. Both
  abort before printing anything, since no zero after a broken calibration is interpretable;
- an exit contract: `0` every selector ran / `2` corpus unusable / `3` calibration failed / `4` a
  selector did not run. It still **gates nothing** — the code says whether the *sweep* is admissible,
  never whether a casualty exists.

The anti-calibration sentinel is composed at run time from pid and clock. A hard-coded sentinel appears
verbatim in the script, so `git grep` finds it and the anti-calibration fails on every run for the wrong
reason. That is measured, not theoretical — the first version did exactly that.

**Also:** `.softhouse/observations/` removed from the `ARCHIVE` predicate. T363's own casualty list
correctly names an observation as LIVE while the predicate hid that whole directory, so the shipped list
was **not derivable from the shipped script** (T367's § 6.2 secondary note). This widens the LIVE list.
