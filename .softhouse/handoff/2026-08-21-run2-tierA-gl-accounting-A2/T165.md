## The concrete failure, demonstrated

`FindRepoRoot(".")` at `main.go:38` set `opts.RepoRoot`, and **four** things hang off it
[VERIFIED: read in this tree at `a2c3c78`]:

| leg | source | what the CWD decided |
|---|---|---|
| the graded corpus | `main.go` `store = filepath.Join(repoRoot, ".softhouse", "vectors")` | which vectors |
| the no-float census | `grade.go:253` `ScanGoTreeForFloatingPoint(filepath.Join(opts.RepoRoot, GuardedGoTreeRel))` | which Go tree is inspected |
| **the frozen contract digest** | `grade.go:292` → `admit.go:79-80` `filepath.Join(repoRoot, pin.ContractFile)` | **which `contract.go` is hashed against the store pin** |
| capture provenance | `admit.go:578` `filepath.Join(repoRoot, v.Provenance.CaptureRef)` | which tree the capture artefacts are read + SHA'd from |

**None of them is the tree the binary was built from, and nothing compared the two.** The contract-digest
leg is the serious one: it has **no shell-side counterpart** in `conformance.sh` (`run_guards` runs
`guard_no_float_in_vectors`, `guard_no_float_in_harness`, `guard_gofmt`, and the two capture guards —
there is no contract-digest guard), so the Go binary is the **only** thing enforcing it.

**Does it fail loudly or silently? Both, and the split matters.**

| CWD | pre-fix behaviour | class |
|---|---|---|
| `/Users/buv/fineract` (the Fineract checkout) | **exit 2**, `no repository root with .softhouse/vectors found above .` | LOUD |
| `/tmp` | **exit 2**, same message | LOUD |
| another worktree that HAS `.softhouse/vectors` | grades **that worktree** silently | SILENT-WRONG |
| a worktree that has **no** `.softhouse/vectors` (rescued branches — real, present) | climbs out and grades **`/Users/buv/gerege-nbfi`** — main's store, main's `contract.go`, main's source tree — `VERDICT: PASS` | SILENT-WRONG |
| main checkout, running a worktree's harness | grades **main** while the shell guards report the worktree | SILENT-WRONG |

So the honest statement is: **the foreign-repo and no-repo cases fail loudly; the same-repo-family cases
fail silently, and those are the ones this program actually runs in.** A dozen worktrees live under
`.claude/worktrees/`, the driver's shell keeps its CWD across tool calls (it ran a merge inside
`/Users/buv/fineract` last fire for exactly that reason), and P-24 scratch merges build trees in `/tmp`.

## Where T154's F-3 is wrong (or right)

T154 F-3 [`.softhouse/handoff/2026-08-21-run2-tierA-gl-accounting-A2/T154.md:326-330`], verbatim:

> **F-3. The no-float census reads the source tree at run time.** `Run` scans
> `<RepoRoot>/nexus/internal/apps/loanschedule`. That is fine for this harness — `FindRepoRoot` walks
> up for `.softhouse/vectors`, so the repo is present by construction — but a future binary shipped
> away from its source would report `THE NO-FLOAT GUARD COULD NOT RUN` and be exit 2. That is
> fail-closed and deliberate; it is written down here so nobody "fixes" it into a skip.

**F-3 is WRONG, in three separate ways.**

1. **"the repo is present by construction" answers the wrong question.** T155 already said this and
   was right: *"the repo it finds may not be the repo under test."* Presence was never the risk;
   IDENTITY was. F-3's argument would license grading any checkout on the machine.
2. **F-3's own failure mode — "a binary shipped away from its source is exit 2, fail-closed" — was
   FALSE pre-fix.** A binary shipped away from its source and run **anywhere inside another
   gerege-nbfi checkout** did not exit 2; it found *that* checkout's `nexus`, censused it, and passed.
   I measured exactly this: `/tmp/T165-scratch.bin` (built in `/tmp`, its source tree carrying a
   float) reported `VERDICT: PASS (exit 0) — 43 parity vectors` when run from this worktree. Fail-closed
   was the claim; fail-**open** was the behaviour, and it is fail-open on the flagship non-negotiable.
3. **F-3 scoped the hazard to the census.** The contract-digest leg and the `capture_ref` leg ride the
   same root and are not mentioned. The contract-digest leg is a hard `user` gate.

**What F-3 got right:** the census reading the source tree at run time IS deliberate, and it must not
be "fixed" into a skip. The fix here preserves that exactly — an unresolvable tree is still exit 2,
now with a message that names what it could not find and tells the caller to pass `-repo-root`.

T155's **D-3** [`T155.md:138`, `.softhouse/reviews/T155-review-of-T154.md:308-322`] is **CONFIRMED**
in full, including that it found it the hard way via a 22-vs-24 cross-check mismatch. T166's
measurement is also CONFIRMED and now closed (see GREEN-7).
