**The defect, on the pre-fix bytes** [VERIFIED: `git show main:…/grade.go`]:

```

:155   // CorroborationsClaimed is how many cross-check claims the admissible vectors
```

Both are incremented in the same loop body, **after** the `case OutcomeRefused: …
continue` — so both count GRADED vectors and the second sentence was false
[VERIFIED: `grade.go` graded-population loop, `case OutcomeRefused` returns before
the increment block].

**What the replacement says**, and it is deliberately A2-24's argument and not
the one A2-24 rejected:

- the two claims do **not** share truth-conditions — a counterfactual asserts
  DISCRIMINATION with grading as its antecedent, a corroboration asserts
  something about the RECORD, is validated offline at admission, and **none of
  the five refusal reasons impugns it**, so a refused vector's corroboration is
  still TRUE;
- it is scoped to the graded population anyway because the report scopes by
  **POLARITY**: hazards (`RateFactorsRecorded`, `OverScaledCells`, counted in
  `gradeVector` before any early return) take the widest population, **support**
  takes the narrowest, and a corroboration is support;
- the degenerate store settles it — one blinded seam refuses everything and the
  wide rule prints `cells compared: 0` beside `corroboration claims: 51` in the
  same report;
- the shed claims are named (`RefusedCorroborationsClaimed`,
  `ErroredCorroborationsClaimed`), printed whether or not they are zero, so the
  store-quality reader recovers the corpus total by addition.

The kill-symmetry argument is nowhere in it. The comment explicitly says "for its
own reason, not by symmetry with it."

The same reasoning is now also in `report.go`, under the printed line, because a
reader of the *report* meets that sentence long before they meet the struct.

**Behaviour-free:** the F1 change is a comment. The only report bytes that moved

## F3 — closed or documented, and why

**CLOSED. Not documented-and-carried.**

**Why I changed the classification A2-24 gave it.** A2-24 called it "latent
only — the single reachable cause already makes the run fatal." That is true of
the **exit code** and false of the **report**, and I measured the difference
before deciding. `Options.Implementation == nil` is not a contrived state: it is
the standing state of `cmd/conformance/impl_hook.go` until a port is registered,
and `Run` has a `FatalReason` written for exactly it. On the **pre-fix bytes**,
committed store, nil implementation
[VERIFIED: scratch probe run on `2e97162` bytes, reproduced in
`A2-27-evidence/F3-RED-errored-vectors-in-graded-population.txt`]:

```
results=51 errored=51 refused=0 inadmissible=0 gradedCells=0
CounterfactualsNamed=113 money=106 structural=7
uncovered=[]
exit=2
```

**A run that compared ZERO cells credited 113 kills and reported every
`in_graded_domain` capability backed.** That is precisely the A2-19 F3 shape the
refused half of this code was written to stop — the case with the least evidence
producing the quietest report — reached through the other door. "Latent" would
have meant nobody could ever read that sentence; in fact anyone running the
harness before the port is registered reads it.

So the deciding facts were: (1) it is reachable through the ordinary public API,
(2) it is therefore **testable**, and a fix I can drive red is worth more than a
paragraph, and (3) leaving it would have left `grade.go` asserting a population
rule its own loop broke two branches later — the same class of defect F1 fixes.

**What "closing" it consists of**, following the precedent A2-19/A2-22 set for
refusals exactly: shed, never drop.

- `case OutcomeError:` in the graded-population loop accumulates
  `ErroredCounterfactualsNamed` / `ErroredCorroborationsClaimed` and `continue`s.
- `report.go` prints them **unconditionally, zero or not** (P-35), beside the
  REFUSED disclosure, with the measurement above written into the printed reason
  so a future reader meets it in the report rather than only in this handoff.
- The struct comment on the new fields records the same measurement.

**Documentation is where a reader meets the code, in three places**, per the
brief: the `Summary` field comment (`grade.go`, the `Errored…` block), the loop
comment above the shed branch, and the printed report lines themselves. Not only
in this handoff.
