```
FAIL    feeToIncomeAccountMappings present and null          -- '<absent>'

```

**VERDICT: neither a defect in the observed evidence nor a defect in the checker's
arithmetic. The checker asserts A2-7's REFUTED claim, and its RED is the correct, intended
verdict — the executable form of a settled finding.**

`run-all.sh:10-12` states the reading rule and it is decisive: *"sections 1 and 2 assert
A2-7'S CLAIMS, so a non-zero exit there is a FINDING AGAINST A2-7, not a broken script."*
A2-7 printed a fenced JSON block attributed to capture
`A2-211-read-product-nine-mandatory.json` whose last three lines were **fabricated**, then
reasoned a contract rule from them — *"the collection-valued mapping fields behave the
opposite way: they are present with the value `null`"* — and fed that rule to the coder
A2-8. That is A2-11 finding **F-1** (`A2-11.md:429-449`), corrected in place by the driver
at `A2-7.md:211-221`, shipped by A2-8 at `A2-8.md:101-120`, and recorded as **P-46**
(`patterns.md:1495-1530`), whose rule 3 is the substance: *"Absent ≠ null ≠ empty. In a
contract-boundary port these are three different wire shapes, and the difference is
`omitempty`/pointer-vs-value in Go."*

### I did not take that on the record's word. Three independent confirmations:

**1 — the evidence is not stale and not corrupt (fresh oracle observation).** The one
question the record could not answer is whether the `obs/` bytes had rotted. That cannot be
settled by replaying them, so I went back to the live oracle
(`capture/t357-a2-11-section1-red/re-observe-t357.sh`, health `{"status":"UP"}`, tenant
`gerege`, `2026-08-28T06:49:12Z`). **Four of four reads came back byte-identical:**

| read | bytes | sha256 (fresh) | vs committed `obs/` |
|---|---|---|---|
| `GET /loanproducts/46` | 7510 | `04b14461410412ed…` | **IDENTICAL** |
| `GET /loanproducts/22` | 7726 | `b2c060af179538cd…` | **IDENTICAL** |
| `GET /loanproducts/28` | 7806 | `7d6b4a79af7576d3…` | **IDENTICAL** |
| `GET /glaccounts/2` | 353 | `1d7fc3cb1e0fe2d7…` | **IDENTICAL** |

In the fresh product-46 bytes each of the three keys occurs **0** times, the literal
`null` occurs **0** times, and the set of keys whose value is `None` is **empty** —
reproducing A2-11's F-1 measurement exactly, a week later, on a live instance.

**2 — the contrast case proves the rule is uniform, not "opposite".** Product 22 *has* a
payment-channel override, and there `paymentChannelToFundSourceMappings` **is** present, as
a **list**; its unset siblings `feeToIncomeAccountMappings` and
`penaltyToIncomeAccountMappings` are **absent**. Set → present. Unset → absent. **Never
null**, in either the scalar slots or the collection fields.

**3 — and it is refuted at the SOURCE, not merely at the wire.** Fineract's read path
serialises through `GoogleGsonSerializerHelper`, which never calls `serializeNulls()`
[VERIFIED: `fineract-core/src/main/java/org/apache/fineract/infrastructure/core/serialization/GoogleGsonSerializerHelper.java` —
`createGsonBuilderForPartialResponseFiltering` :53-59 and
`createGsonBuilderWithParameterExclusionSerializationStrategy` :61-85 both build a plain
`new GsonBuilder()`]. The **only** `serializeNulls()` in `fineract-core` +
`fineract-provider` is `CommandProcessingResultJsonSerializer.java:38` — the
**command-result** serializer, not the read serializer. Gson omits null fields by default.
So on the read path a null-valued field is **absent, uniformly**, and A2-7's "opposite way"
claim was never true of any Fineract read.

**Consequence for the Go port, which is the part that still matters.** The frozen adapter
contract must encode ABSENT-when-unset for **both** the scalar mapping slots and the
collection-valued mapping fields — `omitempty` on a slice, `omitempty` on a pointer, never
a value type that marshals to `null`. A port that emits `"feeToIncomeAccountMappings":
null` diverges from the oracle on the wire. That is the live obligation this RED carries,
and it is not yet vectored (see OPEN, below).
