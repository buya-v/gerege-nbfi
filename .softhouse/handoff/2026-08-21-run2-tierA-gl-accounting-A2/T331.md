
**Both anchors resolved, uniquely, at a fourth rewrite of the file** — T326's and T328's included.
The name-not-ordinal anchor strategy is vindicated: T282's own line numbers would have been stale
by hundreds (the file was 3,842 lines when T282 measured it and 3,900 at `817d2b53`).

**THE FINDING, and it is about the anchor strategy, not the anchor.** T282 specified anchor 1 as
*"immediately BEFORE the line `guard_no_host_state_in_lint_corpus() {`"*. That token resolves
uniquely — **and inserting there is wrong.** In this file a guard is a **doc block immediately
above its function**, and `guard_no_host_state_in_lint_corpus`'s doc block is ~218 lines long
(`:1686`–`:1903`) and ends in a multi-line pinned literal. A literal application splices a brand-new
function **between a guard's documentation and the guard it documents**, leaving the T273 block
apparently annotating T282's code.

**An anchor that names a TOKEN when it means a BOUNDARY is under-specified.** It survives file
churn — that is real and it worked — but it does not survive the reader who applies it exactly.
`bin/apply-wiring.py` therefore anchors on the **doc-block header** and *refuses* unless that header
is immediately preceded by the convention's `# ---` rule line, so a future layout change is loud
rather than silent. It also refuses if either anchor matches zero or more than one line: an anchor
that matched twice has no "the" match, and picking one is a coin flip dressed as a measurement.

Anchor 2 was applied **exactly as T282 wrote it**, one call after
`guard_no_host_state_in_lint_corpus  || failed=1`.

**Two deliberate departures from T282's block, both stated:**

| change | why |
|---|---|
| `python3` → `/usr/bin/python3`, plus an explicit `[ ! -x /usr/bin/python3 ]` refusal | Without it an absent `python3` makes the selftest subshell exit 127 and the guard reports **"FAILED ITS OWN SELFTEST"** — fail-closed, but naming the wrong cause. Same shape and same refusal as `guard_reconciler_ownership` two hundred lines below. A diagnosis fix; it changes no verdict. |
| the census lines are printed with a `conformance:   ` prefix | Every other line the harness emits carries it; without it three census lines appear unindented in the middle of the report. Cosmetic, stated so it is not mistaken for a predicate change. |

## 2. HARD or SOFT — the argument, not the inheritance

**Decision: HARD.** The full argument is written into `conformance.sh` beside the guard, where the
next person to trip it will actually read it. Summarised, with the objection stated at its strongest
first.

**The objection.** This defect's measured materiality was **LOW twice**, for a specific reason: every
prompt wrote the full rule text beside the id, so the number was decoration and the sentence carried
the instruction. **Not one worker was ever misdirected.** A HARD guard exits 2 *before the probe line
prints*. Does a citation-drift defect deserve that?

**(1) THE BRIEF'S PREMISE ABOUT THE SIGNAL IS FALSE, and P-84's own text refutes it.**
The brief says a HARD guard produces "the signal a driver is trained to read as a money
non-negotiable violation". `P-84` says no such thing. Its text is **"EXIT 2 WITH NO PROBE LINE" IS
THE GUARD WORKING — READ THE ABSENCE, NOT THE VALUE**, and its whole subject is telling a **HARD-guard
refusal** apart from an **oracle outage** [VERIFIED: `.softhouse/patterns.md:2813-2820`]. The instance
it was written from was **`p5-probe.sh` moving the fail-open frontier 10 → 11** — an
instrument-hygiene guard of *exactly this guard's class*, not a money violation at all. Eleven guards
already share this exit and `guard_gofmt` is one of them. There is no money-only signal to dilute.

**(2) THERE IS NO SOFT TIER IN THIS FILE, AND INVENTING ONE IS THE DEFECT ITSELF.**
Every guard in `run_guards` is HARD. A SOFT wiring prints a line that nothing depends on — **`P-22`:
a guard, a canary, or a control that cannot fail is worse than none, because it is believed**. That
is not my inference; it is the sentence `conformance.sh` already records at its T323 block
(*"A SOFT wiring prints a line that nothing depends on, which is P-22 … and that is the sentence the
three authors already wrote, with extra steps"*; and *"SOFT was rejected because SOFT is precisely the
defect this task exists to remove"*). And a line scrolling past in a 3,800-line report is **T165
verbatim** — the true statement was in the output and the reader took the summary instead.

**(3) THE CHECKER IS ALREADY TWO-TIERED, so a SOFT wiring would be a THIRD tier that deletes the
second.** Its **report** tier is deliberately generous and prints on every run — 81 findings today in
committed evidence, ratified ADRs and orchestrator-owned files, all corrected *forward* in the
`patterns.md` errata. Its **fatal** tier is the DIRECTIVE zone alone: the only class that is *both*
read as instruction by workers not yet born *and* lawfully repairable in place by an ordinary task.
**Wiring at all obtains the reporting; only wiring HARD obtains anything the tiers were built for.**

**(4) T326's LESSON CANNOT BITE HERE — checked, not hoped.** T326 recorded that *"wiring a guard HARD
is the first time anyone finds out whether its pin is a measurement or a snapshot of somebody's
disk"*, after T316's `os.path.exists()`-derived pin aborted T323's first merge. **This guard has no
pin.** It derives its register from `patterns.md` and its corpus from `git ls-files -z`
[VERIFIED: `check-pnumber-citations.py:719`], never from the disk. The failure mode has no purchase.

### The residual risk, MEASURED — and it is the real cost of HARD

`out/30-fatal-predicate-rate.txt`. With the **zone restriction lifted**, the fatal scorer
(`grams ≥ 2 ∧ score ≥ 9 ∧ cited_score ≤ 1`) fires on **41 sites** (42 at the delivered HEAD; the
extra one is this task's own RED fixture). Only **10** are filed TRUE-DRIFT. **28 of the other 31
are in raw SWEEP OUTPUTS** — `a2-33-dec2-rev5/sweep-output-live-population.txt`,
`A2-32-evidence/sweep-output.txt` — files that *dump* citations gathered from elsewhere, where a
citation is a **mention and not a claim**.

**So the DIRECTIVE zone is doing 100% of the work of keeping this guard honest.** The fatal scorer in
isolation is ~76% false positives. That is stated plainly because it is the strongest argument
against HARD and it should not have to be rediscovered.

**And the margin is one point.** In the directive zone today: **6 findings, 0 fatal.** The closest is
**`.softhouse/conformance.sh:1866` — this very file — at score 8 against a fatal floor of 9**, and
T331 adjudicated it a **FALSE POSITIVE**: it cites `P-66/P-70 — "not found" is a statement about the
search`, which is **correct** [VERIFIED: `patterns.md:1931`, `:2341`]; the extractor merely swept the
gloss past the citation's own sentence into the paragraph beneath it about *population* and *corpus*,
which is `P-76`'s subject. **It is deliberately left alone.** Rewording a *correct* citation to move a
heuristic score is fitting the tree to the guard, and this file already records that clearing a guard
by removing its subject is the move a reviewer should distrust most.

**Why HARD still wins on that record.** The remedy the guard prints is *"write the sentence the rule
wants: correct the id, or state the cited rule"* — one line, in a file the worker already owns. A
guard whose remedy is the rule is not a blocker; it is the rule (the argument T299/T323 already made
for the namespace guard). The one place that remedy is *not* cheap is `patterns.md` itself, and that
is `FU-T331-2` below.

Worth more than the wiring, because it is a property of **wiring this guard at all**.

**The corpus figure is a property of the day it was swept, not a claim to be restated** — T282's
own rule, and it moved four times inside T282's run for the same reason. Read it from the bar
(`out/90-FINAL-BAR.txt`) or run the checker; do not copy it forward.

The one `misdirecting` this branch adds is `bin/drive-through-the-route.sh`, which carries the
planted drifted line as a shell variable so the RED drive is re-derivable — evidence zone,
report-only, and the same *use-is-not-mention* shape as T282's own `drive-red-green.sh` (which is
why that file is in the checker's `SELF_SOURCE_EXACT` skip list and mine cannot be — `FU-T331-3`).

**The blob was trimmed too, after the same reasoning was applied to it.** The redacted findings
file was 1.4 MB / 68k lines, of which 8,392 of 8,473 records were `BARE` — "an id appears here
carrying no sentence", a record with no verdict in it that nothing downstream reads. `BARE` is now
kept as a **count** rather than a **list**: 30 KB. `recheck-14-true-drift.py` reports a missing
lookup as `<no-graded-finding>` rather than `<not-in-corpus>`, so the trim cannot degrade silently
into "this site is clean".

Measured, not predicted: `out/50-checker-after-wiring.txt` vs `out/61-checker-with-redacted-committed.txt`.

This is precisely why `check-pnumber-citations.py` already skips its **own** `out/` directory —
*"grading it would double-count every site in the program and grade this instrument against its own
printout; that is a self-reference, not a measurement."* **But its skip list is a hard-coded path
prefix tuple naming only `t282-pnumber-drift`**, so no other task inherits the protection, and T331
does not own that file. So T331 **redacted instead of exempting**: `bin/capture-findings.py` writes
the raw JSON to a `mkdtemp` **outside the repository** (so an interrupted run cannot leave an
unredacted dump in the tree) and commits a findings file with `detail`, `gloss` and `text` dropped —
every field its instruments consume, none of the free text that makes it a citation dump. The
command to re-derive the dropped fields is written into the file.

Residue, stated: T331's evidence still adds **+112 sites** — 100 BARE, 4 UNDEFINED and 1
negative-control, all **mentions in a transcript**, all evidence-zone, all report-only, `misdirecting`
