## 2. CONDITION 1, second half — closing the fail-open portably

**FAIL DIRECTION: OPEN. This is the P-85 safety half of the task.**

`_lock_json_field released_at str` accepted **any non-empty JSON string** and arm 1 fires on
any non-empty `rel`, so a `released_at` whose value *means* "not released" declared a live
lock free. Reproduced on T342's head against a live pid
[`out/13-t346-stringy-BEFORE.txt`] — `"null"`, `"None"`, `"NULL"`, `" "`, `"   "`,
`"false"`, `"0"`, `"no"`, `"-"`, `"pending"` — **ten** rows, every one `FREE-released`.
After [`out/14-t346-stringy-AFTER.txt`]: all ten `HELD-default`, and the one genuine
timestamp still `FREE-released`.

**I did not apply T346's patch.** It spells the shape check
`TZ=UTC /bin/date -j -f "%Y-%m-%dT%H:%M:%SZ" "$v" +%s`. On this Mac it is correct; on the
three userlands in §1.1 it returns empty, `lock_released_at` returns 0 with nothing printed,
and **arm 1 dies too** — a lock with no release arm and no takeover arm, reclaimable only by
`--force`. Direction of that would still be SHUT, so it is not unsafe; it is a second
BSD-only construct added to the lock path by a patch written to harden it.

**What I shipped instead: `_iso8601_epoch`,** a strict `YYYY-MM-DDTHH:MM:SSZ` parser in zsh
integer arithmetic — days-from-civil (Hinnant) — with **no fork, no `date`, and no floating
point anywhere** (CLAUDE.md: money is integer minor units; a lock stamp is not money, but a
float in a graded path is a rejection either way). It gates **both** sites: the new
`released_at` shape check and `lock_started_age`'s epoch conversion, which is what "fix it
portably for BOTH sites" required.

**Replacing a working parser is only safe if the answers are identical, so that is measured**
[`bin/epoch-parity.zsh`, `out/04-epoch-parity-mac.txt` (macOS) and
`out/07-epoch-parity-linux.txt` (Alpine)]. **51 rows, 0 disagreements on both hosts.**
19 well-formed instants — the epoch, 2000-02-29, 2004-02-29, 2100-02-28/03-01 (century
non-leap), 2400-02-29, both sides of the 2038 boundary, 9999-12-31 — **byte-identical to BSD
`date -j` and to python's `strptime`**; 32 malformed inputs all refused, including `None`,
`pending`, `2026-02-29` in a non-leap year, `2100-02-29`, hour 24, minute 60, an offset
instead of `Z`, and fractional seconds. The function is **extracted from the shipped file by
`sed`, not retyped** (P-46, quote by extraction), and the drive aborts if extraction fails.

One deliberate acceptance, recorded rather than hidden: `:60` (a leap second) is accepted and
maps onto the next second, which is what a POSIX epoch can represent. BSD `date` does the
same; python's `strptime` refuses it. Recorded in §C of the transcript, not treated as a
disagreement.

`_epoch_iso8601`, the inverse, exists for one reason: the self-test needs a "100 h ago" stamp
and the BSD (`date -u -v-100H`) and GNU (`date -u -d @N`) spellings of that are mutually
exclusive with busybox implementing neither. A self-test that only runs on the machine whose
portability bug it checks for is not a self-test.

## 5. CONDITION 4 — the interpreter dependency, said out loud

**FAIL DIRECTION: SHUT. It converts a SILENT permanent wedge into a stated refusal.**

With `/usr/bin/python3` absent or broken, every field read fails, so arm 1 cannot fire and
arms 2, 3 and 5 — *every* takeover path — cannot fire either. Nothing fails open (T342 chose
the safe direction and that is the important half), but the lock becomes unreclaimable except
by `--force`, and arm 3's *guaranteed* takeover stops being guaranteed. The log would read
`started_age=<unreadable> pid_state=absent`, indistinguishable from a corrupt body, and the
two pre-existing `python3` call sites are both `|| true`, so nothing aborts first.

Two gates, before the lock decision, both `exit 2` with a message that names the consequence:

1. `[[ -x /usr/bin/python3 ]]` — absent or not executable.
2. **It must PROVE it works**, because `-x` alone misses the case that matters:
   `/usr/bin/python3 -c 'json.loads → write "ok"'` must answer exactly `ok`. A broken install
   or a shim that prints a banner to stdout fails here — and a banner on stdout is read as a
   `released_at`, which is the **fail-OPEN** direction (T346 F-3).

The dependency is also stated in the polarity paragraph of the reader block, where a reader
of the lock code will meet it, and handed to STEP 0 as a diff in §10.

## 6. F-T346-6 — read atomicity, taken

**FAIL DIRECTION: SHUT. It removes a question, not a measured bug.**

`lock_pid_state` read `host` and `pid` from two independent forks. T346 walked the reachable
interleavings, found them all landing shut, and said honestly it had not proved no fail-open
one exists. New `_lock_json_fields <key:type>…` returns N fields from **one** `json.load`;
`_lock_json_field` is now a thin filter over it, so no caller's contract moved. Wire format
is `=<value>` / `!` per line, unambiguous because the parser already rejects control
characters in strings, so a value cannot forge a line break and an empty string stays
distinguishable from a missing key.

Side effect, measured: a `--lock-signals` cycle drops from 4 forks to 3 —
**2048 ms for 5 invocations ≈ 410 ms each**, against T346's measured 500 ms
[`out/15-t346-no-python-AFTER.txt`, timing section].

## 7. The defect P-22 found in my own wiring

**FAIL DIRECTION: SHUT.** I wired the self-test as `zsh "${0:A}" --self-test-lock-readers`.
`${0:A}` resolves against the **current directory**, and the wiring point is after
`cd "$REPO"` — so with a relative invocation it resolved to
`$REPO/.softhouse/bin/fire-program.sh`, which does not exist when the fire is pointed at any
repo other than the one the wrapper lives in. First `--probe` run:
`lockselftest| zsh: can't open input file: …/repo/.softhouse/bin/fire-program.sh` → `rc=127`
→ `FATAL` → `PROBE_EXIT=2`. **Reading it would not have found it; running it did.**

Fixed by pinning `FIRE_SELF="${0:A}"` beside `SCRIPT_DIR`, before the `cd`, which is the
pattern the file already documents for `SCRIPT_DIR` and which T301 already needed for the
snapshot re-exec. The launchd plist passes an absolute path, so the real fire would never
have shown it — the kind of immunity that is layout, not design, and worth the sentence it
now carries in the source.
