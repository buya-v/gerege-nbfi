## The three sites: shape, polarity, and my re-derivation

All three had the shape

```
if <producer> | LC_ALL=C grep -a?q <pattern>; then  warn/note "…"; bad=1;  fi
```

**Re-derived from the source, not taken on report.** `grep -q` exits 0 *the moment it
matches* and does not read the rest of stdin. The producer, if it has more than one pipe
buffer's worth left to write, is still blocked in `write(2)` when the reader's fd closes;
it takes `SIGPIPE` and dies. `set -o pipefail` (`conformance.sh:396`) makes the pipeline's
status the **rightmost non-zero** status — the producer's 141. So the enclosing `if`
evaluates **FALSE on a float it actually found.** Below one buffer the producer's write
has already completed, it exits 0, and the guard fires correctly. Hence: silent on small
inputs, silent-and-wrong on large ones — the failure mode that survives review.

| # | line (post-fix) | producer | consumer | guard | polarity |
|---|---|---|---|---|---|
| 1 | `guard_no_float_in_vectors`, ~`:546` | `perl -0pe` (strip string literals) | `grep -aEq` | **FLOAT-SHAPED NUMBER in a vector** | **FAIL OPEN** |
| 2 | `guard_no_float_in_harness`, ~`:607` | `perl -0pe` (strip comments) | `grep -aEq` | **FLOATING-POINT IDENTIFIER in Go** | **FAIL OPEN** |
| 3 | `prove()` FALSE VIOLATION check, ~`:1290` | **bash builtin `printf`** | `grep -aqF` | proof's own false-violation detector | **FAIL OPEN** |

Sites 1 and 2 sit directly behind **the first non-negotiable in `CLAUDE.md`**. Site 3 is
the proof that the *grading* is not itself broken — a guard on a guard.

**Polarity is the whole diagnosis, and it is worth stating what is NOT affected.** Site 3's
neighbours in the same block — `:1350`, `:1352`, `:1355`, `:1360`, and the `&&` chains at
`:933` and `:1043`–`:1047`, and `:1241`/`:1242`/`:1249`/`:1253` — carry the *identical*
`printf | grep -q` shape but with `|| note20` / `&& ok=1` polarity. Under the same EPIPE
they read "needle absent" → they **note a failure**. That is a **false alarm**, which is
loud and fails CLOSED. Exactly **one** member of that family, `:1290`, is written
`if … ; then note20`, so its EPIPE is a **silent pass**. I fixed the three fail-open ones
and left the fail-closed ones alone; they are listed under Follow-ups because they will
become flaky as `$out20` grows, but they cannot hide a defect.

`:449` (`grep -an … | head -1`) is *not* a member: `head` can only kill `grep` if **grep's
output** exceeds a buffer, and grep's output there is at most a couple of lines.

**Site 3 producer is the bash BUILTIN `printf`, not an external command,** and I did not
assume it behaves like `perl`. Measured separately below: **it dies of SIGPIPE just the
same** (bash restores SIGPIPE to `SIG_DFL` in the pipeline subshell).

## Pipe-buffer threshold — how I measured it on THIS machine

Nothing inherited. `.softhouse/reviews/T191-probe/measure-pipe-buffer.sh` binary-searches
between 1 KiB and 8 MiB. Its probe writes `N` bytes whose **first line** matches, into
`/usr/bin/grep -aEq`, under `set -o pipefail`, and grades **the pipeline's exit status**:
0 = producer survived (guard fires); non-zero = producer killed (guard inverts). Both
endpoints are printed first so a degenerate search cannot masquerade as a result.

```
producer=perl    consumer=/usr/bin/grep -aEq
  LARGEST CLEAN      (pipeline exit 0, guard fires correctly): 64775 bytes
  SMALLEST INVERTING (pipeline non-zero, guard goes SILENT):   64776 bytes

producer=printf  (bash BUILTIN, i.e. site 3)
  LARGEST CLEAN      : 65548 bytes
  SMALLEST INVERTING : 65549 bytes
```
[VERIFIED: `bash .softhouse/reviews/T191-probe/measure-pipe-buffer.sh perl|printf`]

Both sit at the 64 KiB (65536 B) Darwin pipe buffer; the two differ by ~773 B because the
consumer's own read buffer absorbs a producer-dependent amount before `grep` exits, so
**the threshold is a property of the producer/consumer PAIR, not of the kernel alone.**
That is precisely why I did not reuse T188's 64,768/65,024: those numbers came from a
different pair and are wrong for these two by 7 and 525 bytes respectively. Neither error
matters for the fix, but a handoff that recycles a number it did not measure is how the
36 KB non-reproduction of P-57 rule 2 happened in the first place.

**The second necessary condition, which T188 established and which I built into the rig:**
the consumer must be able to **stop early**. `grep -q` cannot stop before EOF on a
*single-line* input, so a 400 KB one-line JSON does **not** reproduce this at all. Every
large fixture below is therefore **multi-line with the planted match on an early line**.
Both conditions, or no bug.

1. **No committed artefact is currently mis-graded.** The margin table above is the whole
   basis for saying the defect was **latent**. I did **not** find a real float that these
   guards were missing. I did not look for one beyond running the fixed guards over the
   real store and module, which came back clean (50 `.json`, 42 `.go`, exit 0). **A green
   run after this fix is not evidence that a float was ever hidden.**
2. **I did not prove the guards are correct, only that they now speak when they match.**
   The regexes are unchanged bytes. Whatever a float that evades
   `[-0-9][0-9]*\.[0-9]|[0-9][eE][-+]?[0-9]` looks like, it evaded them before and evades
   them now. This task fixed *silence*, not *coverage*.
3. **Producer failure is still invisible at sites 1 and 2, exactly as before.** `hits="$(perl
   … | grep -ac …)" || true` cannot distinguish "perl failed" from "grep matched nothing":
   both yield `hits=0`, rc 1. I measured this rather than assumed it — `PIPESTATUS` is
   **not** preserved through a command substitution (`${#PIPESTATUS[@]}` is 1, holding the
   substitution's own status), and under `pipefail` a perl failure plus a zero-match grep
   both surface as 1. The **pre-fix `if` form had the identical hole**, so this is not a
   regression and I deliberately did not widen scope to close it. Follow-up 1.
4. **`grep` exit 2 (a read error) is also read as "0 matches"** — same shape, same
   pre-existing behaviour, same non-regression. Follow-up 1.
5. **Site 3's fix is proven on a lifted snippet, not on a `prove()` run with a >64 KiB
   `$out20`.** I could not manufacture a real harness run producing 65 KB of output
   *containing a genuine false violation*; the real `--self-test` output is 22,158 B. The
   snippet is real bytes lifted by anchor and the fixture satisfies both necessary
   conditions, but the end-to-end path at that size is **unproven**.
6. **The 512 KiB LARGE fixtures are ~8× the threshold, not adversarially near it.** I did
   not re-verify behaviour in the 64,776–70,000 B band; `measure-pipe-buffer.sh` locates
   the boundary to the byte but `drive-t191.sh` does not sit on it.
7. **I did not run `go build ./...` / `go test ./...` separately.** The full harness ran
   them as part of its own flow and exited 0; I am not claiming an independent Go
   verification beyond that.
8. **Nothing here says anything about cutover.** A green harness means "builds, tests
   green, known-bad patterns absent, matches the reference oracle on captured vectors" —
   never "safe to cut over."

## Follow-ups

1. **Producer failure and `grep` exit 2 both read as "clean" at conformance.sh `:546` and
   `:607`.** Pre-existing, unchanged by T191, and it is the *same class* as this task's
   defect — an error condition entering as a silent pass. The clean fix is to give the
   pipeline a way to report the producer's own status, which `PIPESTATUS` cannot do
   through `$( )` (measured). Worth a task; explicitly out of scope here because closing
   it means restructuring the loop, not editing a line.
2. **The fail-CLOSED members of the same family will become flaky as output grows.**
   `conformance.sh:933`, `:1043`–`:1047`, `:1241`, `:1242`, `:1249`, `:1253`, `:1350`,
   `:1352`, `:1355`, `:1360` all carry `printf "$out" | grep -q` with `&& ok=1` / `||
   note=0` polarity. They cannot hide a defect — a killed producer reads as "needle
   absent" and they **fail** — but once a `$out` crosses 65,549 B they will start failing
   on **correct** output. `$out20` is at 22,158 B today (2.96× margin) and grows with the
   corpus. Converting them to the same `grep -c` form is mechanical and should be one
   sweep, not ten edits (P-26).
3. **`conformance.sh:449` uses `grep -an … | head -1`.** Safe today only because grep's
   *output* there is one or two lines. It is the same hazard reached from the other side
   and deserves a comment saying why it is safe, so a later reader does not "fix" it or,
   worse, copy the shape somewhere it is not safe.
4. **The `.claude/worktrees` exclusion is the only exclusion this lint prints; the hard-coded
   `('.git', 'node_modules', 'build', '.gradle')` prune list is NOT reported in the census.**
   T165's principle ("the graded root stays explicit") is applied to one of the two prune
   paths and not the other. A `.java` file under a `build/` directory is silently ungraded
   and the census says nothing. Low risk, but it is the same shape as the defect T173 fixed.
5. **P-57 now has a second, larger instance and P-58 a fifth rule's worth of evidence**
   (the threshold is a property of the producer/consumer *pair* — perl 64,776 vs bash
   builtin printf 65,549 on the same kernel). `patterns.md` is T192's file; recorded here
   so T192 can pick it up rather than rediscover it.
