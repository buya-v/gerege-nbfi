## MY counting rule, the population under it, and reconciliation of all three prior counts

### Rule R-T183 — stated before it was applied, implemented in `t183_count.py`

- **SITE** — an AST call that **truncates a file in place**: `open`/`io.open`/`codecs.open`
  with a mode containing `w`; `Path.write_text`/`write_bytes`; `os.truncate`.
  `os.replace` is **not** a site (atomic rename, P-48 rule 4).
- **UNGUARDED** — no enclosing `ast.Try` with a `finalbody` covering it, and no
  `atexit`/`signal` registration in the file. (I did not re-litigate T179's reachability
  model; I re-litigated its **target** model.)
- **TARGET** — read off the write call's own first argument, resolved by
  (a) module-level constant substitution, **and (b) one BACKWARD interprocedural step**:
  if the argument is a *parameter* of the enclosing function, take the union of the actual
  arguments at every in-file call site, resolved by (a). Anything still unresolved is
  UNKNOWN and is **printed**.
- **IN-POPULATION** — the resolved target is a ratified/frozen artefact:
  `docs/adr/DEC-<n>*.md` or `nexus/…/loanschedule/contract/contract.go`.
- **UNIT — one `(file, artefact-class)` PAIR.** A file that truncates both counts once
  under each. Per-file and per-site totals are printed alongside so every prior count is
  reconcilable rather than merely contradicted.

Step (b) is not a new capability: T179 **already takes the mirror-image forward step for
guards** (`indirectly_guarded_funcs` — "every in-file call of this function is inside a
try/finally"). It is the same analysis run in the other direction.

## Does the classifier follow imports? (the T178/T167 blindness, tested)

**No, and the blindness is real — but it lands differently from T167's, and in the more
dangerous direction than T179's docstring admits.**

`local_restoring_cms(tree)` reads restoring context managers from **this file's own AST**
only; `RESTORING_CM_NAMES` is a hardcoded stdlib set; `process_handlers` scans **this file's**
`atexit`/`signal` calls. `ast.Import`/`ast.ImportFrom` appear **once** in the whole 855-line
file, at line 405, and only to *skip* imports when seeding module reachability
[VERIFIED: `grep -n "Import" guard_classify.py`].

**Test (PROBE 1).** I built `mylib_guard.py` with a genuine restoring
`@contextlib.contextmanager` (`try/finally` + byte-for-byte `shutil.copyfile` restore) and a
genuine `atexit`-registered restore, then two callers whose **mutation is local** and whose
**guard is imported**:

```
--- UNGUARDED MUTATIONS OF A TRUSTED ARTEFACT (2 sites in 2 files)
  green_imported_atexit.py:10  io.open(mode='w')  tags=ADR   target: P
  green_imported_cm.py:14      io.open(mode='w')  tags=ADR   target: P
PROBE 1 exit=1
```

Both are **correctly guarded** and both are reported **UNGUARDED / TRUSTED**, and `--enforce`
**fires**. Consequence, and it matters more than the fixture: **the check punishes the exact
fix T178 applied.** Factor your guard into a shared module — the thing this program keeps
asking workers to do — and the enforcement step calls you unguarded.

**On the real repo files the manifestation is different, and worth stating precisely so
nobody over-claims either way.** T178 also moved the **write** into `t178_guard.py`, so on
`t47_edit_2.py` T179's tool reports **zero mutation sites**, not UNGUARDED
[VERIFIED: `--file .softhouse/reviews/t47-probe/t47_edit_2.py` → "mutation call sites found
in Python: 0"]. So T179 does **not** reproduce T167's specific mis-scoring of those eight
files. It reproduces the underlying blindness on the general shape, which I had to construct
because no committed file currently has it.

Secondary artefact of the same blindness, visible in the same transcript: the classifier
scores the restore *inside* `mylib_guard.preserved`'s `finally` as itself an unguarded
mutation (`mylib_guard.py:17 shutil.copyfile target: path`). T179 disclosed this class for
`green_try_finally.py`; it is a residual of the idiom, not a new defect.

## Bare assert under python3 -O

   appear **nowhere** in `guard_classify.py`, and the literal guard vocabulary is
   `("trap", "finally", "atexit", "__exit__", "contextmanager")` — no `assert`

   because F-1 proposes running `selftest.py` inside `conformance.sh`.
   `ast.Assert` node count is **0** in all five T179 scripts — `guard_classify.py`,
   `selftest.py`, `rederive_population.py`, `engine_divergence.py`,
   `list_trusted_unguarded.py` [VERIFIED, PROBE 2]. The selftest accumulates failures
   explicitly and exits non-zero. Proven, not inferred: **the sabotaged selftest still exits 1
   under `python3 -O`, in both sabotage directions** (PROBE 4). `-O` cannot neuter it.
