### What each successor changes

Both, identically in spirit:

1. **Every skip is NAMED and COUNTED** in a SKIP REGISTER — for t55: leg, capture id, cell key,
   exact raw text, exception type and message; for t44: path, exception type, message. The register
   **prints on every run, including a clean one**, so a zero is never inferred from a silence.
2. **A non-zero swallow count FAILS the run.** t44 additionally allows an explicit
   `--expect-skips N` acknowledgement which must match exactly; the count is still printed
   prominently and never rendered as zero.
3. **Zero inspected is an ERROR, not a pass (P-35).** t55 asserts and prints the I6 denominator per
   capture and in total, and the money-delta denominator per pair; zero captures, zero money cells
   or zero pairs each fail. t44 fails on zero globs, zero matched files or zero literals found.
4. **Every published figure is scoped to its denominator in the line that prints it** — t44's
   closing hazard paragraph now reads "over the 245 distinct literals actually inspected, in 110 of
   128 requested files … and says nothing whatever about the 18 file(s) in the SKIP REGISTER."
5. **t55 additionally measures a second, structurally different narrowing** the original has no
   name for: `cells()` keeps only `str`/`bool` leaves, so a JSON null, a bare number or a nested
   object is dropped **before I6 ever runs**. Reported as `MONEYISH leaves dropped by cells()
   before I6` (0 on the committed corpus).

Arithmetic unchanged in both: `decimal.Decimal` from exact decimal text, money differences in
integer minor units, no float on any verdict path (P-25). t44's `float()` calls are the original's
own hazard characterisation, retained and labelled.

**Definition used** (stated, because the count is a function of it): a swallow site is an
`except …:` handler whose **own body**, read to its own dedent, contains no statement that records
what was caught — no print/log/write, no append/store, no raise, no exit, no assert, no counter
increment, and no reference to a bound exception name. `pass` / `continue` / `break` /
`return <constant>` record nothing. **Narrow clauses are in scope**; clause narrowness is a
different defect.

### What this sweep structurally could not find (P-26 / P-40)

* A swallow written in Java, bash, Go or SQL — Python only.
* A `try/finally` with no `except` that returns a default.
* A handler that records to a variable nobody ever prints — counted as recording here; a weaker
  defect, but still one.
* **The largest blind spot: a swallow with no `except` clause at all** — `dict.get(k, 0)`,
  `re.match(...) or default`, a glob that matches nothing, a `continue` guarded by an `if`. The
  same vacuity with no exception in sight, and **no AST net over `except` can close it.** One
