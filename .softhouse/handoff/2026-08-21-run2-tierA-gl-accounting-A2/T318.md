## 2. What a sufficient check must cover — and where the boundary is

T304's four terms (HEAD, branch list, config identity, content) are a starting point. Two
of them are **wrong as stated** and there are **three more**.

### The reframing that makes the rest follow

**"Is the tree clean?" is not answerable, because cleanliness is not the property anyone
wants.** A worker is *supposed* to commit; a fire is *supposed* to move `tasks.json`. The
property wanted is **"the repo differs from before only in ways this operation was
authorized to produce"** — which is a relation between three things (before, after, writ),
and no predicate over a single state can express it. Every blind gate in §1 is blind
because it tries.

### The seven terms

| term | what it reads | catches |
|---|---|---|
| **T1** | `rev-parse HEAD` **and** `symbolic-ref HEAD` | commit, amend, reset, rebase, **branch switch at an identical SHA** |
| **T2** | `for-each-ref` over **all** refs | stray branch, tag, **notes**, **stash**, deleted ref |
| **T3** | `status --porcelain` | ordinary dirt — **still necessary, never sufficient** |
| **T4** | `status --porcelain --ignored` | a scratch leak behind a `.gitignore` fence |
| **T5** | `ls-files -v`, any tag ≠ `H` | **`update-index --assume-unchanged` / `--skip-worktree`** |
| **T6** | `config user.name/user.email/core.hooksPath`, `--git-common-dir` | identity forgery, `git init` over a live repo |
| **T7** | `rev-parse HEAD:<path>` for named invariant artefacts | a *committed* clobber of `tasks.json` / `RESUME.md` / `program.json` / `vectors/` |

**T2 corrects T304's "branch list".** `git branch --format` reads only `refs/heads`. It
cannot see `refs/tags`, `refs/notes`, `refs/stash`, or a ref planted at `refs/hidden/x` —
all three of which arm A6 creates and all three of which it misses. Must be `for-each-ref`
over everything.

**T5 is absent from T304's four entirely, and this repo documents the trick against
itself**: `.softhouse/capture/README-pass3i.md:51` — *"`git update-index
--assume-unchanged` silences `git status --porcelain` without moving `HEAD`."* It moves no
ref, changes no config, touches no HEAD. T1, T2, T6 and T7 **all** miss it. It is also the
term that catches the live kill chain in §4.

**`git stash` deserves naming separately.** It does not merely evade the legacy predicate,
it is **what makes the predicate report clean** — it empties the working tree into a ref.
It is also a protocol violation on its face:
`.claude/skills/softhouse-program/SKILL.md:76` — *"if dirty, commit `.softhouse/` state
only; **never stash worker WIP**."* So T2 treats a new `refs/stash` as damage
unconditionally, with no writ option to authorize it.

### The boundary — argued, because an over-broad check gets disabled

The task is right that this is what decides adoptability. Four rulings:

**(a) Ancestry, not equality — the single ruling that makes the guard usable.**
HEAD moving is *not* damage. HEAD moving to a commit that does **not contain** where you
started is. `git merge-base --is-ancestor $BEFORE $AFTER` distinguishes them, and every
legitimate commit in this program is a fast-forward from where the operation began. An
equality test would flag arms G1, G2, G3, G5 and G6 — i.e. every worker, every run — and
would be switched off within a fire.

**(b) A HEAD *ref* change is damage only when the writ does not name the new ref.**
I had this wrong. My first version flagged any symbolic-ref change, and **arm G5 caught
it** — `git checkout -b softhouse/<task>-<slug>` is the sanctioned worker workflow. Arm
**A5** (checkout -b to an *undeclared* branch, SHA byte-identical) stays red; **G5** goes
green. The correction came from the drive, not from reasoning.

**(c) T7 had to become a writ term, and *why* bounds what any such guard can do.**
In arm **A1** the clobber's own commit scored as an **authorized fast-forward on the writ
branch**; only the stray ref and the config rewrite made it red. A clobber that committed
over `tasks.json` and did **not** branch away and did **not** rewrite config would have
**passed**. I added arm **A1b** — that exact minimal clobber — and it was **green against
my own first guard**.

The reason is not fixable by more git archaeology: *"a legitimate commit that edits
`tasks.json`"* and *"a clobber that commits over `tasks.json`"* **are the same git
operation**. Nothing in the object graph separates them. The only distinguishing
information is whether the operation **declared** it would touch that artefact. So T7 reads
the writ: an invariant artefact may change only if `--writ-artefact` names it. **A1b** (not
declared) is red; **G6** — byte-identical mutation, artefacts declared — is green.

**(d) T4 is ADVISORY, not blocking, and that is a deliberate concession.**
A newly ignored file is real damage-adjacent evidence (T314's corollary to P-94), but the
term will also fire on `.DS_Store` and editor droppings. A blocking term that cries wolf on
`.DS_Store` gets the whole guard disabled, and a disabled guard is worth less than a blind
one. It warns, names the file, and does not fail the run.

### What I deliberately excluded, and why — the over-broad side

- **Reflog.** It is how T304 *diagnosed* the clobber, and it is wrong as a *gate*: per-clone,
  expires under `gc.reflogExpire`, absent in a fresh clone, and records every legitimate
  checkout. Diagnostic, not predicate.
- **`git fsck` / dangling objects.** A commit made and then fully `reset --hard` back leaves
  a dangling object while the tree and every ref are **identical**. That is not damage, and
  flagging it flags every abandoned `--amend`. Also minutes of runtime on 7k files.
- **`git count-objects`.** Same, plus it moves on `gc`.
- **File mtimes.** Not repo state.
- **`.git/hooks` file contents.** `core.hooksPath` is in T6; the hook *files* are untracked
  and vary per clone. Named as a residual gap rather than covered — see Unverified.
