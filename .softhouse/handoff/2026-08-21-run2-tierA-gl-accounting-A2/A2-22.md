### Which refusal classes can contribute kills — A2-19 could not close this; it is closed.

There are exactly five refusal reasons, all reachable from `gradeVector`
`[VERIFIED: capability.go RefusalReason consts; grade.go gradeVector]`. A refused
vector contributes coverage for capability `C` iff it is `ClassParity`, `C` is in its
`capabilities_required` (admission enforces `cf.Capability ∈ capabilities_required`,
`admit.go:248`), `C` is `in_graded_domain`, and `StructuralKillIsCompared` holds. Each
class was driven RED with a constructed fixture, so this is measured, not argued
(`TestRefusedVectorCannotBackACapability`, five subtests, all five failed on the
unfixed code):

| Reason | Can it carry kills? | How |
|---|---|---|
| `SEAM_BLIND` | **Yes** `[VERIFIED: red-go-test.txt/SEAM_BLIND]` | Refusal is triggered by capability *D* being blind; a *different* required capability *C* can still be exercised + graded, and its kills were credited. |
| `UNGRADED_CAPABILITY` | **Yes** `[VERIFIED: red-go-test.txt/UNGRADED_CAPABILITY]` | Same shape: *D* exercised-but-ungraded refuses the vector, *C* still credits. |
| `UNKNOWN_CAPABILITY` | **Yes** `[VERIFIED: red-go-test.txt/UNKNOWN_CAPABILITY]` | An undefined *D*, or a seam with no recorded status for *D*, refuses; *C* still credits. |
| `UNKNOWN_SEAM` | **Yes** `[VERIFIED: red-go-test.txt/UNKNOWN_SEAM]` | `IsGraded` reads the *capability*, never the seam, so an entirely unknown seam removed nothing from coverage. |
| `UNGRADED_REQUEST` | **Yes — and it is the worst of the five** `[VERIFIED: red-go-test.txt/UNGRADED_REQUEST]` | The capability gate passes **in full** (every required capability exercised AND graded) and the vector is refused purely on a request field value. So **every** kill such a vector names was credited, not merely some. |

**One sub-case provably cannot contribute**, and it is worth naming so the table is not
read as "all of it": the `UNKNOWN_CAPABILITY` arm reached by *empty*
`capabilities_required`. Admission requires every counterfactual's capability to appear
in `capabilities_required`, and a parity vector must carry at least one counterfactual
`[VERIFIED: admit.go:225-250]` — so such a file is INADMISSIBLE, never REFUSED, and
inadmissible was already excluded.

## Changes Made

Three files under the scope guard, plus one line of an existing test.

**`capability.go`**

- **New `(*CapabilityRegistry).RefusalFor(v *Vector) CapabilityVerdict`** — the refusal
  predicate for a whole vector, extracted verbatim from `gradeVector`'s two inline
  blocks (`Assess`, then `GradedDomain` when `expect.kind == "schedule"`), same
  precedence. It existed nowhere a second reader could call it, which is *why* the
  coverage report never asked. It deliberately does not re-check admissibility: that
  needs the pin and the repo root and is a different question.
- **`CounterfactualCoverage` now skips any vector it would itself refuse.** It decides
  this for itself rather than trusting the caller, because trusting the caller is the
  defect. Re-asking is idempotent — a caller that already filtered gets the same answer.

**`grade.go`**

- `gradeVector` now calls `RefusalFor` instead of duplicating the two checks. Behaviour
  identical; one predicate, one answer.
- The coverage/kill-count population changed from *"every vector not INADMISSIBLE"* to
  *"every vector actually GRADED"* — refused vectors are now excluded from
  `CounterfactualCoverage`, `CounterfactualsNamed`, `MoneyKills`, `StructuralKills` and
  `CorroborationsClaimed`.
- New `Summary.RefusedCounterfactualsNamed` and `Summary.RefusedCorroborationsClaimed`:
  the claims that were shed, **counted, not dropped**.

**`report.go`**

- `counterfactuals named by admissible vectors:` → `… by GRADED vectors:`; likewise for
  the corroboration line. The old word was the bug written down.
- New disclosure block, **printed whether or not it is zero** (P-35 — a line that only
  appears when something is wrong is indistinguishable from one that never ran):
  ```
  kills carried by REFUSED vectors: 0, credited to NOTHING (0 corroboration claims likewise)
      A refusal is not a pass and not a failure: it says no discriminating vector exists here, or
      the seam is blind to the behaviour. A vector that graded nothing kills nothing, so its named
      kills do not enter the count above and do not remove a capability from the UNBACKED list.
      Until A2-22 they did both, and a refusal therefore made this report QUIETER — the one case
      with LESS evidence going silent (finding A2-19 F3).
  ```

**`structural_test.go`** — one asserted report string updated for the
`admissible` → `GRADED` wording. No assertion weakened; the numbers it checks
(`3 (1 money, 2 structural)`) are untouched.

**`coverage_refusal_test.go`** (new) — the census and the two red/green proofs.

**Direction of the change: strictly LOUDER, never quieter.** A capability that loses its
last backing vector to a refusal now becomes `UNBACKED`, which is a fatal reason and
`exit 2`. There is no input on which this fix suppresses something the old code
reported. The one thing that could have gone silent — the shed kill count — is printed.

## Money-math notes

**No money arithmetic was added, removed or altered by this change.** Nothing in the
diff reads, writes, rounds or compares a monetary amount. `MarginMinor` on the
constructed test counterfactuals is a decimal *string* of minor units (`"1"`), the same
representation the store uses. The no-float census walked the new file along with the
rest of the module and reported `0 forbidden identifiers, 0 floating-point or imaginary
LITERALS, 0 forbidden imports, 0 unscannable files` across 5 packages / 45 files /
89999 tokens — the file count rising from 44 to 45 is what shows the new file was in
scope `[VERIFIED: green-conformance.txt vs baseline-conformance-main-cc33f7f.txt]`.

What *did* change is which kills are allowed to count as evidence about money math —
and it changed in the conservative direction only. A refused vector's money kill is now
withheld from `MoneyKills` rather than credited, which can only ever move a capability
*into* the `UNBACKED` list and the run *toward* `exit 2`.

## Follow-ups

1. **`CorroborationsClaimed` was narrowed to graded vectors too, on the same reasoning,
   but with no independent finding behind it.** A refused vector's cross-check claim is
   equally uncashed, and leaving it credited inside the same loop that now withholds
   kills would have been an inconsistency a reader would have to explain. It is
   disclosed separately as `RefusedCorroborationsClaimed`. Both counts are 0 on the
   committed store, so this cannot be distinguished from the alternative today. Worth a
   reviewer's eye: if the narrowing is unwanted, it is a two-line revert in `grade.go`
   and the disclosure line already exists to make either choice legible.
2. **The `graded_against` / `capabilities_required` containment rule now does real work
   in two places.** Admission enforces it (`admit.go:248`); coverage relies on it to
   reason about which capabilities a refused vector could have credited. If that rule is
   ever relaxed, this fix's blast-radius table needs re-deriving.
3. **`Summary.Errored` vectors still credit coverage** — see Unverified. If a future
   change makes `OutcomeError` reachable for reasons other than "no implementation", this
   should be revisited in the same breath.
4. **Consider a standing assertion that `Refused > 0` implies at least one line of the
   report names the refused vectors' withheld kills.** The disclosure exists and is
   asserted by the end-to-end test, but only on the perturbed fixture; there is no guard
   that it can never be deleted while the counts remain.
