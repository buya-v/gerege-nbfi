## Routes to an empty population, enumerated

"Empty population" = `--enforce`/`--enforce-unknown` exits without a single
successfully-parsed Python file to judge. Two structurally different ways to reach
it, and I closed both:

**A. `results` itself is empty (pre-existing, already closed).** `--root <dir>` where
the walk finds zero `.py`/`.sh`/`.bash` files (an empty directory, everything
excluded via `--exclude`, or only non-script extensions). Caught by the pre-existing
`if not results: return 3` guard at the top of `main()` — unchanged by this task,
verified still fires:
```
$ python3 guard_classify.py --root /tmp/truly-empty-dir --enforce
ERROR: zero files inspected — an error, not a pass (P-35)
EXIT=3
```

**B. `results` is non-empty but every entry is a refusal (the actual T212 gap, now
closed by the `py_inspected` guard).** Every route below reduces to the same
underlying condition — `report()` would print "of which Python, parsed: 0" — and all
are now caught by the single new check, not by six separate special cases:

| # | route | mechanism | refusal reason | driven? |
|---|---|---|---|---|
| 1 | `--file <path>` does not exist | `open()` → `FileNotFoundError` | `REFUSED-UNREADABLE` | **RED 1** |
| 2 | `--file ""` (empty-string arg — what an "empty `--file` list" collapses to under `IFS=',' read -ra arr <<< ""`, which yields one empty element, not zero) | `os.path.abspath("")` = cwd, a directory; `open()` → `IsADirectoryError` | `REFUSED-UNREADABLE` | **RED 2** |
| 3 | `--file $DIR/*.py` where the glob matches nothing and the shell (bash, nullglob off — the default) passes the literal pattern text through as one argument | `open()` on the literal, nonexistent path → `FileNotFoundError` | `REFUSED-UNREADABLE` | **RED 3** |
| 4 | `--file a.sh --file b.sh` (only shell files named) | no shell parser exists at all | `REFUSED-SHELL-NO-PARSER` (all) | bonus, driven |
| 5 | `--file bad.py` where `bad.py` has a syntax error | `ast.parse()` raises `SyntaxError` | `REFUSED-PYTHON-SYNTAXERROR` | bonus, driven |
| 6 | `--root $DIR` where `$DIR` contains only `.sh` files (no `.py`) | same as #4, via the sweep path instead of `--file` | `REFUSED-SHELL-NO-PARSER` (all) | bonus, driven |
| 7 | `--file` path exists but permission is denied (`chmod 000`, confirmed not running as root — `id -u` = 501) | `open()` → `PermissionError` (subclass of `OSError`) | `REFUSED-UNREADABLE` | bonus, driven |
| 8 | `--file` path has a non-script extension (`.txt`, etc.) | `classify_path`'s final fallback | `NOT-A-SCRIPT` | bonus, driven |

**What I could NOT close, and why it doesn't need closing.** A literal
"`args.file == []` but still take the `--file` branch" is not reachable through the
CLI at all: `argparse action="append"` only ever *adds* to `args.file` when `--file`
is given a value, so zero `--file` flags means `args.file` stays `[]`, and
`if args.file:` (line 1393) is then false — the code always falls through to the
`sweep()`/`--root` branch (route A above), which was already guarded before this
task. I did not add a redundant guard for an unreachable state; I verified the
unreachability by reading `main()`'s branch condition rather than asserting it.
