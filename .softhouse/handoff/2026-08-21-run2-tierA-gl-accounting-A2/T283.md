## Findings

### F-T283-1 — HIGH, fail-open, **REPAIRED IN THIS BRANCH**. The verifier says VERIFIED over artefacts it has itself computed to disagree

`_crosscheck()` refuses to write a `MISMATCH (…)` line in **derive** mode and *renders* one in
**verify** mode, with the comment: *"the disagreement is rendered as a line that can never equal what
`derive` wrote, and the comparison reports it."* The first half is true and the second half does not
follow — **`verify` never compares against what `derive` wrote.** It compares against what it
re-derives now, and the sidecar is the artefact under suspicion. A forger who rebuilds the sidecar
with the module's own builder gets `MISMATCH` on both sides, an exact match, and `VERIFIED` rc=0.

Three shapes, each captured live and each accepted [MEASURED:
`.softhouse/reviews/t283-review-t274/evidence/10-forgery-arms.txt`]:

```
  FA   the committed request body replaced (46 -> 60 bytes); reqhdr UNTOUCHED
       wire record still says   Content-Length: 46
       committed artefact is    60 bytes
       ACCEPTED sidecar says    content-length-crosscheck: MISMATCH (Content-Length 46, artefact 60 bytes)
       verifier says            VERIFIED ... rc=0

  FB   NAME.status rewritten 400 -> 201; resphdr UNTOUCHED
       ACCEPTED sidecar says    response-status-crosscheck: MISMATCH (status file '201', wire 400)
       and simultaneously       response-status-line: HTTP/1.1 400
       verifier says            VERIFIED ... rc=0

  FC   NAME.json replaced by ANOTHER capture's response (468 -> 264 bytes)
       ACCEPTED sidecar says    response-content-length-crosscheck: MISMATCH (Content-Length 468, artefact 264 bytes)
       verifier says            VERIFIED ... rc=0
```

This is inside T274's own written CLAIM: *"the sidecar, the two committed wire records, the request
body artefact, the RESPONSE BODY artefact and the `.status` file CANNOT DISAGREE UNDETECTABLY."*
They disagree, the module computes the disagreement, prints it into its own expected text, and exits
0. FB is the one that would matter first in this program: **a capture's HTTP status is what decides
whether a vector records an acceptance or a refusal**, and it can be rewritten with two file edits.

**The repair** (`.softhouse/capture/lib/wire_attestation.py`, in `cmd_verify`, before the
re-derivation compare):

```python
    for line in extras:
        if line.partition(":")[2].strip().startswith("MISMATCH ("):
            failures.append(
                "the wire record and a committed artefact DISAGREE -- %s. `derive` "
                "REFUSES to write this line, so a sidecar that repeats it does not "
                "settle it: a disagreement the sidecar agrees with is still a "
                "disagreement" % line)
```

**Why it is safe, and why it is a verdict rather than a refusal.** `derive` raises `Refuse` rather
than writing one of these lines, so **no honestly derived sidecar can contain one** — the change can
therefore only move a case from 0 to 1, never from 0 to 2 and never 1 to 0. It is a **verdict** (1)
and not a refusal (2) because every artefact is present and readable; what they say is NO. It is
generic over the key rather than a list of the three crosschecks, because a list of things we check
is the exact shape T274 removed.

**Red → green, same instrument, one variable:** `T283_FIXED=1` flips only the three expectations.

```
  RED  (T274 as committed, 5e0ae9a4…)   FA 0   FB 0   FC 0    10 as expected, 0 unexpected
  GREEN(repaired,          6daf0c2c…)   FA 1   FB 1   FC 1    10 as expected, 0 unexpected
  and NOTHING ELSE MOVED: FP0 0, FN 1, FA2 0, FC2 0, FD 0, FD2 0, FE 0 in both arms
```
[MEASURED: `evidence/10-forgery-arms.txt` vs `evidence/11-forgery-arms-after-fix.txt`]

**Regression sweep after the repair, all live:** T274's four-routes instrument **18 as expected, 0
unexpected**; the wrap boundary **17 lengths EXACT + record byte-identical**; T250's arms **9 as
expected, 0 unexpected**; my own shapes/error-paths instrument **20/0**; the BAR **PASS, exit 0**.

### F-T283-2 — MEDIUM, false statement in the shipped module, **REPAIRED IN THIS BRANCH**. The stated unforgeability limit is cheaper than stated, and the response leg is the part that matters

The docstring said: *"Tamper the sidecar AND the records AND the digests CONSISTENTLY and you have
forged a matched artefact set."* That reads as four coordinated edits. **The records do not have to
be touched at all.** Nothing committed digests either body — the `.reqhdr` / `.resphdr` records carry
`Content-Length` and nothing more — so a **same-length** swap plus a re-derived sidecar is **two file
edits**, and the accepted sidecar is *shape-identical to an honest one*: crosscheck `MATCH`, zero
`MISMATCH` lines, nothing for a reader to notice.

```
  FA2  probe.req  46 -> 46 bytes, different bytes   a4e0d3eeb2768121 -> 16130a6a374351ba
       ACCEPTED sidecar: content-length-crosscheck: MATCH (46 bytes)   confession: 0 lines
  FC2  probe.json 468 -> 468 bytes, an answer the oracle NEVER GAVE
       ACCEPTED sidecar: response-content-length-crosscheck: MATCH (468 bytes)  confession: 0 lines
```
[MEASURED, and **still accepted after my repair** — this one is not fixable by a verdict rule.]

FC2 is the sharp one and it lands squarely on T274's headline addition. T274 attested the response
because *"a golden vector is graded on the oracle's ANSWER, not on the request"* — correct, and the
answer can now be replaced silently for the price of one extra file edit. T274's own arm 7a already
measured that attesting the response *"raises the COST of forging and does not narrow the
unforgeability limit at all"*; I am extending that honest finding to its true price and putting it
where a reader meets it. The docstring now says: read a `VERIFIED` as **"these six files agree"**,
never as "this is what the oracle was asked and answered", and names `MANIFEST.sha256` /
`capture_sha256` as the controls that carry the rest.

### F-T283-3 — MEDIUM, false statement in the shipped module, **REPAIRED IN THIS BRANCH**. The schema downgrade DOES buy a pass, if the caller is the one being deceived

The docstring said: *"Deleting the schema line to escape the response checks therefore does not yield
a pass; it yields a refusal, which is the whole point."* T274's control `P2` proves that **for a
caller that still presents a response artefact**. Withhold the response artefacts as well — which the
same forger controls — and:

```

       --resp/--resphdr/--status not supplied
```

[MEASURED, arm FE — unchanged by my repair.]

The module cannot know an artefact exists if it is not handed one, so this is a **caller contract**,
not a verifier bug — but it was written as a property of the verifier. The docstring now states the
precondition and the caller's duty. `oracle_send` discharges it; a future caller must too, and this
is the thing T269 has to get right when it wires anything.

## What I could not verify

* **HTTP/2, redirect chains, chunked responses, `Content-Encoding`** — T274 flagged these
  [UNVERIFIED] and they remain so. This oracle answered HTTP/1.1 with `Content-Length` and no
  encoding on every one of my ~40 captures too. FU-T274-2 stands.
* **`captured-at-utc:`** is not derivable; I confirmed its presence is required and its **value** is
  taken on trust. A capture can be back-dated freely and nothing here can tell.
* **The 226 (now 248) legacy `tierA-a2` sidecars.** Unattested by this rig and unattestable by it.
  Nothing in this review says they are wrong.
* **Whether my `MISMATCH` rule is complete for crosschecks that do not yet exist.** It matches on the
  rendered value prefix, which is the same convention `_crosscheck` uses; a future crosscheck that
  renders a disagreement with different wording would slip past it. That is a smaller version of the
  defect it fixes, and the durable form is for `_crosscheck` to return a `(text, ok)` pair. I did not
  make that change: it touches `derive`'s path too, and this is a review.
* **The BAR's ledger and vector arms** were re-run, not re-derived; I did not independently re-derive
  the 7884 cells.
