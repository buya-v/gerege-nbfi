## Changes Made

### 1. THE FIX — resolution is now `git ls-files`, and the disk is never consulted

`.softhouse/capture/t316-dead-path-guards/census_dead_paths.py` — `resolves()` replaced.

- **Was** `os.path.exists(repo_root / literal)`.
- **Is** membership in the set of tracked paths from `git ls-files -z`, or in the set of their
  directory prefixes; `.`/`..`/`//` collapsed **lexically** with `os.path.normpath`, which
  touches no filesystem; a path that normalises outside the root is unresolvable. The
  trailing-punctuation arm is unchanged and is still only ever consulted to say YES.
- New `tracked_universe()` **REFUSES (exit 2) on an empty tracked set** — an empty universe would
  make every literal dead and report a spectacular false finding.

**Why the index and not `git ls-tree -r HEAD`, stated in the source:** on any clean checkout,
clone or worktree the two are identical, so host-independence is unaffected; but a worker who
adds an instrument *and* the file it references in one change should be green before committing,
not after. Neither reads untracked or ignored paths, which is the load-bearing half.

**Two predicates, two fail-closed directions, deliberately NOT merged** (the shape T292 named as
the root of a five-fix losing streak) — written into `check-dead-path-frontier.sh`'s header:

| predicate | source of truth | fail-closed direction |
|---|---|---|
| the guard's **own dependencies** (census script, pin, python3, scratch dir) | **ON DISK**, `[ -f ]`, miss ⇒ exit 2 | "if I cannot REACH what I grade, I have not graded it" — you cannot execute a file that is not there |
| the **frontier's classification** | **tracked set**, never the disk | "the verdict must be a property of the commit, on any host" |
