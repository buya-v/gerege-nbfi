The head returns 0 clean / 1 refusal / 2 unusable. `run_guards` maps **any** non-zero to
`failed=1` and exits `EXIT_UNUSABLE` (2). That is the correct reading and needed no edit: a
failed HARD guard means **no verdict is available**, not a FAIL verdict. `EXIT_UNUSABLE` and
`run_guards`'s trailing block are byte-identical to `main`.

The wrapper preserves the head's exit code across the limits notice:

```bash
guard_ledger_invariants() {

  bash "$REPO_ROOT/.softhouse/guards/check-ledger-invariants.sh" || rc=$?

  return "$rc"

```

`rc` is captured, not inferred from `$?` after the `say`s — under `set -u -o pipefail` the naive
form would have returned the exit status of the last `say`, i.e. **always 0**, which is the
"wired guard that has been quietly neutered" failure the file's own comment at line 736 warns
about. No `| grep -q` and no `| head` was added (P-57 rule 1).

## 6. CARRYING THE LIMITS THROUGH — AND A CORRECTION TO A2-18 §7

The task required that the guard's `NIL-COVERAGE` and `CANNOT-CATCH` notices survive into the
harness output. **Measured, they behave differently, and A2-18 §7's "printed by the guard on
every run, pass or fail" is true of the GUARD but not of its HEAD.**

| notice | standalone head, PASS path | wired harness, PASS path | refusal path |
|---|---|---|---|
| `NIL-COVERAGE` (2 lines) | printed | **printed, verbatim** | printed |
| `CANNOT-CATCH` (33 lines) | **NOT printed** | **NOT printed** | printed (stderr) |

The mechanism, at `check-ledger-invariants.sh:185`: the head captures the guard's stdout into a
variable and, on the pass path, re-prints only

```
printf '%s\n' "$out" | LC_ALL=C grep -a '^CENSUS \|^NIL-COVERAGE ' | …
```

so `CANNOT-CATCH` is filtered out. On the refusal path the head warns every line that is not a
`CENSUS ` line, which is why the full 33-line block *does* appear in the RED transcripts in §3.

**So wiring did not drop anything.** The `NIL-COVERAGE` block reaches the harness transcript
verbatim — including the load-bearing sentence that this Go tree has no DB driver and no SQL, so
the I-4 SQL classes are proven by the guard's `--selftest` and **not** by this tree. What is
missing was already missing standalone, and the head's own PASS text ends *"Read the
CANNOT-CATCH block"* — pointing at a block that, on a green run, is nowhere in the output.

That is a defect in the head. **The head is A2-18's artefact and `.softhouse/guards/` is outside
T208's scope, so it is RAISED (FU-T208-1), not fixed.** What *is* in scope is refusing to let a
green harness transcript carry this verdict without its limits, so the wrapper prints 8 lines on
every run, pass or fail, naming the load-bearing ones:

```
conformance: ledger-invariants LIMITS (CANNOT-CATCH, condensed; the full 33-line block is
conformance:   the cannotCatch const in .softhouse/guards/ledgerguard/main.go, which the
conformance:   guard prints on every run and its head DROPS on the pass path — FU-T208-1):
conformance:   the detection surface is the NAME, so RENAMING A BALANCE DEFEATS THIS GUARD;
conformance:   dynamic SQL is caught only through the call set it recognises; triggers,
conformance:   migrations and stored procedures are not walked at all; I-5's semantic half
conformance:   and non-Go callers are not covered. A PASS here means 'no violation is visible
conformance:   to a source-level guard over the Go tree', NOT 'the ledger tree is covered'.
```

**THE TRADE, STATED RATHER THAN TAKEN SILENTLY.** 8 lines per run against 33 for the full block
(the whole green transcript is 198 lines; the full block would be ~19% of it). The condensation
loses the two measured over-matches (§5 of A2-18), the `_test.go` fail-closed choice, and the
detail of each limit. If 8 is judged too thin, **the fix is FU-T208-1** — make the head print the
block, putting it back at its source — **not** a longer copy maintained in `conformance.sh`,
where it would drift away from the guard it describes. That is the recommendation.

## 7. WHAT THIS DOES AND DOES NOT LICENSE

- **Does:** DEC-2 §5.3 P-8 is met at grade time. A balance write or ledger DML introduced into
  `nexus/` from now on turns the conformance run red at exit 2, before the oracle probe.
- **Does not:** it does not make DEC-2 §4.4.1 false in general. Items 1-10 of A2-18 §7 are
  unchanged — **renaming a balance still defeats this guard**, triggers/migrations/stored procs
  are not walked, I-5's semantic half is not covered, non-Go callers are invisible. The I-4 SQL
  classes remain proven by the guard's selftest and **not** by this tree, because this tree has
  no SQL (NIL-COVERAGE, printed on every run).
- **Does not:** it grades no money. DEC-2 §4.4 I-1/I-2 (debits = credits, splits sum to whole)
  are vector questions and are untouched here. This wiring must never be cited as though it
  covered them.
- **Does not** amend DEC-1 or `contract.go`, and **does not ratify DEC-2**.
