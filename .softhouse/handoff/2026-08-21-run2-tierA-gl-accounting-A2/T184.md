## The byte-preservation property: implemented as described?

**The property is implemented, it is the weaker one T173 says it chose, and it holds on the
committed corpus (278 float-shaped tokens present, 0 altered).** T173's reasoning for choosing
it — that a blanket ban would refuse 221 of 320 committed bodies and pin the harness at exit 2 —
is measured, and I reproduced the 221. On that, T173 is right and honest.

**But the property is named more strongly than it is implemented (F1).** `defect_render`
(`check_wire_float_roundtrip.py:120-124`) branches on token kind: `int` tokens go through
`json.dumps(int(tok))`, `float` tokens through `json.dumps(float(tok))`. Python's `int` is
arbitrary-precision, so **no integer token can ever be flagged**. I measured the gap by calling
`defect_render` directly against a true binary-double round trip:

| token | kind | guard renders | a TRUE binary-double round trip | guard flags? |
|---|---|---|---|---|
| `1200000` | int | `1200000` | `1200000.0` | no |
| `1200000.00` | float | `1200000.0` | `1200000.0` | **YES** ← the T163 defect |
| `21.6` | float | `21.6` | `21.6` | no ← a rate, correctly passed |
| `1162502.5` | float | `1162502.5` | `1162502.5` | no ← the half-cent tie probe, correctly passed |
| **`9007199254740993`** | **int** | `9007199254740993` | **`9007199254740992.0`** | **no** ← a 1-minor-unit residue, waved through |
| **`12345678901234567890`** | **int** | `12345678901234567890` | **`1.2345678901234567e+19`** | **no** |
| `12345678901234567890.12` | float | `1.2345678901234567e+19` | same | **YES** |
| `1e2` | float | `100.0` | `100.0` | **YES** |
| `-0` | int | `0` | `-0.0` | **YES** |

`[VERIFIED: /tmp/t184-property.sh, importing the guard module directly]`

**Is that a defect?** Against the defect model it was built for — T163's P-25, a *Python* rig
script doing `json.load` then `json.dumps` — the int branch is **faithful**: Python preserves
int-ness, so no residue can arise, and flagging every integer would refuse all 3698 integer
tokens in the corpus. So I am **not** asking for the behaviour to change.

What I am asking is that four strings stop claiming the stronger property, because
**integer minor units is exactly the token class the int branch waves through**, and CLAUDE.md's
first non-negotiable makes that the class money lives in. The day a capture rig round-trips a
body through any *double-based* JSON tool (`jq`, Node, any JS), an integer minor-unit amount
above 2^53 is silently mangled and this guard reports clean. At 2 minor units per MNT, 2^53 is
~90 trillion MNT, so the exposure is theoretical **today** — but the sentence is what a later
agent will rely on, and it currently promises cover the code does not provide.

The general ruling on wire money form is **T186**, running in parallel; I have not pre-empted it
and I take no position on whether `principal: 1162502.5` belongs on a wire. This is only about
whether T173's guard does what T173 says it does.
