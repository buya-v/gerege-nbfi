## 2. The three-way (four-way) verdict, and the ARGUED `merged` action

Full argument in `.softhouse/capture/t330-reconcile-merged-work/design.md`. Summary:

| verdict | evidence | action |
|---|---|---|
| `merged` | commit subject on `main` matching `<TID>:` / `Merge <TID>:`, **or** `<TID>.md` handoff tracked on `main` | **REFUSE to demote** |
| `relocated` | a live ref (loose **or** packed) carries `<TID>` under another spelling/case | **REFUSE to demote** |
| `unstarted` | all signals **ran**, all empty | demote → `needs_retry` |
| `indeterminate` | any signal **did not run** | demote → `needs_retry`, note says UNVERIFIED |

`relocated` is a fourth verdict because arms (c) and (d) are neither merges nor
unstarted, and folding them into `merged` would have made the note lie about *why* it
refused.

### The decision: REFUSE to demote. Do NOT promote. (ENGINEERING gate, decided.)

Four options, all weighed under "this runs unattended inside a SIGTERM handler":

- **Promote to `done`/`merged` — REJECTED.** The reconciler establishes *a commit or
  handoff bearing this id is reachable from `main`*. `done` asserts *this dispatch
  completed and a reviewer signed it off*. Those differ: a partial `TID: WIP` commit, or
  a task re-opened under the same id, both carry the same evidence. This function's own
  note has said **"Completeness UNVERIFIED: no handoff was signed off and no reviewer saw
  this"** since before T330 and that is still true. `P-22` — *"A guard, a canary, or a
  control that cannot fail is worse than none — because it is believed"*
  [VERIFIED: `.softhouse/patterns.md:442`]. `done` is in `TERMINAL`
  [VERIFIED: `ready-tasks.py:164`], so it satisfies dependency edges and is never looked
  at again. **The asymmetry is the argument: a wrong demotion costs one duplicated worker
  and gets a human who looks; a wrong promotion costs the work and gets nobody, ever.**
- **New status `needs_adjudication` — REJECTED.** `NOT_RUNNABLE`
  [VERIFIED: `ready-tasks.py:165`] is a closed allow-list; a word not in it is
  **runnable**, i.e. fail-OPEN toward dispatch — the P-77 shape this file has been bitten
  by twice.
- **`parked` — REJECTED.** Mechanically fine, but in this program it means "blocked on a
  `user` gate" and is read out of `gates.md`. It would assert a gate that does not exist.
- **REFUSE: leave the status, rewrite the note — CHOSEN.** `in_progress` already prints
  as *"ALREADY DISPATCHED, do not dispatch again"*, is bucketed away from `ready`
  [VERIFIED: `ready-tasks.py:1364-1370`], and is **not** in `TERMINAL`. Zero vocabulary
  invention. Decisively: **the note lands in `tasks.json`, which is committed** — the
  finding survives the fire in the file the next fire actually reads, rather than in a log
  nobody opens.

**Costs stated, not glossed.**
(a) The file keeps an `in_progress` line with no live worker. Mitigated three ways: the
note says so verbatim, the report prints `*** REFUSED TO DEMOTE ***` per task plus a
`T330 REFUSALS:` roll-up and a count on `RESULT:`, and `--list` now prints
`RECONCILE WOULD: …` at STEP 0.
(b) `in_progress` is not `TERMINAL`, so **downstream tasks stay BLOCKED until a human
adjudicates.** That is the fail-closed direction and it is named in the note. *A blocked
successor is recoverable; a silently-dropped predecessor is not.*

**Idempotence — a defect the refusal introduces, found and closed.** A refused task keeps
its status, so this branch runs on **every** subsequent fire, and the pre-existing writer
appends `[prior note: …]` each time — unbounded growth in a 962 KB file. The refusal note
carries `[T330-REFUSED-DEMOTION]`; a note this function already wrote is **replaced, not
nested**. Measured over 5 consecutive reconciles: **1911 chars, unchanged** (`e2e.txt`).

## 4. Budget — measured, and the naive shape rejected on the measurement

`reconcile_bounded` derives its bound in `fire-program.sh` (**NOT EDITED — T325 owns it**):
`budget = SIGNAL_GRACE_SECS(20) − elapsed − GIT_PUSH_TIMEOUT_SECS(10) − 2`, then
`inner = budget − RECONCILE_TAIL_RESERVE_SECS(1)` ≈ **7 s outer / 6 s inner**, and below
`SIGNAL_RECONCILE_MIN_SECS(2)` the whole reconcile is **skipped loudly**.

**The three signals as the observation phrased them are per-task git calls, and they do
not fit** (`budget.txt`):

| | measured |
|---|---|
| `git log --grep='^Merge <TID>:'` | 0.1214 s |
| `git log --grep='^<TID>:'` | 0.1193 s |
| `git ls-files '<handoff>/<TID>.md'` | 0.0337 s |
| **per task** | **0.2743 s** |
| × N=20 | 5.49 s — fits, barely |
| × N=100 | 27.4 s — **blows the 6 s inner budget** |
| × N=219 | **60.1 s — blows it 10×** |

**So they are not run per task.** Two git calls build an index **once**, for any N:

| source | call | cost | scales with N? |
|---|---|---|---|
| commit subjects on `main` | `git log main --format=%H%x09%s` | 0.1196 s | **no** |
| handoff paths on `main` | `git ls-tree -r --name-only main -- .softhouse/handoff` | 0.0402 s | **no** |
| ref store | `branch_sweep.RefIndex` (`os.walk` + `packed-refs`) | **0 subprocesses** | **no** |
| **total** | | **0.1598 s** | |

**~410× cheaper than the naive shape at N=219.** Per-task cost after that is a dict lookup
plus one compiled-regex scan.

Two sub-decisions, both measured rather than assumed:
- **`--grep` rejected.** One generic `--grep` costs **0.154 s** vs **0.131 s** with no
  grep — git walks every commit either way and the regex is pure overhead.
- **`ls-tree main` used instead of the `ls-files` the observation named.** Same cost
  (0.04 s), but `ls-files` answers about **the index of whatever checkout it runs in**,
  and a worker worktree's index is not `main`.

**End-to-end, worst case** — all **140** branched tasks in the live file, not the
convenient `in_progress = 3`: **+0.642 s, +5.5 %**, of which 0.1598 s is the one-time
index.
