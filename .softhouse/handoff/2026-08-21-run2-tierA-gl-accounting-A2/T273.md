## Changes Made

### 1. `.softhouse/capture/t234-sweep-instrument-audit/instruments/02-escape-matrix-fix.sh` — the defect itself

`C=/tmp/t234_matrix2.txt` at :6, created on :7 by `{ … } > "$C"`. The fail-open linter's C1
rule reads the literal in an assignment position and asks `os.path.exists`; its owned-path
filter searches the file text for a literal `> /tmp/t234_matrix2.txt` and the redirection is
through a variable, so the filter never fired
[VERIFIED: `50-failopen-lint.py:336-371`, `_dead_paths`, `RE_OWNED_HEAD + re.escape(p)` over
`txt`, and `RE_ABSPATH_LOC`'s `[A-Za-z_][A-Za-z0-9_]*=` lead alternative]. The answer to
`exists` was therefore YES only on a host where this instrument had already been run once.

Repaired to a scratch directory the instrument owns and removes:

```sh
D="$(mktemp -d "${TMPDIR:-/tmp}/t234-escape-matrix.XXXXXXXXXX")" || exit 2
trap 'rm -rf "$D"' EXIT
C="$D/matrix2.txt"
```

An `XXXXXXXXXX` template is not a path and the linter drops it before the `exists` call
[VERIFIED: `50-failopen-lint.py:365`, `if "XXX" in p: continue`]. The ten-X positional form is
the one T254b compiled Apple's own `shell_cmds/mktemp.c` to confirm, and it is the form
`conformance.sh:1481-1484` already uses.

**The instrument's output is unchanged byte-for-byte** — it never printed `$C`
[VERIFIED: `diff evidence/20-instrument-output-BEFORE.txt evidence/21-instrument-output-AFTER.txt`
is empty; BEFORE captured from `fe24419`, AFTER from the repaired file]. **It no longer creates
`/tmp/t234_matrix2.txt` at all** [VERIFIED: the path is absent after the AFTER run].

### 2. `.softhouse/conformance.sh` — `guard_no_host_state_in_lint_corpus`, wired

+222 lines, 2617 → 2839, two hunks, both at old line 1551 and below. Repairing one file is not
the job; the class is. The rule:

> No file the fail-open linter classifies may assign a literal absolute path under a shared
> temporary root (`/tmp`, `/private/tmp`, `/var/tmp`) to a name.

Such a path is host state three ways: shared between every worktree on the machine, absent
from every commit, deleted on reboot. C1 and C6 both decide tier by asking whether a path
exists, so the shape is *capable* of moving a tier with no byte of the tree changing.

* **Pinned at 17 rows**, `PATH | NAME=ABSPATH`, no line numbers. Added to `run_guards` next to
  `guard_no_fail_open_instruments`, so it runs on every graded run.
* **The census was EIGHTEEN before the repair and is SEVENTEEN now**, and the row that left is
  `…/02-escape-matrix-fix.sh | C=/tmp/t234_matrix2.txt` — the `-` discipline the pin states,
  honoured in the commit that earned it [VERIFIED: the census expression against `HEAD`
  prints that file's line 6 and exits 0; against the working tree it exits 1, and `git grep`
  exits 1 on NO MATCH and >1 on ERROR, so the 1 is an absence].
* **Fail-closed three ways**: `git grep` >1 refuses (including the 9 the subshell raises when
  it cannot enter `$REPO_ROOT`); a selector returning zero files refuses; and a row the
  normaliser cannot read refuses, because `sed -n …p` silently drops what it cannot match and
  a dropped row is a site leaving the census quietly. No pipeline anywhere in it (P-57).
* **The population selector is a MEASURED superset of the linter's, not an assumed one.** The
  linter uses Python `re` over whole file text; the guard uses `git grep -E`, POSIX ERE,
  line-based, no `\b`. Measured: linter 71 files, guard 86, **files the linter sees and the
  guard does not = ZERO** [VERIFIED: `instruments/40-selector-agreement.py`,
  `evidence/40-selector-agreement.txt`, exit 0]. That instrument exits 1 the moment the zero
  stops holding.
