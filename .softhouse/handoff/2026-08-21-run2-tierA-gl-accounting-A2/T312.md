## Changes Made

### 1. `.softhouse/bin/branch_sweep.py` — NEW. The sweep, as an instrument.
Importable module *and* CLI (`sweep` / `check-dispatch` / `install-hook` / `hook`).

- **Case-INSENSITIVE selection.** `fnmatch` over the case-folded name, so `'softhouse/t3*'` and
  `'softhouse/T3*'` select identically. That alone is the fire-`20260827-230001` defect.
- **Loose and packed are read SEPARATELY and never merged.** Loose names come from `os.walk` over
  `<common-dir>/refs/heads` (readdir returns the name **as stored** — looking a name up by opening a
  constructed path would, on this filesystem, silently return the differently-cased file). Packed
  names come from parsing `packed-refs` case-sensitively, as git does. `git for-each-ref` /
  `git branch` answer *"what is this ref worth"*, which is the loose value when a loose ref exists —
  that single answer is what hid `c1a3888a`.
- **It reports the value no name reaches.** For each case-folded group it prints every spelling's
  loose value, packed value and what `git rev-parse` actually resolves, then flags
  `CASE-SHADOW` / `UNREACHABLE-VALUE` / `DIVERGED`, and for a hidden value prints **its own**
  commit count ahead of `main` — the question "is this branch empty?" answered about the object that
  was hidden, not about the name that won.
- **Noise discipline, so the signal survives.** A same-name loose/packed difference that is an
  *ancestor* of the resolved value is an ordinary stale packed entry; it prints as `--` and is
  counted separately, not as a finding. Without that, the two real shadows in this repo sit inside
  4 benign ones and 221 clean groups.
- **Every report leads with its SELECTOR** — patterns, matching rule, which directory was walked,
  how many loose and packed entries were read, and anything it could **not** read (an unreadable
  `packed-refs` prints "refs that exist ONLY as packed entries are INVISIBLE to this run"). A
  "no findings" line here is a measurement with its scope attached.
- Exit codes: `0` clean · `1` could-not-complete (never read as clean) · `3` findings / refusal ·
  `4` clean but the ref guard is not installed · `64` usage.

### 2. The refusal — where it belongs, and why there
**`check-dispatch <branch>`** refuses (exit 3) when a case-variant of the name already exists under a
different spelling, or when the name is non-canonical-case. It prints the existing spelling and says
to reuse it verbatim — which is what T308's worker did by hand.

**But a check the driver must remember to run is the same class of guard that failed** (P-45), and the
branch name is written by the orchestrator from the skill, which is **outside my edit set**. So the
refusal also lives where nothing can route around it: **`install-hook` installs a git
`reference-transaction` hook** that refuses the ref **creation itself** — `git branch`,
`git update-ref`, `git worktree add -b` and `git push` were each driven against it and each aborted
(§ *Vectors run*). The hook is **pure filesystem**: it runs inside a live ref transaction holding ref
locks, so it must never re-enter git.

Scope of the hook, chosen deliberately: it refuses **shadow creation only**, not non-canonical case.
Refusing lowercase names at the ref layer would break a legitimate `git fetch` of the seven existing
lowercase branches. Canonical case is enforced one layer up, at dispatch, where the blast radius is
one task. Escape hatch for deliberate rescue work, documented in the hook body:
`SOFTHOUSE_ALLOW_CASE_SHADOW=1`.

### 3. `.softhouse/bin/ready-tasks.py` — flags "branch named, and a case-variant exists"
`branch_wip` now suffixes its verdict `/CASE-VARIANT`, or `/CASE-UNCHECKED` when the check could not
run (an absent warning must not read as a clean result). The flag is **appended to every verdict
rather than branching on one**: the six shadowed tasks reported `commits` — the healthiest verdict
this function has — so hiding the warning behind an unhealthy one would have printed nothing on
exactly them. The index is **imported from `branch_sweep.py`, not reimplemented** (T213's rule: the
fixture and the fire run the same bytes), and is pure filesystem, so it spends **no** subprocess and
cannot eat the `--deadline-secs` budget. Nothing in the file compares `kind`, so the suffix is safe.

## Decisions taken (item 5 of the brief — decided, with the alternative rejected)

**D1 — Normalise the branch convention on UPPERCASE task ids; do NOT switch to lowercase.**
`softhouse/T<n>-<slug>` and `softhouse/A2-<n>-<slug>`. Measured, not assumed, by
`git for-each-ref --format='%(refname:short)' refs/heads/` on 2026-08-27 — and the count moves under a
live fire, it was 222 an hour earlier, so read the ratio not the cardinal: of **227** `softhouse/*`
heads, 21 are machine-generated `rescued-agent-*` (exempt), and of the remaining 206 exactly **9**
carry a lowercase task-id prefix — `t264 t265 t268 t273 t281 t286 t297 t299 t305`. Enforced at
dispatch by `check-dispatch` and flagged by
`ready-tasks.py`; **not** enforced at the ref layer, so a fetch of an existing lowercase branch still
works, and `check-dispatch` returns OK for an existing exact spelling so those seven can still be
continued. *Rejected: all-lowercase* — it is 9 of 206, and adopting it means renaming ~200
branches, which is the delete/rewrite this task is forbidden to do, destroys the evidence, and would
have to pass through a case-variant ref to get there — **creating the very shadow** en route.
*Also rejected: rely on the hook alone* — the hook stops shadowing but not two names for one task.

**D2 — Do NOT un-pack `refs/heads/softhouse/*`. Unpacking is the direction that CREATES the surface.**
Measured in the scratch drive (`red-drive.txt`, EXPERIMENT 5): with **both** spellings in `packed-refs`
— a case-**sensitive** text file — `git rev-parse` returns **two different values** for the two names
and nothing is hidden. Writing one back out as a **loose** ref (which any commit on the branch does)
leaves **one file serving both names**, and the other value becomes unreachable. The shadowing party is
the loose ref, not the packed one. *Rejected: "un-pack `softhouse/*` so `packed-refs` can never shadow"*
— it inverts the mechanism. Leave packing to `git gc`.
Corollary, offered to the driver and **not** done by me: a `git pack-refs --all` on the live repo would
make T297's and T305's hidden lines addressable by name again. It is a repo-wide state change under a
live fire, and `refs/rescue/20260827-230001/*` already pins both values, so nothing is lost by leaving
it. `[UNVERIFIED]` on the live repo — measured only in scratch.

## Follow-ups

1. **The three skill edits above.** Without #3 the cloud fire is unguarded; without #1 the driver can
   still write a lowercase branch name into a worker prompt, and only the ref-layer hook will stop it.
2. **`tasks.json` still records lowercase branch names for T304 and T305**, which is why

   fire when it finds a shadow* — it logs. That is deliberate for a first landing (a guard that stops

   `git rev-parse` per name. Unambiguous single-spelling groups could be resolved from the index without
   git; not done, because a predicted resolution that is never checked against git is the shape of defect
   this task is about.
