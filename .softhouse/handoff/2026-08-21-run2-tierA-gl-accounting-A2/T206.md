## (a) The seventh writer — `.softhouse/capture/pathb/t149/promote-vector.py`

**Measured, not assumed: it can truncate the live store, and does not need T203's
"stage at real depth" trick to prove it.** T74/T61/T64/T57/T8 bind their output directory
to a module constant computed from `__file__`, so a `/tmp` copy of any of them cannot reach
the live store — proving anything against such a copy is P-36's null control. This script is
different in kind: its own docstring shows the destination arriving as `sys.argv[1]`, with
both a `/tmp/scratch/...` example and `.softhouse/vectors/loanschedule/...` **itself** as
equally valid invocations. Its *inputs* (`RAW`, `ATT`) are `__file__`-relative and always
resolve to the real committed captures; only the *destination* is caller-controlled. So the
RED proof runs the **real, unmodified, committed** script in place, varying only the argv
destination — never a copy, never a patched `ROOT`.

Pre-fix body (git blob `a142b7a6b5964947000096633732ce8f92ccb378`):
```
    with open(out_path, 'w') as fh:
        json.dump(v, fh, indent=2)
        fh.write('\n')
```
No existence check, no authorisation, no atomicity — a bare O_TRUNC exactly like
T74/T61/T64/T57/T8, differing only in *where* the destination is bound (argv, not a
constant).

**Not hypothetical: a live vector already occupies this script's own documented default
name**, `T149-PATHB-TIE-1M162502pt50-12x21pt6pct.json`, already in the store today.

### Fix

Guarded with **T203's shared module, imported through one hop, no second idiom invented**:
```python
sys.path.insert(0, os.path.join(os.path.dirname(os.path.dirname(os.path.dirname(
    os.path.dirname(os.path.abspath(__file__))))), "handoff"))
import t203_store_guard as guard_store
```
— the identical four-dirname-from-`__file__` resolution `T64-promote-vectors.py` uses,
because this script sits at `.softhouse/capture/pathb/t149`, the same depth under
`.softhouse` as `.softhouse/capture/t64-zeroprincipal/src`. `NAME` + a fresh
`AUTHORISE_TOKEN` (argv-only, per-script, matching every other caller) were added. The write
site becomes:
```python
store_dir = os.path.dirname(out_path) or '.'
filename = os.path.basename(out_path)
out_path = guard_store.write_vector(NAME, AUTHORISE_TOKEN, store_dir, filename,
                                     json.dumps(v, indent=2) + '\n')
```
`main(sys.argv[1])` still reads only the first positional argument, so the authorisation
flag (needed only when the destination happens to be the live store) can ride as a second
argv word without changing what the script treats as its destination.

### Fix

`guarded_create(path, data, what, mode=None)`: refuses unconditionally
(`os.path.lexists`) if the target already exists, otherwise writes atomically —
`tempfile.mkstemp` in the target's own directory, optional `os.fchmod` on the temp fd
*before* it becomes the target (eliminating the third site, the follow-up `os.chmod`,
entirely rather than guarding it separately), `fsync`, `os.replace`, `fsync` the directory —
the same sequence and order as `t203_store_guard._atomic_create`. All three original call
sites now route through it.
