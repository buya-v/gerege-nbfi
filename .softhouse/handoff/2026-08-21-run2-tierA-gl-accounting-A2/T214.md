## What I re-derived and how

**I did not inherit the driver's 79.** Method, entirely from the object store, no filesystem walk:

1. `git for-each-ref refs/heads/softhouse/*` → **191 branches** (194 by the time I finished; other agents
   were creating branches in parallel — I created one and deleted none).
2. For each, `git rev-list --count main..<branch>` > 0 → **23 branches ahead of `main`.** Matches.
3. `git ls-tree -r --name-only main` → **4,239 paths**, held as the reference set.
4. For each ahead-branch, `git diff --name-only main...<branch>`, then exact-path membership of each
   changed path in that 4,239-path set.

**Result: 79.** Same number as the driver's re-done measurement, and the same split:

| branch | changed | **absent from `main` at any path** |
|---|---|---|
| `softhouse/T108-grep-adjudication` | 30 | **28** |
| `softhouse/T131-review-t108` | 30 | **28** |
| `softhouse/rescued-agent-a353b03c0dea4dd41-20260818-200001` | 16 | **15** |
| `softhouse/T109-fork-point-digest-compare` | 19 | **8** |
| the other 19 branches | — | **0** |

**Cross-check by a different derivation, because a diff base can lie.** For each branch I also took
`comm -23 <(sort <(git ls-tree -r --name-only <branch>)) <(sort main-paths)` — the branch's **whole tree**
against `main`'s whole tree, no merge base involved. The column came out **28 / 28 / 15 / 8 / 0**, identical
cell for cell. So the 79 is not an artefact of `...` and none of it is "a file `main` deleted later".

The 79 are **79 distinct paths** — no path is contributed by two branches, which surprised me for
`T108`/`T131` and is explained by T131 having written its own `t131-grep/` corpus rather than re-using
T108's `t108-grep/`.
