## Changes Made

### 1. The fix — `.softhouse/capture/pathb/t149/prove-redgreen.sh`

Arm 1 moved a parity vector out of `.softhouse/vectors` and back with two `mv`s and no
`trap`. Everything below is new.

* **`trap restore_store EXIT`**, plus `trap … INT`, `… TERM`, `… HUP`, each of which
  `exit`s with the conventional `128+signo` so the EXIT handler runs. A signal trap that
  *returned* would resume the proof mid-flight.
* **The restore is idempotent and it VERIFIES.** The handler moves the park back only if
  the store copy is absent; if both exist it `cmp`s them and refuses on a difference
  rather than picking one. It then byte-compares the restored vector against a
  **pre-park backup** taken with `cp`, and re-derives a **whole-store census** (size +
  path of every `*.json` under the store, from `find`, so nothing is enumerated from a
  hand-maintained list) and compares it against the census taken before the park. A
  mismatch prints the `diff` and forces a non-zero exit.
* **An EMPTY census is a refusal, not a pass** — "restored" over nothing is not a fact
  (P-40).
* **Start-up recovery.** `SIGKILL` runs no handler, and no trap can change that. The
  fixed script therefore checks at start-up for a park left by an earlier run and
  restores it before doing anything else, which is the only place that hole can be
  closed. [VERIFIED: `t156/prove-exit-trap.txt`, "POST-FIX start-up recovery"]
* **The mutation driver is backgrounded and `wait`ed** instead of run in the foreground.
  Bash defers a trapped signal until the current *foreground* child finishes, so a
  `kill` arriving during a multi-minute driver would not restore the store until that
  driver chose to end — and never if it hung. Measured: pre-fix, that case was **still
  running with the store short at a 25 s timeout**; post-fix it restored in **1.5 s**.
  [VERIFIED: `t156/prove-exit-trap.txt`, case `parent-int-hang`] `rc1` keeps exactly the
  foreground semantics — `wait` yields the child's status.
* **Every hard-coded count is gone from the assertions.** The task warned the number
  would move under me, and it did — `main` moved from `b4ebb81` to `9e42bbc` mid-task.
  The script previously asserted the literals `| 39 | 3 |`, `| 39 | 4 |` and
  `parity vectors          PASS 43   FAIL 0`. It now reads each arm's size back out of
  `T61-mutations.py`'s own unmutated baseline line and asserts the *relations*:
  arm 2's store is exactly one vector larger than arm 1's; each arm's `PASS + FAIL`
  accounts for its whole store; arm 1's killed-by list is exactly `T61-HE-A,B,C`;
  arm 2's is that list plus `T149-PATHB-TIE` **and nothing else**; arm 2 has exactly one
  more failure and **the same PASS count** as arm 1 (parking a failing vector cannot
  change the pass count); arm 3's unmutated PASS equals the size the driver measured.
  No cell count is asserted at all.

  I did **not** rename the three transcript files, whose names carry `42`/`43`: the
  promoted vector's own `_note` cites `premise-refuted-42-vector-store.txt` **by name**
  [VERIFIED: `.softhouse/vectors/loanschedule/T149-PATHB-TIE-…json`, `_note`], and a
  vector is not this task's to edit. That leaves a naming wart — see Follow-ups.

### 2. The prover — `.softhouse/capture/pathb/t149/prove-exit-trap.py` (new)

Drives the defect **red against the real pre-fix bytes** and green against the fix.

* Pre-fix bytes come from the **immutable git object** `9b973301a6eaa9dff61559f7d1f8a8de05752880`,
  read with `git cat-file blob`, with sha256
  `549eac70bb67b8c4303f4c24af7304a420a2cc72cca6e172e8a9da2809045ce0` checked before use;
  the prover **refuses** on any mismatch. No moving ref (`main:`, `merge-base`) appears
  anywhere — that is the P-24 relocation trap, and this is the A2-5/A2-10 shape.
* **Nothing destructive touches the real store.** Each case runs in a throwaway sandbox
  whose directory shape reproduces exactly what `prove-redgreen.sh`'s own
  `REPO="$HERE/../../../.."` arithmetic expects, over a `shutil.copytree` copy of the
  store. Sandboxes are deleted after grading.
* **The interruption is delivered from inside the window**: the sandbox's
  `T61-mutations.py` is a stub whose call site *is* the gap between the two `mv`s, and
  which signals its parent (the running script).
* **Positive controls on the inputs themselves**: refuses if pre == post, if the pinned
  pre-fix bytes already contain a `trap`, or if the fixed bytes contain none. A prover
  that ran the same bytes twice would report a perfect fix and mean nothing.
* **N is derived**, once, by grading the pristine sandbox store with the committed
  `grade-scratch-store.sh`; no count is written down in the file.

**What the sweep could NOT have found, with the number attached (P-26/P-40):** it read

* **F-2 — `.softhouse/handoff/T61-mutations.py:265,289-291`, a `finally` is not a trap.**

  benign half of the family, but it is the same class. Suggested fix:
  `signal.signal(SIGTERM, …)` raising, or an `atexit` revert.

* **F-3 — the harness has no expected-count pin, and that is the deeper defect.**
  `DuplicateCaseIDs` in `nexus/internal/apps/loanschedule/conformance/vector.go:988`

  rig that can cause it; **any** cause — a bad merge, a stray `rm`, a `.gitignore`
  mishap, a worker's cleanup — produces the same silent green. Suggested fix: a
  committed store manifest (case_id list, or a count with a rationale) that the harness
  refuses to run without matching, in the same voice as the duplicate refusal.
  **Not attempted here** — it lives in `.softhouse/conformance.sh` / `nexus/`, where
