## 1. THE CENSUS, RE-MEASURED — SELECTOR AND WHERE I LOOKED

**Instrument:** `.softhouse/capture/t334-writer-guidance/probe-writer-census.py`, one file run unchanged on
all three hosts so the hosts are compared with the same ruler. **31 legs.**

**Two selectors per leg, not one:**

```
(1) INODE  os.stat(path).st_ino   before the write and after it
(2) FD     os.open(path, O_RDONLY) held ACROSS the write, then os.lseek(fd,0) + os.read
```

**(2) is the hazard itself** — a running zsh holds exactly such an fd — and (1) is the cheap proxy. A leg
where they disagree scores `DISAGREE` rather than being quietly counted. **They agreed on every scored leg
on all three hosts** (0 `DISAGREE`). Every leg also asserts the bytes at the path actually changed and carry
the mutation marker; a writer that no-ops scores `NOOP` and is never evidence.

**Three additions T301's table did not have, all in place, all worth naming** because they are what agents

`awk > tmp; mv tmp f` is **isolated** and `sed > tmp; cat tmp > f` is **in place**. Identical intent,
opposite safety. **It is the last step that decides, never the tool at the front of the pipeline.**

## 2. GNU vs BSD `sed` — THE DETERMINATION

**`sed -i` is ISOLATED (rename) on all three userlands.** BSD `sed -i ''`, GNU `sed -i` (4.9), busybox
`sed -i`: same behaviour — build a temp file, rename it over the target. The spelling differs; the safety
does not.

This was the specific worry: the launchd fire runs here and the cloud fire never does, and T256/T298 spent
themselves establishing that no graded path may depend on where it runs (T326 closed one such defect this
fire). **A writer-safety rule true only on macOS would be that same defect.** It is not: `sed` is portable-
safe, and the one place portability actually breaks is **`cp`**, which the rule as landed does not depend on.

> landed is target-conditional and therefore host-independent, so this does not block it. But nobody should
> write a *writer*-keyed rule until that fact exists. Filed as **FU-T334-4**.

## 3. THE RULE AS LANDED — `P-97` in `patterns.md`

`patterns.md` is the site of definition; the rule is there, appended after the T282 errata block behind
`<!-- T334-WRITER-SAFETY -->`. **Not** "always use `Write`" — the shell-writer guidance is right for almost
everything, and a rule that overreaches gets ignored. The conditional is the target:

> **Never write IN PLACE to a file that may be executing.** Concretely: `.softhouse/bin/fire-program.sh`,
> anything else under `.softhouse/bin/` while a fire is running, `.softhouse/conformance.sh` mid-run, any
> guard under `.softhouse/guards/` mid-run. For every other target — handoffs, captures, `RESUME.md`,
> observations, source, vectors — the shell writers are **fine**: cheap, composable, and **most targets are
> not running scripts**.

**Safe alternatives, in the rule:** (1) edit in a **worktree and land through git** — all eight git write
paths rename on all three hosts; (2) use a writer that **renames** (`sed -i`, `perl -i`, `mv`, `install`,
`patch`, temp-file-then-`mv`, or `Write`/`Edit`); (3) if it must be shell against a live path, write a temp
and **`mv`** it, never **`cp`** it.

**How the entry was written.** By `append-p97.py`, which **derives every cardinal** from the three census
outputs and from the checker's own live JSON, and refuses to run twice. Precedent: T282's `append-pattern.py`
(*"a table of corrected cardinals that someone retyped is the next instance of the defect"*). The `sed`
portability claim is derived **by assertion** — if any userland ever scores `sed -i` as anything but
`ISOLATED`, the script raises `SystemExit` rather than writing a sentence that is true on two hosts of three.

**P-86 compliance, applied to itself as the brief asked.** The entry states in its own body that any
restatement must **name the rule or carry its sentence, never just the id**, and cites `P-86` with its
sentence. This handoff does the same. I restated the rule nowhere else.

## 6. HOW NARROW THIS ACTUALLY IS — the honest statement

**Narrow. It is a default-choice defect, not a live bug, and saying otherwise would be the third error in
this chain.**

The exposure needs **all three** of: an agent writing **in place**, to a script that is **running**, at an
offset **past what the shell has already read**. Against the wrapper as shipped it **does not reproduce** —
T301 drove it and the marker never reached the running fire, because the driver call is nested inside the
final `while` loop, so reaching it forces a read through the loop's `done` and the remaining bytes fall
inside zsh's ~7.6 KB read-ahead. **Nothing is broken today.**

**What is not narrow is that the immunity is layout, not design.** Appending 15 KB of top-level content
after the chain loop — "add a step at the end of the fire" — restores the hazard, which T301 also drove
(ARM FRAGILE: marker **reached**). And the exposed region past the driver's `wait` contains `run_exit_guard`,
`reconcile_tasks_json` and the prune sweep that calls `git worktree remove`. The failure mode is not "the
fire crashes", it is **"the classifier that decides what to DELETE was rewritten under us"**.

**Against that, the honest counterweight:** T301 already landed the snapshot re-exec, which makes the
wrapper immune unconditionally. So `P-97` is **defence in depth for everything the snapshot does not cover**
— `conformance.sh` mid-run, guards mid-run, any future script — plus the removal of a wrong default. It is
worth one rule and no more than one rule.

**Scale of the actual bad practice, measured, so nobody has to guess:** the wrong writer is the *default*,
but on the files that matter it has essentially never been used — every landing to `.softhouse/bin/` in this
program went through **git**, which renames. The defect is in the *instruction*, not in the *history*.

## 7. HARNESS DEFECT IN MY OWN RIG — found, fixed, and it is the evidence

**The `git stash pop` leg passed on a host with no `git`.** Its command is
`sed 's/…/…/' target > t && mv t target && git stash && git stash pop`; the `sed`+`mv` **prologue** already
renamed the file, so `changed=yes` and the leg scored **ISOLATED** while `git` exited 127. It was scoring
its own setup. Caught only because the GNU container has no `git` and the row appeared anyway — on a host
with `git` it would have passed for the right reason and hidden the flaw forever.

**Fix:** `rc != 0` is now **unscorable outright**, before the `changed` test. This is T301's harness defect
#3 and T309's vacuous first draft, one layer over: *a multi-step leg can measure its own prologue.*

**Second, smaller one:** my first count of the paraphrase sites said **16**, matching on the whole sentence;
the real answer is **25**, because several citations are **line-wrapped** and each half is a separate
finding. Caught by asking the same question two ways and refusing the first answer. Both fixes are in the
committed instruments.
