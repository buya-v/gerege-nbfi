### FACT A — `emiDifference` is `B`, EXACTLY, and does NOT grow with the interest deficit

`RepaymentPeriod.getDueInterest()` clamps the period's interest to the instalment
`[VERIFIED — bound by content: ": MathUtil.min(getCalculatedDueInterest(), getEmiPlusCreditedAmountsPlusFutureUnrecognizedInterest(), false),"]`.
So in the non-amortizing regime `Σ dueInterest = n·E` and `Σ emi = n·E`, and the `diff` that
`calculateLastUnpaidRepaymentPeriodEMI` adds to the last row
`[VERIFIED — bound by content: "Money diff = totalDisbursedAmount.plus(totalCapitalizedIncome, mc).plus(scheduleModel.getTotalCreditedPrincipal(), mc)" ".plus(totalDueInterest, mc).minus(totalEMI, mc);"]`
is

```
diff = B + Σ dueInterest − Σ emi = B + n·E − n·E = B          (integer minor units, EXACT)
```

for **every** `n` and **however far `E` is below `I₁`**. `getEmiAdjustment` therefore hands site 3
`emiDifference = B` and `originalEmi = E`
`[VERIFIED — bound by content: "Money emiDifference = lastPeriod.getEmi().minus(penultimatePeriod.getEmi());"]`,
with `uncountablePeriods = 0` because every `totalPaidAmount` is zero
`[VERIFIED — bound by content: "originalEmi.isLessThan(repaymentPeriod.getTotalPaidAmount())"]`.

Unwinding `shouldBeAdjusted`
`[VERIFIED — bound by content: "double lowerHalfOfRelatedPeriods = Math.floor(numberOfRelatedPeriods() / 2.0);" / "emiDifference.abs()" ".multipliedBy(100)" ".isGreaterThan(originalEmi.copy(lowerHalfOfRelatedPeriods));"]`
— `multipliedBy(100)` binds the `long` overload, `copy(double)` goes through
`"return copy(BigDecimal.valueOf(amount));"`, and both sides are MAJOR units — gives, in **minor
units**, exactly `|diff_minor| > ⌊n/2⌋`. **T223's `B_minor ≳ n/2` is right as far as it goes, and
FACT A is why.**

### FACT B — the guard T223 omits entirely, and it is the one that decides the region

The raised instalment is applied to a **copy**, and the copy's own `emiDifference` must be
**strictly smaller in absolute value** or the loop `break`s
`[VERIFIED — bound by content: "if (!getEmiAdjustment(newScheduleModel.repaymentPeriods()).hasLessEmiDifference(emiAdjustment)) {" "break;"` and
`"return emiDifference.abs().isLessThan(previousAdjustment.emiDifference.abs());"]`.
The write-back `"relatedRepaymentPeriod.setEmi(newRepaymentPeriod.getEmi());"` sits **below** that
`break`, so on failure **the copy is discarded and the instalment does not move.**

If the raised instalment `E + a` is still `≤ I₁`, the copy is in the same non-amortizing regime, so
by FACT A its `diff` is `B` again — `|diff′| = |diff|`, not strictly less — **break, no rescue.**
