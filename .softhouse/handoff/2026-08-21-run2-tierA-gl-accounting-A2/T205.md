## 1. THE DEFECT, RE-DERIVED FROM SOURCE

T203's F-2 named the shape. Re-derived here rather than accepted:

```
T74 / T61 / T64 / T58    VECTORS = ".softhouse/vectors/loanschedule"     # RESOLVES

                         open(path, "w")                        -> TRUSTED, tag STORE

                                  os.path.dirname(__file__), "..", ".."))  # RUNTIME
                         OUT  = os.path.join(ROOT, ".softhouse", "vectors", "loanschedule")
                         path = os.path.join(OUT, SLUG[case_id] + ".json")
```

[VERIFIED by extraction, pre-hardening blobs at `git show e2b4609^:…`]
`T74:58`, `T61:27`, `T64:28`, `T58:31` = the module constant; `T57:21,26` and `T8:17,19`
= the runtime `ROOT`. Same store, same bare truncation, one `os.path.join(ROOT, …)` apart.

**The mechanism, which T203 did not have to hand and which is narrower than "runtime
constants don't resolve".** `ConstResolver` has *two* maps. `consts` holds fully
resolved values; `partial` holds the literal string fragments of an expression that
did *not* resolve. `OUT` lands in `partial` with exactly the right fragments
(`".softhouse"/"vectors"/"loanschedule"`). Two things then stopped that evidence
reaching `path`:

1. **`partial` did not chain.** T196-2's second pass harvests a `Name` only when it is
   in `self.consts`. A name whose only evidence is itself `partial` contributed nothing.
2. **`setdefault` blocked the upgrade.** Pass one had already claimed `path` with the
   one constant it does contain — `".json"` — so the `consts` lookup in pass two never
   ran on it at all.

Both are needed to produce the bug, and either one alone explains why T74's shape was
caught: `VECTORS` is in `consts`, and `path`'s assignment contains no string constant
for pass one to claim.

## 2. POLARITY — THE TWO DIRECTIONS, KEPT APART

| | direction | who it hurts | urgency |
|---|---|---|---|
| **UNKNOWN → `--enforce` exits 0** | **fails OPEN** | hides live exposures (T57 = 2 vectors, T8 = 11 including `P-00-baseline-6x7pct.json`) | the one this task fixes |
| **`T58` flagged UNGUARDED despite an `os.path.exists` refusal** (T203's own measurement) | **fails CLOSED** | cries wolf; hides nothing | not touched here |

Every change below states its own polarity. **Not fixed here, deliberately:** the
`os.path.exists`-refusal blindness. It is the fail-closed direction, and mixing a
fail-open fix with a fail-closed relaxation in one diff is how a widening gets
smuggled in behind an urgent fix.

### Change 1 — `ConstResolver.chain`, a transitive fragment closure — **fail-CLOSED**

A fixpoint over single-name assignments that merges literal fragments from
`Constant`s, `consts`, `chain` and `partial`. It is consulted **only** by
`probe(..., chain=True)`; `classify_python` calls that **only** when the ordinary
probe already returned UNKNOWN, and honours the answer **only** when it is TRUSTED.
A chain probe returning SCRATCH is **discarded** and the site stays UNKNOWN.

So the step can move a site `UNKNOWN -> TRUSTED` and **nothing else**. It cannot
excuse a write, cannot create a SANDBOX, cannot touch a guard verdict. Its only
failure mode is crying wolf. With `chain=False` — every pre-T205 caller — the probe
text is byte-identical to T196's.

### Change 2 — `--enforce-unknown` — **opt-in fail-CLOSED**

Makes UNGUARDED+UNRESOLVED sites fatal. Not the default; see §4.

### Change 3 — `ENFORCE-DISCLOSURE` on stderr — **neutral (visibility)**

Every `--enforce` run now prints the residual UNKNOWN+UNGUARDED count and says in
words that it is not fatal. The report already *listed* those sites; what made T203's
F-1 possible is that the **enforcement boundary** was silent about them. It no longer is.

## 8. HONEST NEGATIVES

* **I could not construct an ordinary source shape that drives the SCRATCH-discard
  branch.** The pre-existing scratch machinery dominates it: any assignment whose
  expression contains a scratch-looking literal already makes the name a
  `scratch_name`, and that propagates transitively through assignments, so the direct
  probe returns SCRATCH before the chain is ever consulted. The branch is therefore
  **defensive**, and it is proven by white-box injection (§6) rather than by a natural
  fixture. A branch never driven is not a proven branch; I say which kind of driving
  it got.
* **The `os.path.exists`-refusal blindness that made T58 a false positive is still
  present.** Untouched on purpose (§2).
* **Cross-module targets are still UNKNOWN.** One import hop exists for *guards*
  (T196-3); there is none for *mutations*. The six hardened rewriters in §3b are
  exactly this blind spot.
* **A non-existent path passed to `--file` is scored `REFUSED-UNREADABLE` and the run
  exits 0.** Observed while testing; it is counted and named in the refusal section,
  so it is not silent, but it is another way an `--enforce` invocation can pass
  without measuring anything. Not changed here — out of this task's scope, and worth
  its own task.
* **Cost:** the chain fixpoint adds ~8% CPU to a full sweep (25.65 s → 27.64 s user,
  same host, same root, back to back). The assigned expression is walked once into a
  cached recipe; re-walking it per fixpoint iteration made the sweep unusably slow and
  was fixed before measurement.
