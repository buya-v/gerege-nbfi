### 1. `t80/prove-f1.sh` — the pre-fix bytes run from a SIBLING, in the same directory

```
-git show "$PREFIX_COMMIT:$REL_A" > "$A"          # the LIVE t36/attest.py
-python3 t36/attest.py default emiloop  &         # ...running the downgraded live file
+SIB=$W/t36/.f1-prefix-attest.py
+git show "$PREFIX_COMMIT:$REL_A" > "$SIB"
+python3 "$SIB" default emiloop  &
```

**Why a sibling and not a scratch path — this is the whole task, and I re-verified it rather
than inheriting it.** `attest.py` derives `HERE` from `__file__`, `PATHB` from `HERE/..`, `OUT`
from `HERE/out/<set>`, and then gates on the *shape* of `OUT`. T158's suggestion — "run it from
a scratch path like `prove-f2.sh`" — therefore moves `HERE`, moves `PATHB` and `OUT` with it,
and the arm stops testing the thing. The filename itself is read nowhere.
[VERIFIED: the only self-reference in the pre-fix attester (`813acb1`) is `__file__` at line 34,
consumed as a *directory*; `'generator': 't36/attest.py'` at line 360 is a literal string that
is only written on a SUCCESSFUL run, and this invocation aborts before that — `grep -n
'__file__\|argv\[0\]\|basename\|attest\.py'` over both versions, this fire]

### 2. The invariant is now ASSERTED, not merely intended

`f1_assert_attester_untouched` re-reads the live attester's sha256 after the pre-fix run and
again in the EXIT handler, and fails if it moved. It **deliberately does not restore**: this
script no longer writes that file, so bytes that moved are somebody else's and silently
reverting them would erase the evidence of whoever did it. The message says so.

This is a new guard, so it was **driven red** — see ARM ABLATION below (P-22).

### 3. What the recovery machinery became

* **Removed:** the overwrite; the `git hash-object -w` pin of the live attester (this proof no
  longer writes into the repository's object store at all); the in-run and on-exit *restore* of
  the live attester.
* **Kept and still load-bearing:** all six signal traps + EXIT, `f1_clean_evidence`, the
  BEFORE/AFTER census with its empty-census refusal, and start-up recovery.
* **Added:** `f1_remove_sibling` (idempotent), and a T180 in-flight marker format
  (`sibling` + `watch-sha256` lines).
* **Kept as a LEGACY branch:** `f1_restore_attester`, reachable only from start-up recovery when
  the marker carries a `blob` line — i.e. when a tree was stranded by the *old* overwrite-shaped
  script and this newer script is the next to run. Without it, upgrading this file would strand
  any machine that had been SIGKILLed under the old one. It is **not dead code**: ARM LEGACY
  drives it.

### 4. `t80/prove-f1-recovery.py` (T161's prover) — corrected, not left to rot

T161's prover graded the SIGKILL/POST-FIX row as `attester == "PRE-FIX" and guard` — an
assertion that would now fail on the fixed script *for the right reason*. Updated: the expected
stranded state is the evidence set and the scratch sibling, with the attester **untouched**; the
in-window trigger now watches for the pre-fix digest at *either* `t36/attest.py` (old shape) or
`t36/.f1-prefix-attest.py` (new shape); `corrupt()` counts a leftover sibling as corruption;
the ablation's byte-substitution target follows the renamed invocation and still refuses if it
matches nothing.

## Red demonstration (scratch clone)

`python3 t80/prove-f1-noswap.py` → **exit 0**, transcript `out/F1-noswap-redgreen.txt`.
Every arm runs inside a throwaway `git clone --shared`. **Nothing was interrupted against the
real t36 rig**, per T161's standing instruction.

**The trigger contains no `sleep` and no timer.** T161 caught its own sleep-based arm passing
vacuously — the window does not open until ~10-14s in on this host, so a fixed sleep signalled a
script that had not yet touched anything (P-22). Two observation-driven mechanisms replace it:

1. **The sample.** Poll for the pre-fix digest to *appear* — at `t36/attest.py` for the old
   shape, at `t36/.f1-prefix-attest.py` for the new one — and read the live attester at that
   instant. If it never appears the prover **refuses** rather than reporting a pass.
   [VERIFIED: window observed at 13.8s (RED) and 10.2s (GREEN) — different every run, which is
   exactly why a constant could not have worked]
2. **The kill.** T161's injection hook: `t36/sha256.sh` is *sourced* by `prove-f1.sh`, so a
   `diff` shell function defined there runs in the script's own shell. The first `diff` is the
   BEFORE/AFTER-prefix comparison — after the stamp and the breached `preconditions.txt` are
   written, before any cleanup. Reached by control flow, not by clock. It also means the attester
   has already exited, so SIGKILL leaves no orphan writing behind the prover's back.

## What is retired and what is NOT

**This change REDUCES BLAST RADIUS. It does not retire the recovery.** T161's caveat is carried
forward, and it is now *measured* rather than reasoned: ARM GREEN's SIGKILL still left
`stamp=PRESENT  emiloop=MUTATED(2)  sibling=PRESENT  marker=left`.

**RETIRED — gone from the file:**

* the write of pre-fix bytes over the live `t36/attest.py`;
* the `git hash-object -w` pin of the live attester — this proof no longer creates objects in
  the repository's object store at all;
* the in-run restore of the live attester, and the restore branch of the EXIT handler;
* the "downgraded attester" failure mode itself, on every path including SIGKILL.

**NOT RETIRED — still required, still load-bearing, do not delete:**

* **every trap** (`EXIT INT TERM HUP QUIT PIPE`) — the pre-fix attester stamps
  `CAPTURED-FROM-TENANT` and replaces the committed `preconditions.txt` with a breached
  HALF_EVEN one *whichever file it is run from*;
* `f1_clean_evidence`, and the BEFORE/AFTER census with its empty-census refusal;
* **start-up recovery**, because SIGKILL runs no handler and no trap can change that — it now
  clears the scratch sibling and the evidence set instead of the attester;
* `f1_restore_attester`, on the **legacy** branch only, for a tree stranded by the old script.
  Driven by ARM LEGACY. Deleting it would strand any machine that was SIGKILLed under the old
  shape;
* the backgrounded-attester + `wait` restructure, for the same reason T161 gave: a foreground
  child defers the trap until the attester chooses to end.

Blast radius went from `{live attester + evidence set}` to `{evidence set + a scratch file}`.
It did not go to zero.
