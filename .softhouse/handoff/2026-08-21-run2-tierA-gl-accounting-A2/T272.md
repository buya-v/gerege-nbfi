### STEP 2 — the graft, and what `GEREGE_GO_STRICT` means

Base = the merged Mac file. **KEPT** its stale-`GOROOT` drop. **GRAFTED** the cloud's strict arm
**after** that drop and after the search diagnostics, so a refusal still repairs an inherited broken
`GOROOT` and still names the paths it searched — the two things the cloud version got wrong (F-3 HIGH).

- **What it means.** It makes the *already-written, already-rejected* hard-refusal alternative reachable as
  **configuration** rather than as a patch. It adds no new policy.
- **What turns on when set.** Exactly one arm: pinned toolchain **not found** → export nothing, set
  `GEREGE_GO_SOURCE=refused`, print a refusal banner, **and the sourcing returns 2**.
- **What fails when set.** Nothing at all when the toolchain **is** present — the arm is not reached and the
  result is byte-identical to default mode (driven: A2 ≡ A1). When it is **absent**: the sourcing returns 2,
  so a caller that tests the status fails there and a caller under `set -e` **aborts at the activation line**.
- **What fails when NOT set.** Nothing changes from the pre-graft file (driven: A10).
- **Which fire sets it: NEITHER, TODAY.** [VERIFIED: `evidence/10-locate-cloud-arm.txt` §6 — a selector that
  matches **assignments** (`(export )?GEREGE_GO_STRICT=`) over `.softhouse/bin`, `.softhouse/launchd`,
  `.claude`, excluding `go-env.sh` itself, returns **0 sites**, with rc ≤ 1 on a selector shown in the same
  section to match inside `go-env.sh`.] So the launchd fire and the cloud fire both run with it unset and
  **this graft is behaviour-identical on both**.

**On host state, which the brief made the central question.** `.softhouse/toolchain` is gitignored and
host-local, so *"is the pinned toolchain here?"* already answers differently on the two fires — that is the
fact this file exists to handle and no switch removes it. Strict changes only the **consequence** of that
difference, from a loud substitution to a loud refusal. It never makes the difference quieter and it never
changes anything on a host where the toolchain is present. Since no fire sets it, **the graft moves no graded
verdict on either host**. If a future fire sets it, it must set it for both fires or say in writing why not —
that sentence is in the file.

**A deliberate deviation from T254b's merge-step 3, inside the latitude the reviewer gave.** The reviewer
asked for the cloud's "richer `GEREGE_GO_SOURCE` value" (`substituted:/abs/path/to/go`) but explicitly
allowed *"Keep the Mac's pinned/absent tokens or the cloud's `pinned:$PATH` — either is fine"*. I kept the
**bare tokens** and put the path in a **new `GEREGE_GO_BIN`**, for two reasons:

1. **Host state.** An absolute path folded into `GEREGE_GO_SOURCE` would bake `/Users/buv/...` into the very
   variable **T267** wants printed into the graded verdict block. `GEREGE_GO_SOURCE` is now four bare tokens —
   `pinned` | `fallback-path` | `absent` | `refused` — host-independent by construction and safe to compare
   across the two fires. `GEREGE_GO_BIN` is host detail and the file says never to compare it across hosts.
2. **Renaming the tokens would have rotted two things I do not own.** `reference-oracle.md:660-661` documents
   `fallback-path` and `absent`, and **T256's drive asserts on those literals**.
   [VERIFIED by running it: `evidence/40-t256-drive-after-graft.txt`, 26 asserts / 0 failures, `DRIVE: GREEN`.]
