## What would NOTICE next time — proposal, and what enforces it

**The general defect has two independent failure axes, and they need different fixes:**

1. **No stamp → staleness is invisible** (`selftest-output.txt`'s failure). Fix: every
   committed transcript-of-a-live-sweep should print its own `commit: <sha>` (or `ref: <arg>`
   the way `rederive_population.py` / `list_trusted_unguarded.py` / `a2-33/sweep.sh` already
   do) **as part of the instrument's own output**, not appended by whoever captures it. This
   is cheap for `selftest.py` specifically — it already imports `guard_classify`, which could
   expose the current `git rev-parse HEAD` in one line. I did not make this change: it would
   modify the instrument's behavior beyond "regenerate the transcript," and this task's
   explicit instruction was to run the instrument as-is, not first patch it. **Proposed, not
   implemented** — flagging as a Follow-up.
2. **Stamp present but nobody re-runs it → staleness is visible but uncorrected**
   (`population-output.txt` / `trusted-unguarded-sites-main.txt`'s failure, and the reason a
   real finding — the two new UNGUARDED-TRUSTED sites above — sat unseen). A stamp is
   necessary but provably not sufficient by itself (P-69's own text says exactly this: "stamps
   make staleness VISIBLE but cannot PREVENT it").

**Recommendation: a harness check that a recorded transcript still reproduces, scheduled, not
wired into `conformance.sh` as part of this task** (the task explicitly forbids that last
step — "DO NOT WIRE A NEW GUARD INTO conformance.sh AS PART OF THIS TASK"). Concretely: a
script that, for every `(producer, committed-output)` pair with a self-declared `ref`/`commit`
arg, re-runs the producer at `main`'s current HEAD and diffs; for pairs with **no** `ref` arg
(the `selftest.py` shape), re-runs unconditionally and diffs. It should classify each result
as MATCHES / DRIFTED / CANNOT-RERUN exactly the way I did by hand here, and — this is the part
that actually enforces something — **fail loudly on CANNOT-RERUN** (a hardcoded dead worktree
path, like `a2-31`'s and `t185`'s, is itself a defect: an instrument nobody can rerun is an
instrument nobody will rerun). It should NOT auto-fail on DRIFTED, because DRIFTED is
sometimes the correct, expected state for a deliberately pinned historical demonstration
(`engine-divergence-output.txt`) — the check needs a per-file declaration of "this is a live
sweep, expected to need re-recording" vs "this is a pinned historical capture, DRIFT here is
itself the alarm." That per-file declaration does not exist today and is the actual missing
piece; a2-33's `sweep.sh` header comment (documenting T238's fix) is the closest precedent in
the repo for "an instrument that explains its own staleness risk in its own output," and is
the best model to generalize from.

**What enforces it, honestly stated:** nothing does yet. A convention with no check is exactly
the fail-open class this program has named (P-45, "a convention nothing checks"), so I am not
claiming this recommendation closes the loop — I am recommending it be scheduled as a task,
per the explicit instruction not to wire it here. Until it exists, the only thing that
"notices next time" is a human or worker doing what this task did by hand.
