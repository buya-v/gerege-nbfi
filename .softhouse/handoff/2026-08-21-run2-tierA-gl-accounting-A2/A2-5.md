# A2-5 — capture-rig fixes: D-2 (unreachable transport-failure handler) and D-3 (three-way blind `manifest.py verify`)

Branch `softhouse/A2-5-capture-rig-fixes`. Scope: `.softhouse/capture/tierA-a2/` only. No Go code, no
contract, no vector promoted, no money value computed. No oracle call was made by this task — the D-2
prover deliberately targets a CLOSED port (127.0.0.1:1), which is the whole point of it.

Every material claim below is marked. `[VERIFIED: …]` means I ran it in this worktree and read the output.

## Changes Made

**`cap.sh` — D-2, the dangerous one.** Two changes, because the defect had two halves.

1. `code=$(curl …)` is now `code=$(curl …) || rc=$?`. Keeping the failing command inside an AND-OR list
   is what makes the handler reachable under `set -e`. **Reachability is proven, not reasoned**
   (requirement 6): 16 interpreter/option combinations × 2 code paths = 32 cases, all green
   [VERIFIED: `RED-GREEN-D2-cap-transport.txt`].
2. **Nothing under `out/` is written until the exchange completed.** Previously `out/NAME.http` was
   written *before* the request, with a fresh `captured-at-utc` — that ordering is what turned an
   unreachable oracle into fake evidence. The body now lands in a `mktemp -d` sandbox and is moved into
   place only on `curl rc=0`; `.http` and `.status` are written after that. The timestamp is still
   stamped *before* the request (same semantics as before) but only *committed* on success.

   `set -eu` (was `set -e`) and `${1-}`…`${4-}` for the positional args, so `-u` does not detonate on the
   3-argument (no body file) form.

   **Deliberate deviation from the brief's literal description of the old handler.** The old handler's
   `rm -f "$OUT"` is *not* restored. On a transport failure the fixed script deletes **nothing** under
   `out/` — pre-existing artefacts are evidence, they are covered by `MANIFEST.sha256`, and deleting them
   would both destroy evidence (requirement 3/4) and turn every failed retry into a manifest breakage.
   The stale-under-fresh artefact the `rm -f` existed to prevent is instead prevented *structurally*, by
   never writing a fresh timestamp in the first place. The handler names any pre-existing file for that
   NAME and prints the `captured-at-utc` it actually carries, so a caller cannot mistake it for this
   fire's observation.

**`run-*.sh` — D-2's other half, found while driving it.** All five run scripts are deliberately *not*
`set -e` (a refusal is an observation), so `sh cap.sh …` failing was ignored and the next line
`cat`-ed the stale body into the transcript as if just observed. Every one of the **15** `cap.sh` call
sites now carries `|| exit 1` [VERIFIED: prover counts 15/15 in the shipped files]. A handler that fires
into a caller that ignores it is still blind.

**`manifest.py` — D-3, all three blind spots.**

- (i) **Zero inspected files is now an ERROR** (requirement 2). Two refusals fire *before* any comparison:
  an empty manifest → `REFUSING: MANIFEST.sha256 lists 0 files — INSPECTED NOTHING`; and a `REQUIRED`
  floor (`CAPTURE-PLAN.md`, `DEFECTS-FOUND-BY-REVIEW.md`, `FLAGGED-NOT-REPRODUCIBLE.txt`, `cap.sh`,
  `env.sh`, `manifest.py`) so a *stripped* manifest cannot pass vacuously either — that is the same
  defect through a narrower hole, and it is the one that fires on the real tree.
- (ii) **Recursive.** `os.walk` with sorted dirnames/filenames replaces `os.listdir`, so a fabricated
  observation in `out/<subdir>/` is `UNTRACKED`, not laundered.
- (iii) **Covers the analysis doc, the rig, and itself.** Every regular file in the capture directory
  except `MANIFEST.sha256` is hashed, `manifest.py` included.
- Plus **flag integrity**: `verify` cross-checks `FLAGGED-NOT-REPRODUCIBLE.txt` — a flagged file that
  vanishes from disk (`FLAGGED-BUT-ABSENT`) or loses its manifest line (`FLAGGED-BUT-UNCOVERED`) fails
  the run — and reprints the flag on every green run. A malformed manifest line is now a refusal instead
  of an uncaught `ValueError`.

**`FLAGGED-NOT-REPRODUCIBLE.txt` (new).** Requirement 4: the 30 `attempt1-*` files are kept, kept in the
manifest, and now carry their D-1 flag *in the rig* rather than only in prose. Nothing was deleted.

**`prove-cap-transport-red.py`, `prove-manifest-blind-red.py` (new).** The two counterproofs. Both read
the **real pre-fix bytes from their immutable git blobs** and refuse to run if the blob's sha256 does not
match, per P-22 ("a proof that only shows the after cannot distinguish a fix from a no-op"):
`cap.sh` blob `55d5d63a…` sha256 `5820f363…`; `manifest.py` blob `cbc888d4…` sha256 `65e54af9…`
[VERIFIED: `git rev-parse`, `shasum -a 256` in this worktree].

**`CAPTURE-PLAN.md`** — one marked A2-5 block appended to the *final* paragraph only, because that
paragraph ("`manifest.py verify` is demonstrably failable") was an overclaim A2-4 disproved: it was true
of the hash comparison and false as a claim about coverage. Nothing else in the plan was touched; no
finding, number or table was altered.

**Not changed:** `prove-manifest-red.py`, `env.sh`, `mkreq*.py`, `show.py`, `rename1.py`, `sql/`, and
every byte under `out/` and `req/`.

### D-2 — the handler could not fire, and the artefact it produced was fake evidence

Pre-fix `cap.sh` (blob `55d5d63a…`), sandbox seeded with an earlier fire's body/status and an
`out/NAME.http` reading `captured-at-utc: 2000-01-01T00:00:00Z`, endpoint = closed port:

| | pre-fix | post-fix |
|---|---|---|
| exit code under `/bin/sh` | **7** (curl's own status — `set -e` killed the shell at the assignment) | **1** |
| `TRANSPORT FAILURE` on stderr | **never printed** | printed |
| earlier fire's body on disk | intact, byte-identical | intact, byte-identical |
| `out/NAME.http` timestamp | **rewritten to today** | still `2000-01-01T00:00:00Z` |

That row three + row four combination *is* the defect: **stale oracle bytes under a fresh
`captured-at-utc`.** [VERIFIED: transcript, `DEFECT REPRODUCED`.]

Post-fix, the handler fires and exits 1 in **all 32 cases** — `/bin/sh`, `/bin/bash`, `/bin/dash`,
`/bin/zsh`, `/bin/ksh`, each with `-e`, `-u`, `-eu`, `-o pipefail`, `-eu -o pipefail` as applicable, plus
execution via its own shebang, across both the body and the no-body branch — with the earlier fire's
bytes byte-identical and its timestamp untouched every time [VERIFIED: transcript, 32 × `CAUGHT`].

Two things I did **not** predict and am recording because they are true:

- Pre-fix under `-u` on the *no-body* branch, the script died even earlier, at `BODY=$4` (unbound
  variable), exit 1 with nothing written. So 12 of 16 pre-fix combos produce the stale-under-fresh
  artefact on that branch, and **16 of 16 on the body branch** — not "all shells", and I am not going to
  round it up.
- `curl` never truncated the stale `out/NAME.json`, because it never connected. That is *why* the
  ordering (writing `.http` first) was the fatal part, and why the fix is ordering, not deletion.

D-2b, the caller: pre-fix `cap.sh` + the old loop body → batch **exit 0** and stdout
`-> {"stale":"BODY FROM AN EARLIER FIRE …"}`. Post-fix + `|| exit 1` → exit 1, stdout empty
[VERIFIED: transcript].

### D-3 — verify was blind, seven ways once I attacked it

Each attack: build a sandbox shaped like this capture, `write` the manifest with the tool under test,
perform the attack, `verify` with the same tool. Pre-fix column is the **real** pre-fix blob.

| attack | pre-fix | post-fix |
|---|---|---|
| (i) empty manifest, empty capture | `OK: 0 files match`, **exit 0** | exit 1, `INSPECTED NOTHING` |
| (i-b) manifest written by the OLD tool, verified by the new | `OK: 11 files match`, exit 0 | exit 1, `REFUSING … does not cover` |
| (ii) `out/sub/A2-999-fabricated.json` | exit 0 | exit 1, `UNTRACKED out/sub/…` |
| (iii) reviewer's *"MNT rounds HALF_EVEN and money may be stored as float"* appended to `CAPTURE-PLAN.md` | exit 0 | exit 1, `CHANGED CAPTURE-PLAN.md` |
| (iii) `manifest.py` edits itself | exit 0 | exit 1, `CHANGED manifest.py` |
| (iii) `cap.sh` repointed at another endpoint | exit 0 | exit 1, `CHANGED cap.sh` |
| D-1 flag file deleted | exit 0 | exit 1, `REFUSING … flag … cannot be dropped` |

Three further refusals are new and had no pre-fix counterpart to be blind to, so they are driven red on
the fixed tool alone: flagged evidence deleted from disk (`FLAGGED-BUT-ABSENT`), flagged evidence whose
manifest line was stripped (`FLAGGED-BUT-UNCOVERED`), and a malformed manifest line (`MALFORMED`).
A **control** run on an untampered sandbox goes green — without it every RED above would be equally
consistent with a tool that always fails [VERIFIED: transcript, `exit 0 -> GREEN`].

On the **real tree**, the fixed tool refuses the manifest exactly as A2-3 shipped it:

```
REFUSING: MANIFEST.sha256 does not cover CAPTURE-PLAN.md, DEFECTS-FOUND-BY-REVIEW.md,
FLAGGED-NOT-REPRODUCIBLE.txt, cap.sh, env.sh, manifest.py — this is not a manifest of this capture.
```

That is D-3(iii) reproduced on the actual evidence, not a sandbox [VERIFIED].

## Follow-ups

Outside `.softhouse/capture/tierA-a2/`, so recorded as backlog rather than diffed:

1. **The same `set -e` / `rc=$?` shape may exist in other capture rigs.** I found it in A2's `cap.sh`
   because A2-4 named it. Nobody has swept `.softhouse/` for `code=$(curl …)` followed by `rc=$?` under
   `set -e`, or for a `.http`/metadata file written *before* the request it describes. That second
   pattern is the more dangerous half and it is invisible to a grep for `rc=$?`. Worth a task that greps
   for the *concept* (metadata stamped ahead of the exchange), not the sentence — P-26.
2. **`manifest.py` is per-capture-directory and now diverges.** Other capture dirs carry their own copy
   of the pre-fix tool, still non-recursive, still vacuous on empty input, still not covering their own
   analysis docs. Either promote one hardened copy to a shared location or replicate this fix, but the
   three blind spots are almost certainly still live elsewhere. **I did not enumerate which directories**
   — that is outside my scope and I am not going to assert a count I did not take.
3. **D-1 is closed as a flag, not as a defect.** The 10 `attempt1-*` recipes still cannot regenerate their
   outputs. The flag now has teeth (they cannot be silently deleted or uncovered), but if slice A2 ever
   needs those behaviours they must be **re-captured**, not cited.
4. **`prove-manifest-red.py` hard-codes a victim file** (`out/A2-084-disburse-loan1-paymenttype1.json`)
   and exits 2 if it is absent. Harmless today; brittle the moment that observation is re-captured under
   a different id. Left alone — changing it was not in scope and it is not a correctness defect.
5. **The `.http` records still say `Authorization: Basic <mifos:password>`** — correct redaction, but
   note it means an `.http` file is not directly replayable without `env.sh`. Not a defect, just a fact
   the next capture task should know before assuming `.http` is a runnable recipe.
