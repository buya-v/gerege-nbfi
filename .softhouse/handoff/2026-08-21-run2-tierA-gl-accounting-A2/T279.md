## 1. F-1 — the non-partition, DEMONSTRATED BY RUNNING THE PREDICATES

`.softhouse/capture/t279-lock-partition/rules.py` transcribes each arm of STEP 0 into a boolean function —
one function per sentence, using **only** the terms that sentence names, because "helpfully" supplying a
missing conjunct is precisely how a rule set stops partitioning. `enumerate.py` then runs every arm against
every state. Output: `out/enumeration.txt`.

**The state space, 5 dimensions, 192 states / 97 distinguishable** (lock-absent collapses the other four,
since there is no file to read them from):

| dimension | values |
|---|---|
| lock | present, absent |
| `released_at` | null, set |
| `started_at` age | <6 h, 6–24 h, ≥24 h, **unreadable** |
| `origin/main` tip age | <6 h, ≥6 h, **unreadable** |
| `pid` | alive-here, dead-here, absent, other-host |

`unreadable` is a first-class value, not an edge case: STEP 0 is read by an agent on a fresh clone against a
hand-written LOCK, and *"I could not read that signal"* is a state the rule set must have a verdict for.

### RESULT — the four shipped arms

```
A. STATES MATCHING ZERO ARMS (no verdict):        18
B. STATES MATCHING MORE THAN ONE ARM:             24
C. ... where the matching arms give DIFFERENT verdicts: 22
D. pairwise overlap:  O1&O3: 8   O1&O4: 12   O2&O4: 4   O3&O4: 4
VERDICT: NOT A PARTITION
```

Two classes, and the second is worse than the one T265 named:

**(a) 18 states with no verdict.** T265's named state is there —
`{released_at null, started_at <6 h, tip ≥6 h}`, three rows (pid alive / absent / other-host), the state of
every 08:00 fire. The other 15 are the **unreadable-signal** rows: *every* state where `started_at` or the
tip could not be parsed falls out of the table entirely. STEP 0 says *"the test, in order: 1…4"* and stops.
An agent that matches nothing improvises, and improvising is how the incident happened.

**(b) 22 states where two arms give OPPOSITE answers.** This is not in T265's report and it is the sharper
half of F-1. `{released_at null, started_at <6 h, tip <6 h, pid dead-here}` matches **arm 2 → HELD** and
**arm 4 → TAKE OVER**. Both arms are as written, both fire, and they contradict. The verdict is then
whichever arm the reader happened to evaluate first — i.e. **the answer depends on reading order**, which is
exactly the condition under which a local fire and a cloud fire can both conclude they may proceed.
`{released_at set, started_at ≥6 h, tip ≥6 h}` similarly matches arm 1 (FREE) and arm 3 (TAKE) — same
direction, so harmless, but it is the same structural defect.

### RESULT — the seven repaired arms

```
A. STATES MATCHING ZERO ARMS:                      0
B. STATES MATCHING MORE THAN ONE ARM:              0
C. conflicting:                                    0
D. pairwise overlap:  (none — all arms pairwise disjoint)
E. STATES CAUGHT ONLY BY THE DEFAULT ARM:         15
VERDICT: PARTITION
```

**The proof is stronger than "add a default arm".** A default makes an *ordered* list total, which is cheap
and still leaves the order load-bearing. The repaired arms are written with explicit exclusion prefixes so
that **exactly one arm matches every state and no two arms ever both match** — so reading them out of order
cannot change the answer at all. That is the property F-1 actually needs, and it is asserted a second time
inside `drive-wrapper-vs-skill.zsh` (`assert len(m) == 1` for all 192) so it cannot rot silently.

The 15 states the default catches are exactly the 18 that had no verdict, minus the 3 that arm 3 (ceiling)
now claims. All 15 resolve to **HELD**.

## 2. F-2 — what rule 2 should ask, and the measurement that decided it

**The question rule 2 asks today is the wrong one, and refining the answer does not fix it.**
`git log -1 --format=%ct origin/main` asks *"has anything been published to the repository recently?"* The
question that has to be answered is *"is there still reason to believe **this holder** is alive?"*, and that
decomposes into **two necessary terms**:

* **evidence of life** — something was published recently; and
* **possibility of life** — the holder has not exceeded the longest life a fire can have.

Rule 2 supplies only the first. The first is refreshed by **third parties** (21 distinct git identities
publish to this `origin/main`), so on its own **the lock has no guaranteed takeover time whatsoever** —
which is precisely the property the old `started_at` rule had and this one silently gave up. The second term
is what restores it.

**`started_at` is not a freshness signal, but it IS a valid lifetime bound**, and that distinction is the
whole of the repair. It cannot tell a dead holder from a working one — that is P-85 and it stands. It can
tell you the holder *cannot possibly still be legitimately alive*. Using it as an upper bound is sound;
using it as the primary staleness test is what caused the incident.

### The two candidates, measured on the same fire history (`measure-f2.py`, `out/measure-f2.txt`)

History has grown since T265: **25 real fires** now (T265 had 21), 1967 commits on `origin/main`.
T265's headline reproduces in shape: **18 of 25** fire starts read a stranded lock as HELD (T265: 16 of 21).

| | (A) author-match | (B) ceiling at 24 h |
|---|---|---|
| verdicts CHANGED vs rule 2 as written, over 24 real fire starts | **0** | **1** |
| restores a guaranteed takeover time? | in principle | **yes, at `started_at`+24 h** |
| cost | a new LOCK field that does not exist | takes over a fire legitimately running >24 h |
| **safety hazard** | **24 of 25 fires publish under MORE THAN ONE git identity** | longest fire ever: **9.52 h**; margin **2.52×** |

**(A) is rejected, on measurement rather than taste.** It changes **nothing** on the entire recorded
history — 0 of 24 verdicts — and it is *unsafe*. The LOCK body records `holder`, `host`, `pid`, `fire` and
**no git identity at all**, so the field must be invented, and it can name only **one**. Meanwhile a single
live fire publishes under `Buyanmunkh` (the driver session), `Buyan` (the wrapper's own lock commits),
`SoftFactory`, `Claude` (the cloud fire), and per-task identities — 24 of 25 fires used ≥2, one used 5.
So a **live** holder publishing under its other identity reads STALE, and F-2's *liveness* bug becomes the
**P-85 *safety* bug**. Buying zero verdict changes at the price of a false-STALE is a bad trade.

**(B) is adopted.** And its one verdict change is not synthetic: at the start of `fire-20260827-230001` a
lock **105 h old** faced a tip **2.99 h old**. Rule 2 as written reads that as HELD-by-a-live-holder, and
there is no age at which it stops. Arm 3 takes it.

Honest cost, stated: arm 3 will take over a fire that legitimately runs past 24 h. None ever has (9.52 h is
the record, 2.52× margin), and arm 2 (dead pid) already rescues the same-host case sooner. If a fire ever
does need >24 h, the fix is to raise `LOCK_CEILING_SECS`, not to delete the arm.

## 3. F-3 — the wrapper now decides the SAME way, and that is measured, not asserted

`fire-program.sh` decided staleness on `/usr/bin/stat -f %m "$LOCK"` — the **file's mtime** — which the

It now runs `lock_decide()`, a **pure function of five signals** (`fire-program.sh:100-133`), plus four

worker spawn on a false positive is a hook that parks the whole program (T318 arm G5, T325's own headline).
