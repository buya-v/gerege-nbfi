## 1. THE FRAMING QUESTION — was the substitution right?

**Yes, and it was necessary.** T183's patch, applied as written, would have made the classifier
**worse than not patching at all** for the exact shape it was written to fix. I reproduced this

The deeper point, and the most important thing in this review:

> **T183's own in-patch safety argument is technically true and materially false.** The patch's
> comment reads *"Feeds `partial`, so it can only ever change the reported SCOPE tag, never a
> guard verdict."* In this tool the scope tag **is** the excuse mechanism:
> `guard_classify.py:975-976` — `if verdict == UNGUARDED and scope == SCRATCH: verdict = SANDBOX`

protects against **unreviewed** code, not against **changed** code. T183 was right not to merge

is preserved by structure, not by the patch being byte-identical: implementer implements

version reviewed.** Had T196 shipped the defect to stay faithful to the letter of its brief, the
program would have merged a regression with a reviewer's name on it — the worst of both rules.

## 4. Q3 — "same direction, two questions". **T196 is right, and it matters.**

I read both blocks and they are structurally isomorphic:

- `indirectly_guarded_funcs` (base `:452-469`): for each **function**, gather its **call sites**,
  ask *"is every call site inside a try/finally?"*, propagate the answer **into the callee body**.
- T196-1 (`:330-390`): for each **function**, gather its **call sites**, ask *"what string does
  the actual argument name?"*, propagate the answer **into the callee body**.

Both are *callee looks up its callers*; both move a caller-side fact into the callee. In standard
dataflow terms both are **forward** (arguments and calling context flow caller→callee); neither is
backward. **T183's "mirror-image forward/backward" framing is wrong**, and T196's correction is
right on both the implementation reading and the dataflow reading.

**It matters to scope, materially.** T196 was dispatched to repair two named findings, not to add
capability. If the step were a genuinely new *backward* analysis, adding it would be scope creep
and a rejection under the one-context rule. Framed correctly — the tool **already** performs this
traversal, for guards but not for names, and the fail-open lives entirely in that gap — it is the
**completion of an existing analysis**, which is in scope. The near-isomorphism of the two code
blocks is the evidence, and it is checkable rather than rhetorical.
