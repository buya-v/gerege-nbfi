### Is a numeric-claim detector soundly buildable? — I built it and measured it. It is INERT.

The brief's observation is right: a count is a claim, and `0` from an instrument that never
reached its corpus is indistinguishable from `0` measured honestly. But the natural
implementation — widen `RE_REASSURE`, the vocabulary C2b already consults, with 14 count shapes
(`: 0`, `= 0`, `0 <noun>`, `{var}`, `%d`, `$n`) — measures as follows over the whole tree
[VERIFIED: `transcripts/20-numeric-vocab-probe.txt`]:

```
frontier rows  V0 -> V1   : 10 -> 10
frontier GAINED           : 0
frontier LOST             : 0
does V1 see the subject?  : NO -- STILL INVISIBLE
```

**So the answer to "would it drown in false positives?" is: no — it produces none. It also
produces no true positives. It buys literally nothing.** That is a stronger reason to reject it
than noise would have been, and it is measured rather than argued.

Two **independent** structural reasons, each checked directly against the subject so neither
rests on the other:

1. **The print predicate is shell-only.** `RE_UNCOND_PRINT = ^\s*(?:echo|printf)\b`. The false
   count is emitted by `print(f"...")` at `:142` inside a `python3 - <<'PY'` heredoc. That line
   **does not match**, so it is never offered to any vocabulary — no wordlist can be widened
   enough to reach a line the predicate rejects. (Both terms, P-67: that file has **17** shell
   `echo`/`printf` and **12** python `print(`.)
2. **The association window is 3 code lines.** The `cd` is at `:24`, the claim at `:142` —
   **110 code lines apart, 36× the window**, with `python3 - "$R" <<'PY'` at `:34` breaking the
   association long before it.

Widening the window to 110 lines associates a `cd` with everything a script ever prints, which
is not a rule; widening the print predicate to every language's print without an association
rule is worse. **A vocabulary is the wrong AXIS, not the wrong wordlist.**

### What closes the gap instead: C6 — CORPUS ENTRY IS NON-FATAL

> A file that **enters** an absolute directory that does not exist now — `cd`, `pushd`,
> `git -C`, `--git-dir=`, `--work-tree=`, as a literal **or through a variable assigned a
> literal absolute path earlier in the same file** — and whose entry does not terminate it,
> is fail-open. Everything it prints afterwards is printed about a directory it never entered,
> in whatever words, in whatever language, at whatever distance.

C6 reads **no output words at all**. Termination is *established*, never assumed, by exactly two
checkable things: `errexit` in force at that line (tracked **forward through `set +e`**, so a
disabled option is never read as a protection), or a fatal arm on the entry line (`|| exit`,
`|| return`, `|| die`, `|| _sw_die`, `|| {`). C1's two measured filters — `XXX` is a `mktemp`
template, and a path the file creates/deletes is scratch — are inherited unchanged.
