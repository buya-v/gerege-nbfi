## 2. HARD or SOFT for T299 — the decision, and the measurement behind it

**HARD.** The objection in the brief is real: a HARD guard on a heuristic threshold blocks every
graded run the first time somebody names a directory reasonably. T323 answered it by counting the
**whole history**, not today's tree:

```
git log --format= --name-only --diff-filter=A -- .softhouse/capture .softhouse/reviews
  -> 128 evidence directories EVER created in this repository
  -> 107 carry a t<n> id prefix
  -> ids prefixing MORE THAN ONE directory, over the entire history:  exactly ONE
  -> and it is T256/T259, the real defect the guard was written for, already declared
```
[VERIFIED: T323 ran it.]

So the predicate's **false-positive count over every evidence directory this program has ever
created is zero**, and its true-positive count on the only event in class is one. The residual
risk is prospective — a future task legitimately wanting two directories — and for that the
threshold is already `N−1` rather than `N`, which is the lowering T299 made after its own first
draft went red against a correctly-named directory. The remedy the guard *prints* is to add one
file whose entire content is the sentence the rule is asking for. **A guard whose remedy is
"write the sentence the rule wants" is not a blocker; it is the rule.**

SOFT was rejected because SOFT is the defect this task exists to remove — `P-22`, *"a guard, a
canary, or a control that cannot fail is worse than none, because it is believed"*.

**Residual risk, recorded so it is not rediscovered as a surprise:** the id space is folded
across `capture/` **and** `reviews/`, so a future `reviews/T<n>/` directory beside a
`capture/t<n>-…/` directory would collide. That shape does not exist today — reviews are
overwhelmingly flat `.md` files and no tracked review *directory* shares an id with a capture
directory. If reviews become directories by convention the two namespaces need separating, the
way T299 already separated the `a2-<n>` space after folding it produced four false collisions.

### A real defect the wiring found and repaired

T299's guard resolves its own root with `git rev-parse --show-toplevel`, which answers a question
about **the caller's working directory**, not about `$REPO_ROOT`. Measured, not reasoned:

```
$ cd /Users/buv/gerege-nbfi && bash <WORKTREE>/.softhouse/guards/check-capture-namespace.sh
namespace:   root    /Users/buv/gerege-nbfi          <- the WRONG tree
```
[VERIFIED: T323 ran exactly this.]

Wired naively, that reintroduces the divergence `guard_graded_root_is_this_tree` exists to refuse
(T165/T201). The wiring therefore (a) runs the guard in a subshell pinned to `$REPO_ROOT`, and
(b) **does not take its word for it** — it reads back the `namespace:   root` line and refuses
unless it names `$REPO_ROOT`, physical paths on both sides. Arm `T299-04` drives that readback
red. This is wiring, not a redesign of T299's guard: the guard's own file is unmodified.

## 3. T316 — the frontier was ALREADY RED on main, and why the delta lives in `conformance.sh`

Before any wiring, on a clean checkout of `main`:

```
T316-DEADPATH-FRONTIER: REFUSED rows=102 pinned=98 added=4 removed=0
```

**This is `P-83` exactly** — *"TWO INDEPENDENT MOVEMENTS OF ONE PINNED NUMBER RECONCILE BY
RUNNING, NEVER BY ARITHMETIC"* [VERIFIED: `.softhouse/patterns.md:2775`]. T316 re-derived its pin
at 98 in `5b4f6702`; T305's red drive landed separately in `bb72b57b` and names four paths that
do not resolve. The two could not see each other:

```
$ git cat-file -e 5b4f6702:.softhouse/capture/t305-openingbalance-accepting-side/red-drive-conformance-guard.sh
fatal: … exists on disk, but not in '5b4f6702'
```
[VERIFIED.] **102 is a measurement taken by running the guard on the merge result; it is not
98 + 4.**

**The four rows are dead-by-design and were inspected, not inferred.** All four belong to T305's
red drive and all four are paths that drive *creates at run time inside a throwaway clone*
(`:58`, `:59`, `:101`, `:102`); `t999-rig` is a deliberately fictional task id. A red drive plants
a file that must not exist in a clean tree — that is what makes it a red drive.

**Why the reconciliation lives in `conformance.sh` and not in the pin.** The correct home for
these rows is `.softhouse/guards/dead-path-frontier.pin`. **That file is outside T323's edit
grant**, and wandering outside a grant is the scope violation this program treats as a
rejection — *the same constraint that left these three guards unwired in the first place*. So the
delta is carried in the file T323 does hold, as `DEADPATH_T323_RECONCILE_LIST`, in the shape of
the two pins already in that file.

**The list is NINE rows in two groups, and the line between them is the reusable part.** Group 1
is T305's four. Group 2 is **five rows from T323's own `drive-red-t323.sh`**, which is a tracked
instrument and therefore visible to the census, and which names paths that must *not* resolve
because planting them is its function — a red drive naming only paths that resolve could not
drive anything red.

That looks identical to the case in §4 that was *repaired* rather than pinned, so the test is
written into the file beside the list:

> **Can the instrument still do its job if the literal goes away?**
> **YES → it is INCIDENTAL — repair it.** (§4: the prose quoted paths it did not need; an
> ellipsis cost it nothing.)
> **NO → it is FUNCTIONAL — pin it, and write down which operation needs it.** (Group 2: the
> literals *are* the arguments to the operations the drive exists to perform.)

Rewriting Group 2's literals into runtime-assembled variables would have made the number go green
by hiding true dead literals from a census whose whole job is to find them — defeating the
instrument to flatter its own figure, which is the pinning-away this frontier exists to prevent.

**It cannot rot into an amnesty.** The wiring refuses if the guard goes **green** while the list
is non-empty (arm `T316-08`), if anything is **removed** from the frontier, if any added row is
not a byte-exact member of the list, if the list has a member that is not added, or if the
guard's `added=` cardinal disagrees with the number of `+` rows it printed (its listing truncates
at 40, and comparing against a truncated set would let row 41 through).

> **ACTION FOR WHOEVER NEXT HOLDS THE PIN:** fold these nine rows into
> `.softhouse/guards/dead-path-frontier.pin` and set `DEADPATH_T323_RECONCILE_LIST=''` **in the
> same commit**. Doing one without the other fails the bar by design (arm `T316-08` drives
> exactly that half-done state red).

### The self-referential property survived — verified, not inherited

T316's guard refuses at exit 2 when any path *it* depends on fails to resolve. T323 did not take
that on faith after wiring: arms `T316-06` (census removed) and `T316-07` (pin removed) each run
**the whole bar** and require exit 2 with the oracle probe line **absent**.

**`P-95` was obeyed rather than cited.** *"A dead literal is equally consistent with a fail-open
and with an announced fallback, so it can never be classified by reading — only by removing every
candidate and observing the exit"* [VERIFIED: `.softhouse/patterns.md:3084`]. No path in this work
was classified by reading it; the removal experiment was run.

## 5. T304 — NOT wired, and the reason is a finding

Full argument and figures: `.softhouse/capture/t323-wire-the-unwired-guards/T304-CENSUS-NOT-WIRED-AND-WHY.md`.

T323 tested the obvious answer (pin the population, fail on growth — the shape used three times
in this file already) and it does not work here. Two measurements:

**(1) It has already moved, hard, in one day.** T304's three instruments re-run unmodified:
raw sites `4,901 → 5,409`; resolved `1,574 → 1,798`; **HARD sites `223 → 307` (+37.7%)**. A guard
pinned at 223 is red by 84 rows on its first graded run, one day after the census was committed.

**(2) The load-bearing one: the census is not a function of the instruments.** Three instruments
that newly contribute a hard site were last touched **2026-08-19, -21 and -22** — before T304's
census on **2026-08-27** — and **their bytes have not changed** [VERIFIED: `git log -1` per file].
T304's resolver classes a target TRACKED if it *"is a directory prefix of at least one tracked
path"* (`20-resolve-targets.py:13`, T304's own honest documentation), so a site's classification
depends on the **whole tracked corpus**. Committing an unrelated file elsewhere flips an old
script from "scratch" to "destroys committed evidence" with no commit touching it.

**A frontier pin is only reviewable when a moved row is attributable to the diff that moved it.**
Here rows move for reasons no diff contains, so the only available response each fire is to
regenerate the pin — `P-22` with a maintenance cost, and the "switched off within two fires"
outcome the brief predicted.

**Consequence worth more than the wiring:** T304's 223-site classification into
defect / correct-by-design / correct-but-undeclared **is already stale by 84 rows**, for reasons
unrelated to anyone's code being wrong. A future task citing "T304 classified 223 sites" as a
standing fact is citing a number that moves on its own.

Two directions for the follow-up, offered as directions and **not** as findings — neither was
built or driven by T323: (a) make the declaration **local to the instrument**, so a row moves only
when that instrument's diff moves it (T299's *"say who owns it"* applied to destruction: *"say
what you are destroying"*); (b) pin only the corpus-independent `TRACKED-FILE` half — **whether
that half is actually stable is `[UNVERIFIED]`** and must be measured across two commits before
it is believed.

### 6c. P-84 survives — and it is an assertion, not a hope

> **`P-84` — "EXIT 2 WITH NO PROBE LINE" IS THE GUARD WORKING. READ THE ABSENCE, NOT THE VALUE.**
> [VERIFIED: `.softhouse/patterns.md:2782`]

By construction: `run_guards` is called on `main_grade`'s second line and `probe_oracle` is not
reached for ~25 lines after it, so a refusal from any of the three exits 2 with the probe line
**absent** — not `down`. The driver's park condition is `exit 2` **and** a probe line **present**
**and** reading `down`, so a guard refusal cannot be parked as an oracle outage.

**Every red arm asserts `probe=ABSENT` as a pass condition, and the green control asserts
`probe=PRESENT`.** If a red arm ever shows `PROBE=PRESENT` the arm fails. Two of T299's arms and
the T316 refusal arms depend on this staying readable, so it is graded rather than described.

### 6d. Fail-closed direction, stated per guard, not widened

Deliberately three narrow directions rather than one broad predicate — the shape T292 identified
as the root of a five-fix losing streak, and three guards landing in one commit is exactly when
it would happen:

- **`guard_capture_namespace`** — fails closed towards *"an undocumented id collision, or a corpus
  this guard could not verify it was reading, is a refusal"*. Says nothing about content, dead
  paths or ownership predicates.
- **`guard_dead_path_frontier`** — fails closed towards *"any movement of the dead-path frontier
  that is not the one recorded and reasoned about here is a refusal"*. It **counts; it does not
  classify** — it does not judge whether a dead literal is a fail-open, because T316 measured that
  it usually is not.
- **`guard_reconciler_ownership`** — fails closed towards *"the ownership predicate that can demote
  live work is ungraded, or grades wrongly, is a refusal"*. Says nothing about namespaces or dead
  paths.

### 6e. `--selftest` is not optional

T319's argument was read before deciding and is accepted: the RED leg is the only thing
distinguishing this guard from one that cannot fail (`P-22`), and a flag somebody sets on good
days is `P-45` by another name. Making it optional would have rebuilt the defect this task exists
to remove. The wiring also requires the rig's `SELFTEST OK:` attestation to be **present** — a
zero exit without it is an instrument failure, not a pass.

Arm `T319-10` confirms the matrix's own contract still fires through the wiring: with no cell able
to see a re-dispatch, `_assert_matrix_can_see_a_redispatch` fails **the whole run** rather than
producing a smaller green one.
