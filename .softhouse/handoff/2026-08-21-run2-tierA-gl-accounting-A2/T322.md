## 1. THE HOLE, AND ITS FAIL DIRECTION

### What it was

T305 wrote the opening-balance leg condition out **three times** and the copies were **not
complements**:

| rule | gate as T305 left it |
|---|---|
| POSITIONAL `amount_major_text` pairing | **skipped** when `command == "defineOpeningBalance"` |
| MULTISET `amount_major_text` pairing | **applied** when `command == "defineOpeningBalance"` **AND `kind != "refusal"`** |

So for `command == "defineOpeningBalance"` **AND** `expect.kind == "refusal"` **AND**
`len(expect.legs) > 0`, **both were off and the request/expect amount cross-check was absent
entirely.** Before T305 the positional rule covered that case.

T306 replaced the three copies with one boolean
[VERIFIED: `nexus/internal/apps/ledger/conformance/admit.go:741`]:

```go
obAcceptingLegs := v.Request.Command == "defineOpeningBalance" && v.Expect.Kind != "refusal"
```

read by the length rule, by the positional rule (`!obAcceptingLegs`) and by the multiset rule
(`obAcceptingLegs`) — now **exact complements**. **The code was right when I arrived. Nothing
asserted it.**

### THE FAIL DIRECTION, STATED

`Admit` is **fail-closed**, and its output is **a refusal to GRADE — never a verdict on a port.**
A reason added here removes a vector from the graded corpus (the run counts it `inadmissible` and
compares none of its cells). The two directions are **not symmetric**:

- **CLOSING the hole can only ever make MORE vectors inadmissible.** It cannot make a wrong
  implementation pass, cannot move a money cell, and cannot turn a FAIL into a PASS. Its worst
  case is a vector this store loses and a bar that goes **red loudly**.
- **LEAVING it open** lets an expect amount that is **not** the amount the request carried enter
  the store **silently**, be graded as truth, and become the standard a Go port is measured
  against. That is an **unobserved number entering a money corpus**.

So the closure is the cheap side of an asymmetric bet, and the only thing worth measuring is what
it cost. **Measured: zero.** `THE FAIL DIRECTION, MEASURED` asserts every committed vector still
admits with no reason at all, and the bar reports `inadmissible 0`.

### WHY IT WAS CLOSED ANYWAY, THOUGH IT WAS UNREACHABLE

T306's own note says the combination is already inadmissible one rule higher: the `case "refusal"`
arm refuses `len(v.Expect.Legs) > 0` **unconditionally**
[VERIFIED: `admit.go:676-680` — *"expect.legs is non-empty on a refusal expectation. A refused
request created no entry…"*]. That is true, and it is **exactly the shape of dependency this file
exists to refuse**: an argument that a money gate's hole is unreachable, resting entirely on a
different rule staying exactly as it is, **with nothing pinning that rule**.

So the arm `the SECOND rule is not doing the work` asserts **both** sentences on the same vector —
the amount rule ABSENT when amounts agree, the refusal-legs rule PRESENT — which is what pins the
dependency instead of trusting it.

### THE ARMS (new file `nexus/internal/apps/ledger/conformance/admit_widening_test.go`)

| arm | what it fires on |
|---|---|
| the COMMITTED refusal vector is admitted with NO reason at all | anti-vacuity: a rule that refused everything would satisfy every RED arm while emptying the corpus |

[`.softhouse/capture/t322-admit-widening/out/DETERMINISM.txt`]:

```

EVALUATIONS = 1300  (65 Admit() calls per invocation, each in a fresh process)
T322-DETERMINISM: byte-identical reason text in 20 independent processes -- EXIT 0
```

**Why repetition and not a source read.** Reading `sort.Strings(surplus)` proves the call is
*there*; it does not prove the report is stable — a second unsorted map anywhere downstream would
reintroduce the defect and the source read would still look right. Go randomises map iteration
order **per range statement and per process**, so 20 fresh processes are 20 independent seeds.
And mutant **D** shows the measurement can fail: remove the sort and the arm goes RED.
