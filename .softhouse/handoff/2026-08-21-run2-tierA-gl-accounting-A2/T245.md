## Should the attestation convention require the TENANT? (proposal only, no implementation)

**YES — and the tenant, not the database.** Argument, then enforcement.

**Why.** The database name is only a proxy. The tenant is what selects the timezone
(`Asia/Kolkata` vs `Asia/Ulaanbaatar`), the `c_configuration.rounding-mode` ordinal (6/HALF_EVEN vs
4/HALF_UP), and the `MoneyHelper` cache the arithmetic actually reads. A capture that names
`fineract_gerege` has told you where the rows live; a capture that names tenant `gerege` has told you
what arithmetic produced them. The registry join makes them 1:1 **today**, at this commit, on this
instance — that is a fact with a shelf life, not an identity.

**Why a convention alone is not enough.** F-2. The existing convention *is* "state the tenant", the
capture rig *does* state it, and the statement is a compile-time constant. A convention nothing checks
is the class this program has named four times (P-45).

**Proposed enforcement, in order of value. NOT IMPLEMENTED — this is a proposal.**

1. **Make it a graded, default-deny vector field.** Add a `Tenant` string field with JSON tag `tenant` to
   `OracleStamp` — `nexus/internal/apps/ledger/conformance/vector.go:193–202` — and grade it in
   `admit.go` **exactly the way `Seam` is already graded** at `admit.go:118–123`: an absent or unknown
   value **REFUSES** (default-deny, DEC-2 §4.10). Pin the permitted value in `PIN-ledger.json` as a new
   `tenant` field and check per-vector against it the way `oracle.fineract_commit` already is at
   `admit.go:54–56`. This is a shape the codebase already has twice; it is not new machinery.
   - **Cost is known and bounded:** both decoders run `DisallowUnknownFields`
     (`ledger/conformance/vector.go:620`, `loanschedule/conformance/vector.go:839`), so adding the field
     re-stamps the whole store in **one commit** — which `PIN-ledger.json`'s own `_note` already
     contemplates for the contract-digest case, in those words.
   - Do the same for `PIN.json` and the loanschedule `OracleStamp`, which today carries
     `threaded_mathcontext` / `ambient_mathcontext` but **no tenant**.
2. **Make the sidecar echo the variable.** `echo "$T"` instead of the literal, in a **new** `cap10.sh`
   — T114's standing ruling forbids editing a script that produced committed evidence. Without this,
   item 1 grades a field copied from a constant, and the enforcement is one level of indirection away
   from being real. **Item 1 without item 2 is cosmetic.**
3. **Put the tenant in the store pins.** Neither `.softhouse/vectors/PIN.json` nor
   `.softhouse/vectors/PIN-ledger.json` names a tenant **or** a database today [VERIFIED, `9b6c596`].
   They should carry `tenant` and `tenant_timezone`, because they are the artefacts that decide
   comparability, and two captures from different tenants are not comparable.
4. **The model already exists — copy it.** `.softhouse/capture/lib/attest_gate.py` takes a `tenant`
   argument, keys its pinned half-cent canary by tenant (`PINNED_CANARY_BY_TENANT`, gerege → product 11,
   default → product 10), and **refuses a tenant with no pinned tie rather than falling back to another
   tenant's request**. `.softhouse/capture/leapboundary/ATTESTATION.md:32–35` is the good template:
   `| Tenant | gerege | fineract_tenants.tenants |` plus timezone plus rounding mode plus the source of
   each. The **ledger** capture set (`capture/tierA-a2/`) has **no ATTESTATION document of that kind at
   all** — its `PROVENANCE-A2-15.txt` never says "tenant", and only `CAPTURE-PLAN.md` mentions `gerege`.

**Rejected alternative, recorded:** require the *database* instead, since it is what a DB read-back
actually touches. Rejected because it re-creates this exact defect one level down — `fineract_default`
tells a reader nothing about `+05:30` or `HALF_EVEN` unless they already know the registry, and the
registry is not in the vector store. Name the tenant; derive the database when you need it.
