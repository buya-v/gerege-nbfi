## The counterfactuals, and the blind spot these cells close

**That control is also the first-hand re-verification of the claim the whole route rests on:** *the Go
port reproduces family B cell for cell.* T159's follow-up 4 flagged that this had never been checked
outside T100's two demo cells. It is checked now, on a fresh capture, at n = 104 and n = 108.

**T64's six existing mutations are all invisible on the two family-B cells** (0 divergent cells each).
So I asked what defect these cells *do* discriminate — and **the port's own source names it**
[VERIFIED: `nexus/internal/apps/loanschedule/emi.go:1832-1842`]:

> *"THERE IS NO SPECIAL CASE THAT SETS THE FINAL ROW'S PRINCIPAL TO THE WHOLE REMAINING BALANCE. …
> **A port that special-cases the principal instead reproduces the same numbers on this corpus and is
> wrong in shape.**"*

That last sentence is a **standing admission of an ungraded blind spot**, true because every promoted
vector is a shape where the final-period EMI adjustment *succeeds* in settling the balance, so "the
last row settles whatever is left" (the amortization folk rule, and what every textbook writes) and
"the last row's principal is `emi − interest`" agree to the minor unit. **Family B is the first
observed shape where the adjustment does not settle the balance**, so it is the first shape on which
the two readings can be told apart at all.

`G8-FINAL-ROW-SETTLES-THE-BALANCE` (`src/T116-mutations.py`, T64's file untouched):

| `T116-FAMB-R600p0-N104-B1` | **4** | 1 minor unit |
| `T116-FAMB-R600p0-N108-B1` | **4** | 1 minor unit |

The four cells on N108: `period[107].interest_minor` (observed 0, counterfactual 1),
`period[108].interest_minor` (1 → 0), `period[108].principal_minor` (0 → 1),

region is at the rounding floor — MNT 0.01 is the smallest representable principal in MNT — so one

## Follow-ups

1. **`patterns.md` candidate — an EXEMPTION is a silenced check and must be printed with its reason,
   not counted.** Finding T116-N1. Until this fire the harness printed only an `exempt` count; the
   reason lived in JSON. The NOT-RUN section had this right since T58 and the rule simply had not
   been extended to the other way a check stops checking. **`report.go` now prints both, and the
   SUMMARY carries the exempt count on the line below `invariant violations`.**
2. **`patterns.md` candidate — a scoring routine that cannot say "UNRUN" will eventually say "RED".**
   My mutation script produced two confidently false verdicts from five arms that had all exited 2
   before the probe line. The cure is three lines: count the probe line, return a distinct code for
   "did not run", and abort if the control is not green. **This is P-62/P-64 reproducing itself
   inside a task that was briefed on P-62/P-64**, which is the strongest argument for making it
   mechanical rather than a habit.
3. **`patterns.md` candidate — T64's scratch-repo recipe is now stale and silently so.** Any future
   task copying `run-harness-mutations.sh` inherits the symlinked capture tree and the missing
   `git init`, and gets exit 2 on every arm. `run-harness-mutations-t116.sh` carries the fixed shape
   and explains why in a comment. Worth pointing at from `patterns.md` before a fourth task rediscovers it.
4. **The G-8 write-up in `gates.md` was NOT edited by T116** — deliberately, because it is the
   artefact a `user` gate reader weighs and rewriting it is not this task's mandate. It now
   **understates the corpus**: it records the family-B vector as *"Prepared and NOT promoted"* and the
   count as 42. **Somebody must reconcile it**, and the reconciliation should also carry T159's
   MNT 10.01-at-n-3000 figure (T159 follow-up 1), which is still the number that reaches Buyan.
5. **Family A still has no coverage and cannot get any by exemption.** The only routes are a port
   change (option c) or a documented refusal (option b), both hard `user` gates. Recorded so that a
   later task does not spend another fire discovering it.
6. **`ThrewOutcome` should be adopted by the shared harness builder, not per task.** T116 is the
   second consecutive task to re-derive the T169 handler by importing another task's builder. The
   third should not have to.
7. **`.softhouse/capture/lib/check_no_narrow_catch.py`'s FROZEN list is a decay surface.** It is
