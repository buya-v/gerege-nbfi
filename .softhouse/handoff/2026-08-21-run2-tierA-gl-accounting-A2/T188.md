## (B) pipefail sweep — count and every site

`conformance.sh` sets `set -u -o pipefail` at line **396** and **never sets `-e`**
[VERIFIED: `grep -n '^set ' .softhouse/conformance.sh` → one hit, line 396]. So an inverted
pipeline does not abort the script; it silently flips one `if`.

### The threshold, sized by me, not inherited

Binary search on this machine, producer = bash builtin `printf`, match on **line 1**:

| payload after the match | pipeline rc |
|---|---|
| 4 096 / 16 384 / 32 768 / 49 152 | **0** — no inversion |
| 65 536 / 131 072 / 320 935 | **141** — INVERTED |

**Largest non-inverting ≈ 64 768 B; smallest inverting ≈ 65 024 B — a 64 KiB pipe buffer.**
macOS exposes no `kern.ipc.*pipe*` sysctl to confirm it by declaration
[VERIFIED: `sysctl -a | grep kern.ipc.*pipe` → no output], so the number is the measured one.
I chose the sizes by bracketing that boundary rather than reusing 320 935 B; **36 KB fits the
buffer and reports the bug absent**, which is exactly the trap named in my brief, and my own
first bracket at 32 768 B reproduces that false negative.
[VERIFIED: transcript §B1]

A second condition matters and is not in the driver's write-up: **the consumer must be able to
stop before draining.** A 400 KB *single-line* JSON does **not** invert, because a
line-oriented `grep` must read the entire line before it can match. My first perl probe at
288 KB "passed" for exactly that reason. Producer output must exceed ~64 KiB **and** be
multi-line **and** carry the match inside roughly the first buffer-full.
[VERIFIED: `/tmp/t188_pipebuf.sh`, `/tmp/t188_perlprobe.sh`]
