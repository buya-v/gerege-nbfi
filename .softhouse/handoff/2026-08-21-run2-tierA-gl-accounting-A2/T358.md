`:(glob)` is applied — so the pathspec now means what it says — but the depth is **kept and

## 2. C-2 — the architectural one. **The argument, and the three alternatives I rejected.**

### The defect, restated precisely

Both remedies T323's guard printed — *call it from `run_guards`* and *add its row to the
DECLARATION TABLE* — are edits to `.softhouse/conformance.sh`, which this program **serialises to
one holder per batch**. So the task that trips the guard **cannot lawfully fix it**. That is not
hypothetical: `check-capture-namespace.sh`'s own header says wiring itself into the harness
*"would be the scope violation this program treats as a rejection"*, and that is exactly why
T299's guard sat unwired until T323 was granted the file.

T323's HARD argument — *"a guard whose remedy is 'say the thing the rule is asking for' is not a
blocker, it is the rule"* — is **sound for T299**, whose remedy is an `OWNER*.md` inside the
tripping task's own directory. It **does not transfer** to a guard whose only remedies live in
the serialised file. T337 is right about that and right that this is the real defect.

### THE CHOICE: keep it HARD, and change the REMEDY, not the severity

I added a third declaration direction, **`REACHED-BY`**, whose row lives **in the member's own
header**:

```
GUARDS-DIR-REGISTRATION: REACHED-BY <witness path, repo-relative>
```

and the guard then verifies, every graded run, that the witness

1. **exists**,
2. is **tracked** (an untracked witness is host state — absent from every commit, unreviewable),
3. is **not the member itself** (no self-certification), and
4. **names the member's basename**.

**The row's LOCATION moved; its burden of proof did not.** That is the same evidentiary standard
as the existing `CALLER` direction, whose token has always been the member's basename. And the
excuse now travels in the same diff as the file it excuses, which is a strictly smaller blast
radius than a table in `conformance.sh` where one task can excuse another task's file.

All four verification failures are driven red through the whole bar — arms 17, 18, 19, 20 — plus
arm 26 for an unreadable row. Without those five arms `REACHED-BY` would be a self-certification
hole, which is worse than the defect it repairs.

### What I rejected, and why

* **MAKE IT SOFT.** Rejected. The defect T323 existed to close is *three finished guards that
  reached nothing and nobody noticed for three fires*. A warning nobody must act on is that same
  non-event with a line of output. SOFT is also precisely what T299 rejected for its own guard,
  on the identical ground, and T337 endorses T299's HARD.
* **MOVE THE WHOLE REGISTRATION RECORD OUT** of `conformance.sh`, into a shared `.softhouse`
  registry file. Rejected on three counts. (1) It only **relocates the serialisation point** — a
  single shared registry becomes the next contended file, and we are back where we started one
  fire later. (2) It is a **suppression list**: it lets one task excuse a file it does not own,
  and it grows without the excuse ever appearing beside the thing excused. (3) It has a
  **bootstrap hole** — the registry would itself live in the guards tree, and nothing would guard
  the guard's own registry.
* **DROP THE DEPTH** (T337's one-token patch, applied alone) so fixtures cannot trip it.
  Rejected at §1: it makes the remedy problem go away by not looking, which is the larger F-3.
* **TIGHTEN `INVOKED` TO REQUIRE AN EXECUTED CALL** (T337 F-T337-4's second option). Rejected,
  and the reason is measured, not aesthetic: two of the three genuinely-invoked members are
  reached through `bash "$g"` after a `local g=` assignment, so an execution test needs dataflow
  this harness has no business growing, and both would go red on arrival. I corrected the
  **claim** instead — see C-3 below.

**Why HARD is still right once the remedy is in-grant.** A HARD guard whose only remedy is
forbidden is not a bar; it is a bar that gets switched off within two fires — which is the same
failure one level out, and the thing T323 was written to prevent. With `REACHED-BY` the remedy is
one line in a file the tripping task already owns, and that is the T299 shape T337 endorses.

## 4. FINDINGS OF MY OWN — three, and two of them are corrections to my brief

### F-T358-1 — MEDIUM, and it is a **fail-open I closed**: the DECLARATION TABLE could vouch for a member it does not declare

T323 matched DECLARED rows before the invocation test *"so that the table's own text cannot
satisfy the invocation test below and vouch for its own SUBJECT."* That protects the row's
subject only. **A row also names a WITNESS PATH**, and the invocation test is a substring match
over the comment-stripped file — so row 2's witness column,
`drive-red-ledger-invariants.sh|SUBJECT|.softhouse/guards/ledgerguard/main.go|ledgerguard`,
reports **`main.go` INVOKED**: one member absolved because a *different* member's excuse happens
to name it. Latent before T358 (`main.go` was not in the population); live the moment the
population widened to Go.

**Fixed:** the table's own rows are cut out of the haystack before the invocation test, with a
vacuity check if the cut leaves nothing. Nothing in the table is a call site, so nothing in the
table belongs in the haystack.

### F-T358-2 — MEDIUM, **a finding about the bar's own cost profile, not merely a bug I fixed**: a guard CAN spin the whole bar, and nothing short of a full run detects it

I first wrote the table-cut as pure parameter expansion, `code="${code//"$row"/}"`, reasoning
that no second process means no pipeline and therefore no P-57 EPIPE surface. **That reasoning
was right and the code was unusable.** Bash's pattern substitution over a ~200 KB string is
quadratic; the guard — advertised in `run_guards` at under a fifth of a second — sat at
**99.7 % CPU for 9 min 43 s** on two rows before I killed it. It was caught by running the
**whole bar** and by nothing else: the standalone reasoning was clean.

The delivered form is `grep -vF` over a **here-string** — a here-string is not a pipeline, so
the P-57 property the parameter expansion was chosen for is preserved, and `grep -v` consumes
all of its input anyway. Two rows, two greps, milliseconds.

**THE INTERESTING HALF IS THE DETECTION, NOT THE BUG.** Three things this program relies on all
failed to see it, and they are worth naming because the next author will lean on the same three:

1. **`bash -n` was clean.** A quadratic substitution is syntactically perfect.
2. **The standalone route was clean.** Lifting the function out and running it on a small tree
   returns instantly; the pathology is a function of the 200 KB haystack, which only the real
   `conformance.sh` supplies. This is T323's own thesis — *a guard that is green because the
   route never reaches it is exactly the defect you are fixing* — pointed back at T358, and I
   walked into it in the same file where T323 recorded walking into it.
3. **No guard in the bar measures the bar.** `run_guards` carries a hand-written cost comment
   per guard (`# … — 0.4 s`, `# … — 30.3 s`) and **nothing checks them**. A guard whose comment
   says 0.16 s and whose real cost is unbounded is not caught by anything; I caught it because
   a run I expected to take 75 s had not returned after ten minutes, which is a human noticing,
   not an instrument.

**A grading instrument nobody will wait for is a grading instrument that gets bypassed**, and
that is the same failure as switching the guard off — the exact shape T337's C-2 is about, one
level down. The cost figure in the header is now a *measured* 0.23 s (mean of 10 uncontended
iterations of every operation the function performs) rather than an estimate, and the episode is
recorded in the file beside the code that caused it.

**FOLLOW-UP I AM NOT DOING, NAMED RATHER THAN LEFT IMPLIED — FU-T358-1:** nothing in the bar
asserts a wall-clock ceiling, per guard or in total. A cheap version exists (record each guard's
elapsed time, refuse if the total exceeds a pinned bound) and it would have caught this in 75
seconds instead of ten minutes. It is a change to `run_guards` and belongs to whoever next holds
`conformance.sh`, with its own tier argument — a timing gate that fires on a loaded host is a
flaky bar, which is its own way of getting the bar bypassed.
