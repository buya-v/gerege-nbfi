## Changes Made

### 1. `.softhouse/capture/lib/check_wire_float_roundtrip.py` — NEW (272 lines)

T163's `audit-req-float-roundtrip.py` property, with the root **derived** instead of named.

**The property:** *every numeric token in every capture request body is byte-preserved under a
binary-double round trip.* That is exactly the P-25 defect T163 found in `resolve7.py` —
`json.load` with no `parse_float`, then `json.dumps` — which re-emits `repr(float)`. `1200000`
survives; `1200000.00` comes back `1200000.0`; `12345678901234567890.12` comes back
`1.2345678901234567e+19`, a residue of −890.12 on the way **to** the reference oracle.
`[VERIFIED: the guard's own selftest case (a), and T163's `prove-resolve8-float-red.py`]`

**The derivation, following T166's shape.** No rig is named. It walks `.softhouse/capture`
recursively and takes every `*.json` under **any directory named `req`, at any depth**, plus every
`*.req` (the wire-bytes artefact `cap8.sh` commits). T163's audit was rooted at `tierA-a2` and saw
**1 of the 6 rigs that carry request bodies** — 90 of 320 bodies. The derived walk sees all six.

**Detection is the parser, not a regex (P-48 rule 1).** `json.loads` calls `parse_int`/`parse_float`
with the original source text of each token. Selftest case (b) is the reason that matters: it plants
`"note": "1200000.00"` — a **string** — and requires the guard to pass. A regex would have refused it.
Line numbers are located afterwards, for the human only; the locate can return `?` without touching
the verdict.

**P-35 on three counts, not one.** Zero request bodies, zero rigs **or** zero `req/` directories is an
ERROR. A file count alone cannot tell a whole-tree walk from a single-directory walk — the exact
correction T166 made on the Go side with its package count.

**A file in the derived set the JSON parser rejects is a REFUSAL, not a skip.** Nothing goes into an
`except: continue` (the G-9 shape). A request body that is not a request body cannot be certified
clean, and it is named with its exact parser error.

### 3. `.softhouse/conformance.sh` — MODIFIED (+134 / −3)

- `load_toolchain` gains a **python3** check with the same D-2 shape as the existing perl check:
  absence exits 2. A `command -v python3 || return 0` would have turned "the interpreter is

- Two new HARD guards, `guard_no_float_in_capture_requests` and
  `guard_no_narrow_catch_in_capture_rigs`, sharing one `_run_capture_guard` body so a later fix to
  the missing-script or empty-output handling cannot be applied to one and forgotten on the other.
- **A missing guard script is an ERROR, not a skip.** `[ -f … ] || return 0` would mean deleting the

  enough if it can later be neutered silently; a guard that cannot be shown to refuse is worse than
  none, because it is believed (P-22). Both selftests are pure Python over temp directories — they
  never read the real tree, never contact the oracle, and cost under a second. Output is captured
