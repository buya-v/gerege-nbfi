## 2. THE FIX

Inside `check_census()`, immediately after the existing `^CENSUS |^NIL-COVERAGE ` filter loop and
gated on `[ "$rc" -eq 0 ]` (the PASS path — the only path missing the block; see §3), a second
extraction pulls the CANNOT-CATCH paragraph out of the same already-captured `$out` and re-prints
it through `say`, matching the existing lines' `ledger-invariants: ` prefix:

```bash
if [ "$rc" -eq 0 ]; then
  printf '%s\n' "$out" | LC_ALL=C awk '
    $0 ~ /^CANNOT-CATCH / { grab = 1 }
    grab {
      if ($0 !~ /^CANNOT-CATCH / && $0 !~ /^[ \t]/) { grab = 0; next }
      print
    }
  ' | while IFS= read -r line; do
    say "ledger-invariants: $line"
  done
fi
```

**Extracted structurally, not by content.** The block's first line is the only one starting
`CANNOT-CATCH `; every continuation line is indented (`  1. DYNAMIC SQL...`, `     builder's own
AST...`); the guard's next line after the block (`clean: ...` on a pass) is flush left. The awk
program grabs from the marker line through the last indented line and stops — it does not hunt
for any particular wording inside the block, so it survives future edits to the const's text as
long as that indentation convention holds. `[VERIFIED: /tmp/T209/after-standalone-v2.txt lines
16-48 == ledgerguard/main.go lines 733-765 sed -n range, both 33 lines]`.

**Runs to completion — no P-57 rule-1 violation.** The awk program has no `exit` statement; it
reads every line of `$out` to EOF and only toggles whether it prints. Combined with `set -u -o
pipefail` at the top of this file, an early-terminating consumer (`head`, `grep -q`) on this
pipeline would risk a SIGPIPE-driven nonzero pipeline status; this does not, by construction.

**Gated on `$rc -eq 0`, not unconditional — a correction made mid-task.** My first draft ran the
extraction unconditionally, before the existing `if [ "$rc" -ne 0 ]; then ... warn "$(... grep -av
'^CENSUS ')" ...` refusal block. That existing refusal block already dumps every non-CENSUS line
of `$out` — CANNOT-CATCH included — so on a refusal the block was never missing (T208 §3: the red
transcripts already carried it in full). An unconditional extraction printed it a **second** time
on every refusal (verified: two `CANNOT-CATCH — the honest limits...` lines in a red transcript,
one prefixed `ledger-invariants: `, one not). Gating on `$rc -eq 0` confines the fix to exactly the
hole T209 was opened for — the PASS path — and leaves the refusal path's existing behavior
untouched. `[VERIFIED]` both versions built and run; see §5.

## 6. Transcript cost, measured — chosen and stated, not taken silently

**Standalone head, PASS path:** 18 → 51 lines (+33, +183%).
**Full harness (`conformance.sh`), PASS path:** 198 → 231 lines (+33, +16.7% of the new total,
~14.3% of it).

T208 weighed the same trade at its own condensation (8 lines vs. the full 33, ~19% of a 198-line
transcript) and chose the condensation *for that file*, explicitly recommending the full block go
back at its source instead of growing a second copy (§2 above). I chose to print the **full**
block here, not a further condensation, for three reasons stated rather than assumed:

1. **A single source of truth.** The guard head is not conformance.sh's transcript; it is the
   thing whose own text tells the reader to go read this block. A condensed copy living in the
   head would be a *third* hand-maintained rendering of the same 33 lines (the const itself, plus
   conformance.sh's existing 8-line one) — more surface to drift, not less.
2. **The instruction that dispatched this task says so directly**: fix "at source in the guard
   head, not by growing T208's 8-line condensation... where the two copies would drift apart."
   Printing a *second* condensation at the head would be exactly that failure mode relocated.
3. **A limit nobody reads is not a limit** (the task's own framing). The load-bearing fact this
   block carries — renaming a balance defeats the detector's only surface, since there is no type
   checker behind it — is precisely the kind of claim that must not be summarized away by an
   agent's judgment call about which parts matter enough to keep.

**The known consequence, stated rather than hidden:** `conformance.sh`'s `guard_ledger_invariants`
still unconditionally prints its own 8-line condensation on every run (I did not touch it, per
the explicit instruction not to edit `.softhouse/conformance.sh`). After this fix, a green
`conformance.sh` transcript now carries **both** the full 33-line block (from the head, newly
surfaced) **and** the pre-existing 8-line condensation describing it — the condensation's own
comment ("the CANNOT-CATCH block does NOT [reach a green run]... FU-T208-1") is now stale, since
the block DOES reach it. This is a direct, foreseeable side effect of fixing the head while
`conformance.sh` is out of scope; whoever next holds `.softhouse/conformance.sh` should either
remove the now-redundant condensation or shrink it to a one-line pointer at the head. I did not
do this myself — it is a `.softhouse/conformance.sh` edit and the task explicitly forbids it
("a conflicting diff will be rejected on the scope check").
