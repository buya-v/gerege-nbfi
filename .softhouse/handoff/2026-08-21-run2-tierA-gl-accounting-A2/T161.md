## Changes Made

### 1. The fix — `.softhouse/capture/pathb/t80/prove-f1.sh`

Pre-fix: blob `06e6dd756effe16144348ec7c207d24031217404`, sha256
`c8d192b91ae43fb6318e3d36db3eed82e59e23409531ac5d0e76f23d8a63663f`, 4,620 bytes,
`grep -c '^[[:space:]]*trap '` → **0**.
Post-fix: sha256 `b7c206712147f550e0f3a191c5440ce76af1b87366efbbc827fd482285970c44`,
18,792 bytes, `grep -c '^[[:space:]]*trap '` → **7** (6 of them unindented statements, one
is the handler's own `trap - …` de-arm). [VERIFIED: both counted this fire]

It is **T156's shape, not a second idiom** — the same helper names, the same
census-and-refuse discipline, the same start-up-recovery placement as
`t149/prove-redgreen.sh`:

* **`trap f1_guard_exit EXIT`**, plus `INT`, `TERM`, `HUP`, `QUIT` and `PIPE`, each of
  which `exit`s with the conventional `128+signo` so the EXIT handler runs. A signal trap
  that *returned* would resume the proof with pre-fix bytes on disk.
  * **EXIT is not decoration here.** The script carries no `set -e`, so before this fix an
    ordinary non-zero exit inside the window stranded the rig exactly as a signal did —
    driven separately as the `exitfail` case below.
  * **`QUIT` — the decision the task asked for, and the reason.** The task's list stopped
    at HUP, and the sibling `SIGQUIT` defect in `t149/prove-redgreen.sh` belongs to
    **T168**, whose files I have not touched. I **cover QUIT here**: it is catchable, it is
    produced by one keystroke (Ctrl-\\) at the same terminal that produces SIGINT, and the
    state it strands is byte-for-byte the state SIGINT strands — the only thing
    distinguishing the two holes would be which key the operator hit. Driven red/green
    like the rest.
  * **`PIPE` — added, and it is not hypothetical.** `sh prove-f1.sh | head` closes the pipe
    mid-run and kills the script inside the window. Reading a proof's output through `head`
    must not downgrade the attester it is proving. Driven red/green. (I piped this very
    script into `tail` while investigating; `head` would have corrupted my scratch tree.)
* **The restore is VERIFIED, not assumed.** `f1_restore_attester` re-hashes the file after
  writing and fails if the bytes are not the ones asked for — `git cat-file` and `mv` are
  not credited because they printed nothing. The evidence set is then re-censused: sha256
  of every regular file under `t36/out/emiloop`, compared against a census taken before the
  window opened and held in a **shell variable** as well as a file, so the handler still
  works if `out/` disappeared underneath it. **An empty census is a refusal, never a
  silently-satisfied comparison** (P-40).
* **Idempotent by construction.** `f1_restore_attester` returns success immediately if the
  file already hashes to the wanted digest; `f1_clean_evidence` removes the stamp only if
  present and runs `git checkout` only if `git status --porcelain` is non-empty. Both are
  called from start-up recovery, from mid-run, and again from the EXIT handler; running
  the restore twice is a no-op. [VERIFIED: case C of `F1-recovery-startup-branches.txt`]
* **START-UP RECOVERY for SIGKILL**, which no trap can catch. An in-flight marker
  `t80/.f1-swap-in-progress` is written **before** the traps are armed and **before** the
  overwrite, because the only state that cannot be recovered is one that was never
  recorded. On entry, a marker left by a dead run is validated (hex shape, blob present in
  the object store, blob's bytes hash to the recorded digest) and the attester, the stamp
  and the evidence set are repaired **before the BEFORE census is taken** — a census over
  a corrupted set would enshrine the corruption as the baseline and the proof would then
  "pass" against it.
* **The restore source is an IMMUTABLE GIT BLOB, not a dotfile in the output directory.**
  The old `cp "$W/t36/attest.py" "$O/.f1-fixed"` put the only copy of the live attester
  inside `t80/out/` — a `rm -rf out/` would take it, and *that backup was itself part of
  the defect*. It is gone. The script now pins the live attester's bytes into git's object
  store: the index blob when the working tree matches it (no new object created — the
  ordinary case), else `git hash-object -w` so a **locally modified** attester is preserved
  exactly rather than silently reverted to the index. The pin is verified by digest before
  the window opens, and the marker holds a *pointer* into the object store, never bytes.
* **The stamp and the evidence set are cleaned on every path too.** Restoring the attester
  while leaving a forged-looking `CAPTURED-FROM-TENANT` behind is a half fix, so
  `f1_clean_evidence` runs wherever `f1_restore_attester` runs.
* **The attester is backgrounded and `wait`ed** instead of run in the foreground. A shell
  defers a trapped signal until the current *foreground* child finishes, so a `kill`
  arriving while `attest.py` ran would not restore the rig until the attester chose to end.
  Measured below: **8.8 s of deferral** on this host, and unbounded if a `docker exec`
  hangs. `st1` keeps exactly the old foreground semantics — `wait` yields the child's
  status. The handler also `kill -TERM`s a still-live attester before cleaning, so it
  cannot re-create the stamp after the cleanup.
* **P-24 on the bytes under test.** `PREFIX_COMMIT=813acb1` was already an immutable commit,
  but the script now also pins the pre-fix attester's blob
  `8e9f865ba6e9f8841c9be81962770e3c818fe53f` / sha256 `c56825ad…` and **refuses to run** if
  `git show` hands it anything else — a proof should be able to say which bytes it tested.

### 2. The prover — `.softhouse/capture/pathb/t80/prove-f1-recovery.py` (new)

Drives the defect red against the **real pre-fix bytes** and green against the fix.

* Pre-fix bytes come from the **immutable git object** `06e6dd75…`, read with

  moving ref (`main:`, `merge-base`) appears anywhere — that is the P-24 relocation trap.
* **Nothing destructive touches the real rig.** Every case runs inside a throwaway

  cases. Every write in the file targets the sandbox path; `REPO` is only ever *read*
  (`git cat-file`, `git clone`, `open(..., "rb")`). [VERIFIED: grep over the file]
* **The interruption is delivered from inside the window.** The sandbox's `t36/sha256.sh`

  `diff` shell function. The first `diff` in `prove-f1.sh` is the BEFORE/AFTER-prefix

* **Positive controls on the inputs themselves**: refuses if pre == post, if the pinned
  pre-fix bytes already contain a `trap`, or if the fixed bytes contain none. A prover that
  ran the same bytes twice would report a perfect fix and mean nothing.

## SIGKILL start-up recovery

SIGKILL runs no handler, and no trap can change that. Both byte-sets are therefore stranded
by it; the claim under test is what the **next invocation** does.

* **POST-FIX.** The killed run leaves the marker on disk. The next invocation prints, before
  doing anything else:

  ```
  RECOVERED: an earlier run died mid-swap and left .softhouse/capture/pathb/t36/attest.py
  at c56825ad…; restored to 567e4cf0… from blob 9e38fe5e273c959a004423faa7e612f0240f51bc
  ```

  and then removes the stamp, restores `out/emiloop` from git, and **runs the proof to a
  clean exit 0**. On entry: `attest.py=PRE-FIX stamp=PRESENT emiloop=MUTATED marker=left`.
  After: `attest.py=live stamp=absent emiloop=clean marker=gone`. [VERIFIED:
  `F1-recovery-redgreen.txt`, "POST-FIX start-up recovery"]

* **PRE-FIX — and this is worse than "no recovery".** Re-running the pre-fix script over
  the tree it wrecked leaves it wrecked (`exit=1`, still `attest.py=PRE-FIX`, stamp still
  present). The mechanism is the dotfile backup: `:45` `cp "$W/t36/attest.py" "$O/.f1-fixed"`
  **backs up the already-downgraded file** and `:65` restores *that* at the end. The
  downgrade is not merely un-repaired, it is **promoted to the new baseline by every
  subsequent run** — including the `BEFORE` census the proof grades itself against.
  [VERIFIED: `F1-recovery-redgreen.txt`, "PRE-FIX the same start-up state"]
