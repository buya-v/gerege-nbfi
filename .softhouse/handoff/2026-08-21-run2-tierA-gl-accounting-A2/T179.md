## Changes Made

**One new directory. No existing script, rig, vector, ADR or contract was modified.** The only
edit outside my own directory is an append to `.softhouse/patterns.md` between the existing
markers (P-53, P-54), which I own this fire.

`guard_classify.py` answers a different question from T156's. T156 asked *"does the word `trap`
appear in this file?"*; this asks *"is a guard NODE reachable from THIS mutation call?"*

1. **Guards are AST nodes on the mutation's own ancestor chain.** `GUARDED-FINALLY` = an
   enclosing `ast.Try` that has a `finalbody` and whose `finalbody` does not itself contain the
   site. `GUARDED-CONTEXTMANAGER` = an enclosing `with` whose context manager is
   `contextlib.ExitStack` or a *locally defined* restoring CM (a `@contextmanager` generator
   containing a `try/finally`, or a class defining `__exit__`). `GUARDED-FINALLY-INDIRECT` = the
   one interprocedural step taken: every in-file call of the enclosing function is inside a
   `try/finally` (a single unguarded call site disqualifies it). `GUARDED-PROCESS` = an
   `atexit.register` / `signal.signal` call proven reachable from module execution — a **weaker,
   separately named** verdict, because the tool proves a handler is *registered*, never that it
   restores this artefact.
2. **`ATOMIC` is a first-class verdict** (P-48 rule 4): `os.replace` / `Path.replace` of a
   temp-derived source needs no handler at all and is not reported as a defect.
3. **The target is read off the mutating call's own argument expression**, resolved through
   module constants, `os.path.join`, f-string fragments and partial literal fragments — never off
   whole-file text. Unresolvable targets go to a `UNKNOWN` scope that is **printed**, not dropped.
4. **Sandbox detection is per-site and transitive.** `mkdtemp()` / `TemporaryDirectory()` / a
   `"/tmp/…"` literal binds a scratch name, and scratch-ness propagates through assignments to a
   fixpoint. This matters here because **this repo's sandboxes mirror the repo layout**:
   `capture/lib/check_no_narrow_catch.py` builds `<tmp>/.softhouse/capture/newrig/src/` in its own
   selftest, and it was scored TRUSTED until `with … as tmp` bindings were propagated
   [VERIFIED: the site disappears from `trusted-unguarded-sites-main.txt` after the change].
5. **Shell is refused, not guessed** — see the next section but one.
6. **The tool passes its own measurement.** Its single write (`--json`) is `mkstemp` + `fsync` +
   `os.replace`, so `guard_classify.py`'s own verdict on itself is `ATOMIC`, not `UNGUARDED`
   [VERIFIED: `worktree-sweep-output.txt`, UNKNOWN/ATOMIC = 2, and the file is absent from the
   unguarded list while present in the P-48 detector list with 40 guard words in literals — i.e.
   **T156's regex would score my classifier GUARDED on its own docstring too**].

Exit codes: `0` report / clean, `1` `--enforce` with an unguarded TRUSTED site, `2` usage,
`3` **zero files inspected — an error, not a pass** (P-35) [VERIFIED: `--root` on an empty
directory returns 3].

## The regex-engine divergence, demonstrated

`engine_divergence.py` lifts T156's `GUARD` pattern out of its source with `ast` (never retyped)
and runs it over `bf67a85:.softhouse/reviews/t47-probe/t47_edit_1.py` — 13,267 immutable bytes,
pinned by commit, never via `main:` (P-24):

| engine | matches | verdict it implies |
|---|---|---|
| Python `re` (T156's own) | **3** | GUARDED |
| `/usr/bin/grep -E` | **0** | UNGUARDED |
| shell `grep -E` (resolves to `/usr/bin/grep` here) | **0** | UNGUARDED |
| `/usr/bin/awk` | **0** | UNGUARDED |
| `/usr/bin/sed -nE` | **0** | UNGUARDED |

**Two independent incompatibilities, separated by measurement rather than asserted:**

1. **`[^#\n]`.** Python honours the `\n` escape inside a bracket expression (*not `#`, not
   newline*); POSIX ERE has no escapes there, so it reads *not `#`, not backslash, not the letter
   `n`*. The anchored `[^#\n]*` cannot cross a letter `n`, and every `trap` in the corpus sits
   after one (`One trap worth …`). Isolated on two one-line inputs:

   | input | Python `re` | `grep -E` | `awk` |
   |---|---|---|---|
   | `a trap here` (no `n` before `trap`) | 1 | **1** | 0 |
   | `One trap worth naming` (an `n` before `trap`) | 1 | **0** | 0 |

2. **`\b`.** `awk` scores 0 *even on the line with no letter `n`*, so awk's zero has a different
   cause: `\b` is not a word boundary in POSIX ERE. One pattern text, two engine-specific
   readings, three behaviours.

The script **fails (exit 1) if every engine agrees** — a demonstration that cannot fail is P-22.
Recorded as **P-53**.

Consequence, stated plainly: T156's committed population is *the Python-`re` answer*. The same
sweep expressed as a shell one-liner — the form a follow-up would naturally reach for — returns a
different population, silently.

## Unverified

- **[UNVERIFIED] The 250 shell files.** I did not classify a single one, in either direction. The
  absence of a shell file from any list here is a refusal, never a clean bill. `bashlex` is not
  installed (checked at import; printed in every run header) and `shlex` is a tokeniser, not a
  parser — it cannot see reachability, here-docs, subshells or uncalled functions.
- **[UNVERIFIED] 37 of the 43 flagged Python files.** I hand-read 6 (5 true, 1 false-and-fixed).
  The rest are the tool's word.
- **[UNVERIFIED] Whether `GUARDED-PROCESS` handlers actually restore anything.** The tool proves
  registration and reachability only. No file in this repo currently hits that verdict, so nothing
  rests on it today.
- **[UNVERIFIED] Ordering of a registration relative to a mutation.** Static analysis cannot
  decide it; a handler registered *after* the mutation would still be reported as live.
- **[UNVERIFIED] Cross-file mutations.** A helper in another module that does the writing is
  invisible. So is anything invoked through `exec`, `importlib`, or a subprocess whose argv is
  assembled at runtime.
- **[UNVERIFIED] Name-based scope resolution can mis-attribute.** The constant/scratch maps are
  keyed by name and are not scope-aware (first assignment wins, scratch-ness unions). A name reused
  for a sandbox path in one function and a real path in another resolves to **one** answer for
  both. This can hide a true positive as well as create a false one; every site prints its target
  expression so a reader can overrule it.
- **[UNVERIFIED] Nothing about Fineract, money math, vectors or the oracle was touched or claimed
  by this task.** No vector was read, captured or promoted; the oracle was not contacted.
