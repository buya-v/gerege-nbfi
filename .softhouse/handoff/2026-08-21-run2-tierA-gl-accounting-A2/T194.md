## Changes Made

All three changes are inside `_run_capture_guard` and its two callers.

**1. The census head now reads the FIGURE, not the line count.**
`census_lines` (count of lines matching `^CENSUS `) is retained as the presence test — it is
correct and T191 repaired its EPIPE hazard — and a *second* test is added after it that extracts
the integer following `inspected ` out of the census line with

```
ins_all="$(printf '%s\n' "$out" | LC_ALL=C sed -n 's/^CENSUS .*inspected \([0-9][0-9]*\).*$/\1/p')"
inspected="${ins_all%%$'\n'*}"
case "$inspected" in ''|*[!0-9]*) inspected=-1 ;; esac
```

and refuses unless `inspected >= floor`, with `floor` derived by the caller. A census line with no
`inspected <N>` in it (which is what the stub `CENSUS 0 files / 0 dirs` is) yields `-1` and is
refused. Exactly one line per guard matches the extraction — measured, both guards, below.

**2. `_run_capture_guard` now takes a mandatory third argument, the population floor.**
`local script=... label="$2" floor="${3:-}"`. An unset or non-numeric floor, or a floor `< 1`, is
itself an ERROR — a floor of zero would readmit the vacuous pass the test exists to refuse, and a
future third guard cannot be wired up without measuring its population. Driven RED (below).

**3. The selftest head now requires BOTH POLARITIES, not a nonzero line count.**
`cases` is kept for the human-readable line; the *gate* is now `red >= 1 && green >= 1` where
`red` counts `^  -> exit [1-9]` and `green` counts `^  -> exit 0$`. This checks the claim the say
line has always *printed* — "drives it RED on a planted defect and GREEN on the clean equivalent"
— and which nothing checked. It is deliberately **not** a floor on the count: a number there
would go stale the day a case is added or retired.

The output line changed from `selftest OK, N cases (each drives it RED ... and GREEN ...)` to
`selftest OK, N cases (R drive it RED ..., G stay GREEN ...; both directions READ)`, and a new
line `census figure READ: inspected N >= F tracked by git (floor DERIVED, not pinned)` is printed
after the census lines so a reader can see the comparison that was made.

**Diff locality for T192/T193/T195:** the whole change is three contiguous hunks inside
`_run_capture_guard` plus one hunk in each of the two `guard_no_*_in_capture_*` wrappers. Nothing
outside lines ~749–950 is touched; no shared helper, no verdict code, no vector code.

## Why this floor is derived and not hard-coded

A literal (`-lt 300`) would be a second silent pass wearing the costume of a check: it is true on
the day it is written and nothing tells the next reader the day it stops being true. Each caller
therefore measures its own population with **`git ls-files` — a different program from the guard's
`os.walk`, over the same set**:

- **wire-float**: the guard's `derive()` takes every `*.json` whose DIRECT parent directory is
  named `req`, plus every `*.req`, at any depth under `.softhouse/capture`
  [VERIFIED: `.softhouse/capture/lib/check_wire_float_roundtrip.py:78-102`]. Floor:
  `git ls-files -z -- .softhouse/capture | tr '\0' '\n' | grep -acE '(/req/[^/]+\.json|\.req)$'`.
  Measured: guard **320**, floor **320**.
- **narrow-catch**: every `*.java` in the repository except the `.claude/worktrees` checkout root
  the lint excludes and names [VERIFIED: `.softhouse/capture/lib/check_no_narrow_catch.py:104-136`].
  Floor: `git ls-files -z -- '*.java' | tr '\0' '\n' | grep -av '^\.claude/worktrees/' | grep -ac '\.java$'`.
  Measured: guard **57**, floor **57**, and a filesystem `find` with the guard's own prune set also
  **57**.

Because the floor is read from the index, it moves with the corpus by construction: add a capture
rig and both numbers rise together; retire one and both fall together. There is no number in the
harness to update, and no number that can go stale.

Two drift risks were checked rather than assumed:
- **Tracked files under a directory the guard prunes** (`build`, `node_modules`, `.gradle`) would
  push the floor above what the walk can reach and cry wolf. Measured: **0** such tracked `*.java`
  and **0** such tracked files under `.softhouse/capture`.
- **`.claude/worktrees` being counted by git but excluded by the lint.** `.claude/worktrees/` is
  in `.gitignore`, so `git ls-files` never lists one — measured **0** tracked `*.java` under it.
  The explicit filter is belt-and-braces and is commented as such, so that un-ignoring those trees
  could not silently push the floor above what the lint will walk.

## The alternative I rejected and what it would still catch

**Rejected: hashing the guard scripts** (T184's own alternative, resting on T173's FU-3 that
nothing hashes the Python).

Why I rejected it as the *primary* fix:

1. **It answers a different question.** Hashing asks "are these the bytes we blessed?" The defect
   class that has actually bitten this program is not byte-substitution — it is a *real, honest*
   guard whose inspected population silently collapses: T163's audit that opened one rig out of
   six while printing a healthy-looking number, and 7,018 lines of money code that were passed by
   never being looked at. A digest is GREEN for all of those, because the bytes are the blessed
   bytes and the walk is simply reaching less than the author thought. The census floor catches
   that class; hashing cannot.
2. **A pinned digest is the hard-coded-floor trap in another costume**, on the exact axis this
   task warns about. It must be updated by hand every time a guard is legitimately improved, and
   the update is done by the same worker whose change is being pinned. The failure mode is
   habituation: a red digest becomes "oh, T-whatever edited the guard, bump it", and the day it
   matters it gets bumped too.
3. **A digest against `HEAD` instead of a literal** (the tempting no-stale variant) only catches
   *uncommitted* tampering. A stub committed to a branch — which is how every worker in this
   pipeline ships — passes it, and it fires spuriously on every legitimate in-progress edit.

**What hashing would still catch that mine does not, stated plainly:** a stub that fabricates
figures at or above the derived floor. Stub B in the RED evidence above is exactly that stub — it
prints `inspected 57`, the true number, and my census gate accepts it; only the selftest-polarity
gate refuses it, and a slightly better stub printing one `-> exit 1` and one `-> exit 0` would
pass BOTH of my gates. Any output-parsing check is defeatable by a sufficiently faithful
impersonator; pinning the bytes is what closes that, and it is recorded as a follow-up rather than
claimed as done. What my fix buys against that adversary is that the impersonation is no longer
*cheap* — the stub must now know the true corpus size and reproduce both selftest polarities,
which is strictly more than "print a line and exit 0".

I did not implement both because the task asks for a tight, localised diff that T192/T193/T195
rebase over, and because a half-implemented hash gate (a pin nobody enforces on the day it moves)
would be a third silent pass. The follow-up below specifies the version worth building: not a
digest at all, but the harness planting its own defect and requiring the guard to refuse it, which
no impersonator can fake without doing the work.
