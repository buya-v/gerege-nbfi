## Findings

- **F-A (MICRO-FIX, required).** `LedgerError.ApplicableSlotName` does **not** carry "the enum
  that actually applies". `resolveProductAccount` holds the typed `slot` and discards it,
  passing only the bare `code`; `mappingNotFound` then re-derives, so `applicable == rendered`
  unconditionally. **Measured over all 48 (code, family) pairs:** on a **cash** product at codes
  22/24/25 the field reports the **accrual** name — it duplicates the oracle's wrong rendering
  instead of correcting it. No test reads it. Not a parity defect (never on the wire), but it
  defeats the exact mitigation A2-8 offered for its deliberate deviation. 4-line fix given in
  the review; `rendered` must not change (it is graded).
- **F-B (the answer to "hunt for a claim that should have been `[UNVERIFIED]`").**
  `glaccount.go:251-254` states SQL `SUBSTRING` with a negative length "yields the empty
  string". **PostgreSQL raises `ERROR: negative substring length not allowed`** — I ran it on
  the live `fineract-db-1`. Unreachable in practice (every hierarchy the oracle writes has at
  least one dot), but it is a confident, refutable claim presented as a verified reproduction.
  The rest of `NameDecorated` is correct: 40-char pad both sides, zero-length → bare name,
  saturation at 40 — all three verified against Postgres.
- **F-C.** *"All 27 JSON `amount` fields"* (`money.go:26` and the handoff) is not reproducible;
  I measure **52** across 147 files, 0 under `req/`. The substantive claim is TRUE and I
  verified it more strongly. Only the count is wrong, and it sits in committed code under a
  `[VERIFIED:]` marker.
- **F-D.** The handoff and `f50e006`'s commit message both attribute the null-vs-absent
  correction to `f50e006`. That commit is gofmt whitespace + a new test file + a comment block.
  **The correction was already complete in `5d80a72`**, the first commit. Code right, story
  wrong.
- **F-E (widens the driver's T166).** Both in-package scans use `os.ReadDir(".")` and skip
  directories. I drove it: a `float64` in `nexus/internal/apps/ledger/sub/` passes the package
  test **and** `conformance.sh`. **T166 must widen to a recursive walk of `internal/apps`, and
  must be driven red against a float planted in a SUBDIRECTORY**, or it will inherit the same
  blind spot.
- **F-F.** The cross-family scan catches the direct conversion and the `.Code()` form; it
  misses conversion via an intermediate variable and from a bare `int32`. A2-8 states the limit
  honestly; this is the enumeration.
- **F-G (cosmetic).** *"18 files: 9 source, 8 test, 1 doc"* — actual **10 source, 7 test,
  1 doc**. Total and insertions correct.
- **F-H (rig hygiene, not A2-8's).** `req/disburse-086-nopaymenttype.json` is used by no
  capture; `A2-086`'s `.http` names `disburse-084-paymenttype1.json`. A reader matching by
  number would model the duplicate-row 403 as a null-payment-type case and mis-derive the whole
  `NullPaymentTypePolicy` question. `CAPTURE-PLAN.md` should delete it or say why it exists.
