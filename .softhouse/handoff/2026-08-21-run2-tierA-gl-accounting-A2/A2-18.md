## 2. The detection surface, derived from DEC-2 §4.4 / §4.4.1

I did not invent the target. The two rows and the four bullets below are the whole brief.

**§4.4, the table rows, quoted:**

- **I-3** — *"Balances are DERIVED, never written"*; checkable statement: *"No write path to any
  balance column exists in the Go tree"*; *"Gradeable only by a source-level guard over the Go
  tree."* And the oracle is explicitly **not** a positive example: `m_trial_balance.closing_balance`
  is *"a written, stored, unsigned sum wearing a balance's name"*, deliberately not ported (§7).
- **I-4** — *"The ledger is append-only"*; checkable statement: *"No `UPDATE`/`DELETE` against
  `acc_gl_journal_entry` from application code"*; *"'No update ever happened' is not observable
  from a capture."*

**§4.4.1, the four things nothing looks for, quoted:**

1. *a write path to any balance column (that is I-3);*
2. *an `UPDATE` or `DELETE` statement against `acc_gl_journal_entry`, or any Go call that would
   emit one (that is I-4);*
3. *a derived-balance function that caches instead of deriving;*
4. *a correction path that mutates a leg instead of adding a reversing pair (that is I-5).*

Plus CLAUDE.md's own wording, which adds the hold clause DEC-2 files as I-6 and puts out of the
*contract* domain — but the guard is a guard over the Go tree, not over DEC-2's contract domain,
and the non-negotiable is repo-wide: *"Holds are postings and alter `available` only, never
posted `balance`."*

That maps onto **eight classes**, each traced to the sentence that demanded it:

| class | fires on | traces to |
|---|---|---|
| `I3-FIELD-WRITE` | assignment or `++`/`--` whose LHS is a **field**, **dereference** or **index** whose name matches `(?i)balance` | §4.4.1 bullet 1, "a write path to any balance column" |

**Three deliberate non-detections, each argued rather than omitted.**

- **`INSERT` into `acc_gl_journal_entry` is NOT flagged, and that absence IS append-only.**
  Appending is the correct and required behaviour. A guard that refused the only lawful write
  would be refused itself on its first run. `mutatingVerbRe` therefore omits `insert`, and
  `upsertRe` catches `ON CONFLICT … DO UPDATE` separately because that mutates a committed row.
- **A bare identifier on the LHS is NOT a write target.** `balance += leg.Amount` in a summation
  loop is *exactly how a derived balance is written* —
  `nexus/internal/apps/ledger/money.go:215-233` `DoubleEntryBalances` sums into bare
  `debit, credit`. Flagging it would refuse the only correct implementation. A **field**, a
  **dereference** and an **index** are targets, because each stores into something that outlives
  the expression. Residual, fail-CLOSED: a *local* struct used as an accumulator
  (`acc.Balance += x`) is flagged; the fix is a bare accumulator, which the tree already uses.
- **A composite literal `View{Balance: derive(legs)}` is NOT flagged.** It is a return value,
  not a store. Selftest case (k) asserts this stays true.

## 7. WHAT THE GUARD CANNOT CATCH

Printed by the guard on **every** run, pass or fail, so it can never be quoted without its
limits. Verbatim summary:

1. **Dynamic SQL.** A statement assembled at run time is not readable as text. The guard
   converts that blind spot into a **refusal** for the mutating driver family (`OPAQUE-SQL`) —
   but only where it recognises the call. A mutating call through an interface method it does
   not name, or through reflection, is invisible.
2. **Indirection through a name that is not a balance.** A field called `Amount`, `Total`, `Net`
   or `Position` that *is* a stored balance is not detected: the surface is the **name**,
   because without a type checker there is nothing else to key on. **Renaming a balance defeats
   this guard.**
3. **Stored procedures, triggers and migrations.** The guard walks Go only. An `UPDATE` inside a
   Liquibase changelog, a Postgres trigger or a hand-run `psql` script is out of reach — and the
   schema is Fineract's, which *has* such objects.
4. **I-5.** "A correction that mutates a leg instead of adding a reversing pair" is only
   decidable once a leg type and a correction path exist in the Go tree; neither does. The
   mechanical half (a write to a committed row, a write to a balance) is covered; the semantic
   half is **not**, and is not claimed.
5. **Semantics of derivation.** A struct-field cache inside a service object with a non-balance
   name is not detected. Only the package-level case (`I3-PKG-STATE`) is.
6. **Non-Go callers.** Anything reaching the database without going through this module.
7. **The two over-matches in §5.**
8. **Tests are inspected, not exempted.** A `_test.go` that assigns a balance field as a
   *fixture* is reported. Fail-CLOSED by choice; the fix is a constructor, not an exemption.

Two more limits that belong here rather than in the program's output:

9. **The protected-table pattern is a NAME pattern** (`…journal_entr(y|ies)…`). A journal table
   renamed to something without those characters escapes `I4-DML`. `I4-BUILDER`'s Go-name
   pattern has the same shape.
10. **Nothing here grades money.** DEC-2 §4.4 I-1/I-2 (debits = credits, splits sum to whole) are
    *vector* questions and remain ungradeable for the reasons DEC-2 §5 gives. This guard does not
    touch them and must never be cited as though it did.

  functions are not exported to a child, so a script never sees the session's `grep`). Typed
  into the Claude Code Bash tool, `grep` is a shell function re-execing as **ugrep with `-I`**.
  Every load-bearing invocation in both scripts carries **`LC_ALL=C`** (defeats BSD grep going

  whole file). Neither token defeats both programs; both are kept.
- `sed` is `/usr/bin/sed` (BSD). It consumes all input and never exits early, so the census
  parse adds no member of the `| grep -q` / `| head` EPIPE family (**P-57 rule 1** — neither
  appears anywhere in the two scripts under `pipefail`).
- `go` is `go1.26.6 darwin/arm64` from `.softhouse/toolchain/go` via `.softhouse/bin/go-env.sh`.
  The guard module declares `go 1.23`.
- Input shapes: the guard's input is UTF-8 Go source under `nexus/` (44 tracked files); the
  head's input is the guard's own stdout, ASCII plus the `—` em dash in the census line, which
