## THE DRIVER'S QUESTION — does leg 3 close the **deflated** direction?

**No. It closes inflation only. The driver's reading is correct.** Measured on the merged tree:

| store | exit | parity | cells | verdict |
|---|---|---|---|---|
| intact | 0 | 43 | 5664 | PASS |
| **one parity vector removed** | **0** | **42** | **5533** | **PASS — no warning anywhere** |
| **five parity vectors removed** | **0** | **38** | **5345** | **PASS — no warning anywhere** |
| whole context removed | 2 | 0 | 21 | UNUSABLE — corpus collapsed, not counted |
| one extra unloaded `.json` | 2 | 0 | 0 | UNUSABLE — census names it |

*(T156 reports `42 / 5576`; I get `42 / 5533` because I deleted a different victim — `P-01`, worth 131
cells, vs the T149 vector's 88. Direction and silence identical; the cell count is a function of
which vector is deleted.)*

**Which lines make it structural.** `StoreFileCensus(storeRoot string, loaded []*Vector,
accountedErrs []LoadError)` takes only **what is**, never what *ought* to be; `seenJSON++` and every
`problems = append(…)` sit inside the `filepath.WalkDir` callback, so it can only speak about files it
**found** — its own error text says *"N .json files were found … and M of them are unaccounted for."*
A deleted file is walked by nothing and both enumerators agree it is absent, so the census is
satisfied. `CaseIDIntegrity(vectors []*Vector)` has the same shape: it sees ids that collide, never
an id that is missing. **Nothing else supplies the missing side** — `PIN.json` has no expected corpus
size or id set, and `conformance.sh` has no `expected_vector`/`manifest`/`corpus_size` notion
[VERIFIED: grep empty].

**Not grounds to reject T154.** Its brief asked for a census that *"REFUSES any `.json` under the
store root the harness did not load"* — inflation by construction. It delivered exactly that, well.
Deflation is a separate pre-existing hole T154 neither opened nor was asked to close.

**Scoping the driver's new task** — a committed manifest of expected `case_id`s is the right shape,
and it is the only artefact that can distinguish *"complete"* from *"self-consistent"*. Three
constraints, each this same trap in a new costume: (1) it must **never be regenerated from the
store**, or it is a tautology that passes by construction; (2) a missing or empty manifest must be an
**ERROR**, and the check must report the count it compared, or the vacuity just moves up a level;
(3) it must **not be deletable in the same edit as the vector** — `PIN.json` is a natural home, being
already on the census allowlist and already float-checked by `LoadPin`.
