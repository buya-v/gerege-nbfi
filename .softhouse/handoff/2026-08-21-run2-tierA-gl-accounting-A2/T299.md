## Changes Made

### Item 2 — `50-failopen-lint.py` never writes over a tracked path again

**`.softhouse/capture/t238-failopen/instruments/50-failopen-lint.py`** — added `import
tempfile` and a `_dest_is_tracked()` gate before the `json.dump`. If the resolved destination
is git-tracked, the JSON goes to a `tempfile.mkstemp` path and the diversion is **announced on
stdout**. Exit codes are untouched (0 clean / 1 violations / 2 corpus refusal).

Three design decisions, each of which could have gone the other way:

- **Refuse vs. divert → divert.** The task allowed either. A hard refusal makes the bare
  invocation useless, and the bare invocation is a legitimate debugging action — it is what
  T256 was doing when it hit the trap. Diverting keeps the instrument usable and still ends
  the defect.
- **The class, not the instance.** The check is *"is this destination tracked"*, not *"was the
  env var set"*, so a caller who points `FAILOPEN_LINT_JSON` at a tracked file **by mistake**
  is protected too. Driven against `lint.json`, `CLAUDE.md` and `patterns.md`.
- **The default deliberately still points at the tracked file.** Repointing it at scratch would
  silently falsify `conformance.sh:1560-1562` — *"The linter's default destination is a TRACKED
  file, and a harness that rewrote a tracked file on every graded run would dirty the tree it
  is grading"* — and `conformance.sh` is outside this task's grant. Leaving the default where
  it is keeps that sentence true and its diversion necessary. **This avoided writing a P-80
  rot into the graded harness while fixing a defect.**

**Why the documented remedy was the wrong shape**, which is the task's own premise and I agree
with it: T256's handoff says *"anyone debugging that guard by hand should set
`FAILOPEN_LINT_JSON` first."* That is **P-45** — *"**A test-only guard is not a guard.** T154's
float-literal census is called from `Run`, not only from the Go test, because `conformance.sh`
never invokes `go test` — a test-only fix would have left the third silent green standing while
looking fixed. **Rule: when hardening a check, verify the path that actually executes in
CI/conformance calls it, not merely that a test does.**"* — read on the *safety* rather than on
the check. T243 made the destination overridable and diverted **its own call site only**,
leaving the trap armed for everyone else. The path that actually executes for a human at a
terminal is the **bare** one, and the bare one was unsafe. The linter's own docstring already
rules the shape out sixty lines above the defect: *"a remedy that consists of asking the next
author to be more careful cannot work here, because it was already tried on the most careful
author in the chain and it failed."*

## The two arguments the task asked me to make

### Is a directory rename an "edit in place" under T114/T176?

The ruling's exact text lives **inside the directory in question** [VERIFIED:
`.softhouse/capture/t256-verdict-predicate/acknowledged.json`, `_about` block; restated at
`check_verdict_predicate_agreement.py:29`]:

> *"**PINNED TO BYTES.** Each block names the sha256 of the file it acknowledges. Edit one byte
> of that file and the whole block goes VOID… That is **T114/T176 ('anything that produced
> COMMITTED EVIDENCE is superseded, NEVER edited in place')** enforced by the instrument instead
> of by discipline."*

**On the letter: NO.** `git mv` changes no committed byte, and the sha256 pins in
`acknowledged.json` are over files in `t229-g8-site3/` and `t219-g8-residual/` — not over
anything in the renamed directory — so the acknowledgements would **survive** a rename. Claiming
the ruling forbids a rename outright would be reading a conclusion into it, and I will not.

**On the mechanism: it fails, and the mechanism is the ruling's real content.** T114/T176 pins
*bytes* because what is being protected is the correspondence between a recorded result and the
artefact that produced it. A rename leaves every byte innocent and destroys exactly that
correspondence: **138 occurrences across 26 committed transcripts** would describe a run at a
location that does not exist, and **26 references in 16 other tasks' instruments** stop
resolving (24 → 0, measured).

**And the second step decides it.** The rename can only be *completed* by editing those 49
files — which is unambiguously editing **eight other tasks' committed evidence in place**
(T219, T262, T271, T284, T286, T290, T291, T293). **A move whose only clean completion is the
prohibited act must be refused at the first step, not the second**, because a half-finished
rename leaves the guards red and the transcripts lying at the same time.

The measurement that settles it independently of any ruling: **two of the three instruments the
rename kills are guards**, and `guard_rvpa_floor_t290.py` is the guard T290 built specifically
to close the T114/T176 retro-edit evasion. **Renaming kills the guard that protects this
directory's own conclusions.**

Both prior workers reached the same answer from smaller premises and were right to. T256: *"I
did not rename it — it is committed evidence and another task's."* T259: *"The name is left
alone deliberately — renaming it would break the only pointer the task carries."*

**So the defect was never the name. It was that the reason lived in T259's handoff, which is
not where a reader who greps `t256` lands.** That is what this task fixes.

## The convention I am installing

> **A capture or review directory is named for its SUBJECT. The task-id prefix is a
> CONVENIENCE, never the directory's identity. Identity lives in an `OWNER*.md` file inside the
> directory. The directory name is FROZEN AT FIRST COMMIT and is never renamed; when an id
> moves, the OWNER RECORD is corrected — because content can be superseded and a path cannot.**

1. **Never rename a committed capture/review directory.** Its path is cited by transcripts that
   cannot be corrected without editing them.
2. **If the prefix id is not the owner, say so IN THE DIRECTORY, IN THE FILENAME.** Not in the
   handoff — that is where T259 correctly put it, and T256 *still* had to file a defect three
   fires later. Shape: `OWNER-IS-T<owner>-NOT-T<prefix>.md`, or plain `OWNER.md` where there is
   no collision to shout about.
3. **Prefer the subject over the number (P-86).** `verdict-predicate` cannot rot; `t256-`
   already did. 21 of the 115 existing directories carry no id prefix at all and are
   structurally incapable of colliding this way.

**Root cause, verified two ways, and it is not carelessness.** The name came from the
`files_hint` T259 was **dispatched** with, and the task was **renumbered T256 → T259 on merge**
after a concurrent cloud fire published a different T256 [VERIFIED:
`.softhouse/handoff/T259-verdict-predicate.md:10-12`; and `tasks.json` T259 `note`, *"RENUMBERED
T256->T259 on merge: the cloud catch-up fire published a different T256 first."*]. `tasks.json`
**still carries `.softhouse/capture/t256-verdict-predicate/` in T259's `files_hint`** — the
dispatch artefact that minted the name is still sitting there.

That double allocation is **P-85** — *"TWO ORCHESTRATORS HELD THE LOCK AT ONCE… Three task IDs
(`T253`, `T254`, `T255`) and one pattern number (`P-78`) were **allocated twice with different
content**."* T256 was a fourth. And the shape of the resulting rot is **P-86** — *"an **ID IS A
CARDINAL**. Never restate a pattern id in a second document — make the second site NAME THE
RULE, or cite the id AND its sentence together so a shifted number is self-correcting…
**Prefer the name over the number.**"* **A directory named `t256-` is a task id restated in a
path, and a path is the one restatement that cannot be corrected afterwards.**

**Guard design decisions, both of which are measurements rather than taste:**

- **The threshold is `N−1`, not `N`, and my first draft was wrong.** Demanding a record in
  *every* member went red against `capture/t256-toolchain-population` — which is **T256's own
  rig and is correctly named**. That punishes the party that did nothing, and it would have
  forced an edit into a directory T298 is holding this fire. An id may legitimately own one
  directory; every further one belongs to somebody else and must say whose. The guard **names**
  which member it treats as the legitimate owner, so the choice is visible rather than assumed.
- **The `a2-<n>` id space is kept separate.** Folding it into the `t<n>` space produced **four
  false collisions** — `a2-29`/`t29-probe`, `a2-31`/`t31-probe`, `a2-33`/`t33-probe`,
  `a2-34`/`t34-probe` — eight unrelated tasks in two id spaces. A census that cries wolf on its
  first run is a census that gets pinned away.
- **The selector is `^t<digits>` with any following character**, not the anchored
  `^t<digits>[-_]` form, because `t256verdict` would evade the anchored form and collide unseen.
  Widths measured and reported: strict 93 prefixed / 22 unprefixed; loose **94 / 21**.

1. **My own fix diverted every legitimate caller.** The first `_dest_is_tracked` asked git about
   every destination. A scratch path under `TMPDIR` is **outside the work tree**, and
   `git ls-files --error-unmatch` answers **128** there, not 1 — so it was treated as "unknown →

   determination, not a guess). Measured codes at `39d2156`, git 2.50.1: tracked **0**,
   untracked-inside **1**, outside-the-tree **128**.
2. **My rename drive shipped a fail-open.** It wrapped each probe in `timeout`, which is
   **absent on this host**. All three probes exited **127** before *and* after, identically, so
   the arm reported *"the rename changed nothing"* having **executed nothing** — the T238
   linter's C2 shape, committed in the instrument written by the task that cites it. The wrapper
   is gone and the calibration is now **enforced**: any non-zero pre-rename exit aborts the
   drive. A second bug in the same pass mislabelled a dead-file count as a referencing-file
   count; both terms are now printed (P-67).
3. **The namespace guard shipped red on its own first run.** Its selector used
   `\(capture\|reviews\)` in a **BRE**, and BSD `sed` — `/usr/bin/sed` on this host — does not
   implement `\|`. It matched **zero** directories. It printed `ABORT(2)` **with the reason**
   instead of `collisions: 0`. **The fail-closed arm caught its own author**, which is the
