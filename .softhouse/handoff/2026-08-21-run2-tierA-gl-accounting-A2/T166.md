## Changes Made

### 1. The guarded root is DERIVED, and it is the GO MODULE ROOT

Three sites named `nexus/internal/apps/loanschedule` and now name `nexus`, walked
recursively:

| site | before | after |
|---|---|---|
| `conformance.sh` `guard_no_float_in_harness` | `find "$NEXUS_DIR/internal/apps/loanschedule"` | `find "$NEXUS_DIR"` (find recurses by default) |
| `conformance.sh` `guard_gofmt` | `gofmt -l "$HARNESS_PKG" …/conformance/cmd` | `gofmt -l "$NEXUS_DIR"` (recurses), contract.go filtered from the OUTPUT |
| `nofloat.go` census root | `LoanScheduleTreeRel` | `GuardedGoTreeRel = "nexus"` |

`ScanGoTreeForFloatingPoint` moved from `filepath.Walk` to `filepath.WalkDir` and
descends at every depth.

**No second hard-coded path was added** (the brief's explicit prohibition; P-26).
**No allowlist and no exemption list was added** — see "Evasions closed" for why
and what replaces it.

**Why the module root rather than `internal/apps`, which is what A2-9's F-E
prescribed.** `internal/apps` is itself a hard-coded path: a package landing at
`nexus/internal/domain/` or `nexus/pkg/` would be silently uncovered, and SILENT
is the defect class, not the particular directory. The two roots select the
identical file set today — every `.go` file in the module is under
`internal/apps` — so the wider root cost nothing. It is driven red below with a
plant at `nexus/internal/domain/`, which the F-E prescription would **not** have
caught. This is a deliberate widening beyond the brief's floor, flagged here
rather than made quietly.

### 2. Packages are counted, and zero packages is an ERROR

`FloatingPointCensus` gains `PackagesScanned`, `PackageDirs` (the sorted set),
and `ImportsScanned`. `ScanGoTreeForFloatingPoint` errors on zero files **or**
zero packages. `grade.go` asserts `PackagesScanned == 0` in a **separate
statement** from the census call, for the same reason T155 required the
files-scanned assertion to be separate: a minimal deletion of the census call
site leaves the assertion standing and it fires.

Rationale: a file count alone cannot distinguish "the whole module was walked"
from "one directory was walked and the rest of the module was never opened", and
the second is exactly the state this repository was in while printing a
healthy-looking `24 Go files`.

`report.go` now prints the covered package **SET**, not merely its size.

### 3. Renamed, because the old names lied

- `LoanScheduleTreeRel` → `GuardedGoTreeRel`
- `TestNoFloatInTheLoanScheduleTree` → `TestNoFloatInTheGuardedGoTree`

A reader of `grade.go` saw `LoanScheduleTreeRel` and read it as a deliberate
scoping decision rather than the accident it was.

### 4. A THIRD arm: a parser-based import ban (`math`)

`x := math.Sqrt(y)` / `math.Pi` / `math.MaxFloat64` / `math.Inf(1)` produce
IEEE-754 doubles while naming **no** forbidden identifier and containing **no**
`token.FLOAT`. Both pre-existing arms were blind to all of them — including
inside the tree the old guard already walked. Measured, not argued (probe 5
below).

`forbiddenImportPaths` bans the plain `math` import, detected with
`go/parser` in `ImportsOnly` mode (P-48: a parser, not a regex — a path named in
a comment or a string cannot trip it, and an **aliased** import cannot hide from
it). `math/big` and `math/bits` are **not** banned; `big.Float` is already
blocked by the `Float` identifier.

Banning the package rather than enumerating `Sqrt`/`Pi`/`Round`/`Abs`/… is the
P-26 point: a name list closes only the members somebody thought of, and it
collides immediately with real integer identifiers in this module — `Abs`
appears 3× on `math/big.Int` and `Rounding*` appears 140×
[VERIFIED: T166 `grep -rno` over `nexus/internal/apps/loanschedule`].
No file in the module imports plain `math`
[VERIFIED: `grep -rn '"math"' nexus/` returns only `"math/big"` ×4].

### 5. T165's CWD defect made VISIBLE (not fixed — see Blockers)

`report.go` now prints `census root walked: <absolute path>`. `GuardedGoTreeRel`
is a relative path and a relative path cannot say which checkout was graded.

## Evasions closed, and evasions that remain with the reason

### Closed as a set

| evasion | closed by | driven red |
|---|---|---|
| float LITERAL, no forbidden identifier (`0.036 / 12.0`) | `token.FLOAT` / `token.IMAG` arm (T154) at the widened root | plant 1, plant 4 |
| float-typed IDENTIFIER | identifier arm at the widened root; both shell and Go legs | plant 2 |
| float in a **subdirectory** (A2-9 **F-E**) | `filepath.WalkDir` + `find` recursion | plant 3, and `the_guard_descends_into_subdirectories` at 3 depths |
| float in **another package** | derived root | plants 1–3 |
| float in a package **outside `internal/apps`** | root is the module root, not `internal/apps` | plant 4 |
| float via `math.*` (`Sqrt`, `Pi`, `MaxFloat64`, `Inf`, `Round`, …) — no forbidden ident, no float literal | `forbiddenImportPaths` ban on `"math"`, `go/parser` `ImportsOnly` | plant 5, incl. the **pre-fix control inside the already-guarded tree** |
| the same via an **aliased** import (`m "math"`) | parser leg reads the import spec, not the selector | plant 5 uses the aliased form |
| a guard that walks **nothing** | zero-files AND zero-packages errors, in both languages, `grade.go` asserting separately | zero-package probe; 2 sub-tests |
| a guard that **names one tree and walks another** | `census root walked: <abs>` printed | T165 divergence measured below |
| a **new package** silently uncovered | root derived from disk; `every_go_package_in_the_module_is_covered` re-enumerates the module by an independent walk and requires set equality | that sub-test fails if the root narrows |

An **allowlist was considered and rejected**. The brief permitted "an explicit
committed allowlist the harness refuses to run without"; I chose the derived
walk instead and added **no** exemption mechanism at all, because an allowlist
entry outlives the reason it was added. The one file that must name forbidden
spellings in code (`nofloat.go`) splits them across string concatenations, and
the one new test that needed to do so in a string literal now does the same. That
is an exemption that cannot rot.

### Remaining, enumerated with the reason (recorded in `nofloat.go` too, not only here)

1. **float64 by TYPE INFERENCE from another package** — `v := somepkg.Rate()`
   where `Rate` returns a `float64`. No forbidden IDENT and no FLOAT token at the
   use site. **Closed transitively, not directly:** every package in the module
   is inside the guarded root, so the *declaration* is flagged even though the
   *use* is not. The conditions that keep it closed are (a) `go.mod` declares no
   third-party requires [VERIFIED: `nexus/go.mod` is `module …` + `go 1.23`,
   no `require` block] and (b) no package escapes the root, which
   `every_go_package_in_the_module_is_covered` asserts. **Add a dependency and
   this class reopens.** Closing it directly needs a type-checked scan
   (`go/types` with a source importer) — a larger change than T166, raised as a
   follow-up.
2. **float64 by DECODING** — `encoding/json` yields `float64` for a number
   unmarshalled into `any`, with no float token anywhere. In the vector loader
   this is already closed **by construction rather than by scanning**:
   `dec.UseNumber()` plus `RejectFloatTokens`, which rejects any non-integer JSON
   number in any field [VERIFIED: `conformance/vector.go:768-773` and
   `RejectFloatTokens` at `:792`]. In a **future** package it would be open, and
   `any` on a money path is the shape a reviewer must look for by eye.
3. **`unsafe` punning, reflection, cgo.** Nothing textual can see these. The
   module imports none of them today; `forbiddenImportPaths` is where an import
   ban would go if that changes.
4. **A2-9's F-F — the cross-family enum conversion evasions.** These are **not
   closed and are not closable by this guard**, for two separate reasons, and I
   want both on record rather than one:
   - The code F-F describes (`TestNoCrossFamilySlotConversion` in
     `nexus/internal/apps/ledger/`) **does not exist on `main` and does not
     exist in my worktree** — A2-8's branch is unmerged. I verified this:
     `find nexus/internal/apps -maxdepth 1 -type d` returns only `loanschedule`.
     I could not modify a file that is not here, and `ledger/` is outside my
     `files_hint`.
   - Even where it does exist, it is a **typing** question, not a lexical one. A
     token scan cannot resolve `int32 → enum` through an intermediate variable.
     A2-9 reached the same conclusion ("the language cannot do better ... the
     compiler is the stronger guard here — duplicate map keys / duplicate switch
     cases caught two of my six perturbations outright"), and I adopt it rather
     than pretend otherwise. **What T166 *does* give F-F: `ledger/` and every
     subdirectory of it are now inside the guarded root the moment A2-8 merges,
     so the FLOAT half of the ledger port is covered by default and its
     in-package `go test` scans are no longer the only thing looking.** The enum
     half remains a review obligation, recorded as a follow-up.

**Explicitly noted, as the brief required:** A2-8's in-package
`TestNoCrossFamilySlotConversion` and `TestNoFloatingPointInThisPackage` are
`go test` checks. `conformance.sh` never runs `go test` — it runs `run_guards`
and then builds and runs the harness binary [VERIFIED: `conformance.sh`
`main_grade()` calls `load_toolchain`, `run_guards`, `build_binary`, then
`"$CONF_BIN"`; there is no `go test` invocation anywhere in the script]. So those
scans **do not close this**, and every T166 leg lands on the path
`conformance.sh` actually executes: the two shell guards, and the census that
`grade.go` runs inside the binary and turns into a `FatalReason` (P-45).

## Follow-ups

1. **T165 must land.** Until it does, `conformance.sh` can grade a tree the shell
   guards did not walk. The visible-diagnostic mitigation here is not a fix.
2. **A type-checked no-float scan** (`go/types` with a source importer) is the
   only thing that closes remaining evasion 1 directly. Worth doing before any
   third-party dependency enters `go.mod`; today the class is closed only
   transitively, and adding a dependency reopens it silently. Consider pairing it
   with a guard that fails if `nexus/go.mod` grows a `require` block.
3. **A2-8's `ledger/` in-package scans should be deleted or re-pointed** when that
   branch merges. They now duplicate a strictly weaker version of the module-wide
   census (`os.ReadDir(".")`, no recursion), and a weaker duplicate of a rule is
   how a reader comes to believe the wrong thing about coverage. The cross-family
   enum scan should stay — it checks something this guard does not.
4. **A2-9's F-F enum evasions remain a review obligation**, not a mechanical one.
   Recorded in `nofloat.go` so the next reader does not go looking for it in the
