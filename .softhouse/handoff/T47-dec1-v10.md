## 1. What changed, per finding

### Finding 1 — the month-end special case is NOT SEPARABLE; pin the packed rule. **CONFIRMED, re-derived independently, and it is the one substantive change.**

**Re-derived by this task before writing, as the brief required.** With `pm(d) = d.year × 12 + d.month`,
`k = pm(b) − pm(a)`, `len(b)` the length of `b`'s month, and `a ≤ b` (which every reachable call site
guarantees, because the seed is either `ScheduleStartDate` — the first repayment period's `FromDate`
[`ProgressiveLoanInterestScheduleModel.java:209-211`] — or this period's own `FromDate` [`:1477-1480`]):

```
packed(a, b)  = k − [a.day > b.day]                    (k ≥ 1)
clamped(a, b) = k − [min(a.day, len(b)) > b.day]
packed ≠ clamped  ⟺  b.day = len(b)  ∧  a.day > b.day
```

The equivalence: `min(a.day, len(b)) > b.day ⟹ a.day > b.day`, so they can differ only when
`a.day > b.day ∧ min(a.day, len(b)) ≤ b.day`; given the first conjunct the second forces
`len(b) ≤ b.day`, and `b.day ≤ len(b)` always, so `b.day = len(b)`. That right-hand side is
**verbatim `ProgressiveEMICalculator.java:1432`**. When it fires the oracle measures to
`FromDate.plusDays(1)` [`:1433`] — the 1st of the next month, `pm` up by one — and the predicate itself
forces `a.day > b.day = len(b) ≥ 28`, so `a.day ≥ 29 > 1` and
`packed(a, b+1d) = (k+1) − 1 = k = clamped(a, b)`. **`k_oracle ≡ k_clamped` identically.**

**One refinement T46 did not state, and this task added.** At `k = 0` Java's truncation toward zero
makes `packed = 0` where the floor form gives `−1`. It is unreachable — `a ≤ b` with `pm(a) = pm(b)`
forces `a.day ≤ b.day`, so neither the `:1432` predicate nor the divergence can fire — but a port that
transcribes the **closed form** instead of `MONTHS.between` must reproduce the truncation. Recorded in
§4.1.1 step B.
