## The answer to the question the task asked

The brief's hypothesis was "this is systematic, not three coincidences." It is systematic — but the
pattern is sharper than "guards are broken", and the sharp version is what makes it routable:

> **Every vacuous guard in this repo is a NEGATIVE assertion — it tests that something is ABSENT.
> Every guard that survived attack is a POSITIVE one — it tests that something is PRESENT AND EQUAL.**

A negative assertion (`count == 0`, `[ -z "$x" ]`, `grep found nothing`) is vacuous on zero input **by
construction**; no amount of care in writing one fixes that. All three defects the fire found are
instances, and so is every new one below. The corollary for reviewers is a one-line test:
**if a guard's PASS sentence would still print when its input was empty, it is not a guard.**

Second answer, and it is worse than any single row: **`.claude/skills/softhouse-uat/SKILL.md:35-43`
publishes a table headed "HARD checks — must be zero" with five rows, and four of them have no
executable existence anywhere in the repo** (ledger append-only, balance writes, hold semantics,
`Idempotency-Key`). A `/softhouse-uat` PASS is read as certifying all five. This is P-22 at the
document level and it is one edit to fix.

## Tool-behaviour note (P-33), because it decided one of the findings

On this host, at the Claude Code Bash-tool top level `type -a grep` reports *"grep is a shell function
from …/shell-snapshots/snapshot-zsh-…"* before `/usr/bin/grep`; **inside a script it is
`/usr/bin/grep` alone — BSD grep 2.6.0-FreeBSD**. The ambient locale in this session is
`LANG=C.UTF-8` with `LC_ALL` unset, and **BSD grep treats `C.UTF-8` as multibyte**, so M-1's blindness
reproduces at the *default* locale, not only under `en_US.UTF-8`. Every sweep in this audit was run
from a script under `LC_ALL=C` with `-a`. If a later worker cannot reproduce a finding here, check
those five things before concluding the finding is wrong.
