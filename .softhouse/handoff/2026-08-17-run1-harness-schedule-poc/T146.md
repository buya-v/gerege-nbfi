## Answer to the question the brief asked first

**Graph 4 CAN be made to catch all four edits, and it now does — but not by a
line-oriented command, and the limit that IS published is a different one.**

- **No sed/tr/grep pipeline can decide this.** A Java enum constant list is not a
  line language: constants carry constructor arguments and class bodies with nested
  braces, `/* */` comments span lines, the first constant may sit on the enum header
  line, the last may drop its comma. Deciding it needs a scanner with a nesting depth
  and a comment state. That is stated in the block in those words.
- So graph 4's command is now a **program**: a 45-line POSIX **awk** census, written
  out in full inside `emi.go`, which goes **RED on all eight** legal five-constant
  edits (T96's three, T128's four, and one of my own) and **errors loudly** on starved
  input.
- **It is awk and not Python for a reason I had to discover the hard way.** I wrote
  it in Python first. `gofmt -l` then named `emi.go`: gofmt reflows doc comments and
  **flattens any line indented deeper than the block's own base**, which silently
  destroys an indentation-significant program and would have left the next reader
  copying out a broken census. awk does not care about leading whitespace, so what is
  printed is what runs. That is recorded in the block.
- **What is published as a limit instead** is the residual set the tokeniser still
  cannot see — chiefly a `\uXXXX` escape that hides structure (JLS 3.3 resolves it
  before lexing), which the program now **refuses** rather than answers.
