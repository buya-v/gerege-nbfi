## 1. F-T119-1 (P2) — the only behavioural one. **Decision: make the check genuinely store-wide.**

**The hole, reproduced on T110's own binary before it was closed.** `LoadStore` applied `contextFilter` at `vector.go:830-832` *before* it collected, so `DuplicateCaseIDs` only ever saw the contexts being graded. One scratch store carrying `case_id` `P-00` in **two** context directories, both binaries built from `git archive`, one common store, `-oracle-probe=up`:

```
                                exit  parity  DUPLICATE-lines  verdict
t110  unfiltered                 2      0           1          UNUSABLE
t110  -context=loanschedule      0     42           0          PASS        <-- THE HOLE
fix   unfiltered                 2      0           1          UNUSABLE
fix   -context=loanschedule      2      0           1          UNUSABLE    <-- CLOSED
```

`[VERIFIED: my run, /tmp/t123/out/cross-*.txt]` T110's filtered run printed `VERDICT: PASS (exit 0) — 42 parity vectors match the pinned reference oracle, 5555 cells compared`, over a store that had two files claiming to be `P-00`.

**Which of the two answers, and why.** T119 offered either making the check store-wide or narrowing the claim to what the code does. I made it store-wide, for the reason T110 keyed on `case_id` alone in the first place: **the report prints CASE without CONTEXT**, so the two rows a cross-context duplicate produces are indistinguishable to a reader *whichever* run surfaces them. Narrowing the claim would have left a defect that is invisible from one angle and visible from another — and the run that hides it is the one somebody quotes. The claim and the behaviour now agree, and they agree in the direction that makes the guard stronger rather than the sentence weaker.

**How.** `LoadStore` collects every context directory into `all`, sorts, takes the census over `all`, and only then returns the graded subset. *The filter narrows what is GRADED; it does not narrow what is CHECKED.*

**The two costs, written down rather than discovered later** (both in the doc comment):

- a context directory that cannot be **enumerated** now fails the run even when the filter excludes it. Uniqueness across the store cannot be asserted over a directory that could not be listed.
- a file **outside** the filter that fails to **load** is skipped and is not recorded as a `LoadError`, exactly as before. This is a blind spot and it is confined to files that could not have been counted anyway: a vector that does not load is never graded, so it cannot inflate a count; and in the unfiltered run `conformance.sh` performs it is a `LoadError` and the run is exit 2 regardless.

**A clean store under a filter is unchanged** — `cmp`, not inspection: `-context=loanschedule` and `-context=_selftest` are **byte-identical** between the T110 and T123 binaries on the pristine store. The change bites only when the store is defective. Wall time for the filtered run: t110 `0.573s`, fix `0.553s` — the wider census is inside the noise at 47 vectors.

**Driven red (P-22):** new mutation **M6** reinstates T110's filter-before-collect and turns the new sub-test `duplicate_outside_the_context_filter_is_still_refused` **red on exactly one sub-test**, with the message `LoadStore with -context=loanschedule accepted a store in which loanschedule/P-00-baseline-6x7pct.json and _selftest/ZZZ-crossdir-duplicate-of-P-00.json both declare case_id P-00: it loaded 46 vectors and reported a clean run.`

The new sub-test has three anti-vacuity `t.Fatal`s before it asserts anything: the duplicate must be planted outside the filter; the filter must load a non-zero number of vectors; and the filter must **strictly narrow** the store (`len(filtered) >= len(unfiltered)` fails loudly), or it would be sub-test (3) wearing a different name. It also asserts the report names `DUPLICATE case_id` and both paths, because exit 2 has eight-plus other causes and "exit 2" alone would not prove it reached that code for this reason.

## 4. T119's census ruling, recorded here so **T120 inherits it** instead of rediscovering it

T119 ruled **in favour** of the store census T120 will build, and corrected the naive design twice. Both corrections are load-bearing; the first kills the obvious implementation outright.

1. **The two enumerations already disagree on the CLEAN store.** `find` sees **49**, `LoadStore` sees **47**, because `PIN.json` and `capabilities.json` sit at the store root and are loaded by `LoadPin` / `LoadCapabilityRegistry` instead. **A naive equal-counts census is red on day one.** The predicate must be `{everything under the root} − {PIN.json, capabilities.json, README.md} == {what LoadStore loaded}`, with that exemption list **explicit and short**, or it will be widened later until it exempts the defect.
2. **It must be Go-side inside `LoadStore`, not in `conformance.sh`.** A shell census can only check the shell's own view, and the defect *is* that the two views differ. It would also miss E2 outright: `find … -type f` cannot see through a symlinked context directory either. A Go census (`filepath.WalkDir`, symlinked directories **detected and refused** rather than followed) makes `LoadStore` the single authority on what is in the store, which removes the disagreement instead of measuring it — and it inherits the refusal channel T110 built, so its guard can be written the same way, through `LoadStore` and `Run`.
3. **The `case_id` charset rule `[A-Za-z0-9._-]` is SOUND.** Measured by T119 over the committed store: 47 ids, **0** outside the set, **0** non-ASCII bytes, 47 distinct and still 47 after case-folding — and the same across **all 15** historical commits. It closes F-T110-5 outright and F-T110-4's realistic form with no `golang.org/x/text` dependency. Implementer's constraint: the charset rule is a property of **one file**, so raise it as a `LoadError`, **not** through `DuplicateCaseIDs`, and drive it red on a scratch store carrying `P-00-café` before believing it.

T123 makes one thing easier for T120: `LoadStore` now enumerates every context directory unconditionally, so the census has the whole store in hand at the point the check would go.
