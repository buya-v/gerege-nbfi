## 1. THE RULING

**The token `grep` means two different programs on this host, and which one you get depends on
where you type it. That single fact explains all four contradictory claims, and every worker
measured something real.**

| Where `grep` is typed | What actually runs |
|---|---|
| Directly into the Claude Code **Bash tool** | a **shell function** from `~/.claude/shell-snapshots/<session>.sh`, which re-execs the `claude` binary with `argv[0]=ugrep` — **ugrep 7.5.0**, with **`-I` (skip binary files) hard-coded** |
| Inside a script run as `sh x.sh` / `bash x.sh` | `/usr/bin/grep` — **BSD grep 2.6.0-FreeBSD**. Shell functions are not exported to children. |
| `command grep`, ~~`command -v grep`,~~ `/usr/bin/grep` | BSD grep — the function is **deliberately bypassed**~~, which is why every probe that used `command -v` was blind to it~~ **[F-T131-1 — `command -v grep` does NOT belong in this row; see the correction block below]** |

There is **no standalone `ugrep` binary**. ugrep is **embedded in the `claude` executable**. That is
why `command -v ugrep` is empty while `grep --version` prints `ugrep 7.5.0`.

> **CORRECTION [F-T131-1, `.softhouse/reviews/T131-review-of-T108.md` §6, applied by T221 — struck, not
> deleted, so the original claim stays traceable]. `command -v` does NOT bypass shell functions.**
> `command <cmd>` bypasses the function when it *runs* the command; **`command -v <cmd>` reports the
> function** — POSIX requires it to. Proven by construction in both shells (T131 `probe-commandv.sh`):
> `bash -c 'foo(){ :; }; command -v foo'` → `foo`, and `zsh -c` likewise; with a `grep` function defined,
> `command grep --version` → `BSD grep … 2.6.0-FreeBSD` while `command -v grep` → the bare word `grep`,
> **not** `/usr/bin/grep`. In the live Bash tool `command -v grep` prints `grep`.
>
> **What survives, unchanged:** the ruling, the two-programs finding, and the rule *"use `type -a`, never
> `command -v`, when the question is which program runs"* — because `command -v` on a function returns a
> bare name that names **no program**, which is a different and weaker defect than bypassing. **What is
> withdrawn** is only the stated *mechanism*. The operative reason T107b was blind is the **other** reason
> this document already gives and which is sufficient on its own: **it ran from a script**, and shell
> functions are not exported to children. This is the same defect class §1.2 convicts T80 of — right
> conclusion, wrong reason, propagated into a durable file (P-11).

## 7. PROPOSED PATTERN — for the driver to place in `patterns.md` (I did not edit it)

### P-29. A claim about a TOOL is a claim about a BINARY, a VERSION, a LOCALE, an INVOCATION and an INPUT SHAPE — name all five or it is not a measurement

**Fires `20260820-200002` → `20260821-080001`, T80 → T85 → T91 → T107 → T107b → T108. Four workers,
four incompatible claims, one word: "grep".**

Nobody was careless with a number. T80 measured BSD grep and reported it accurately. T91 measured a
different byte shape under the mitigation it was testing and honestly reported a non-reproduction.
T107 measured the embedded ugrep and was right. T107b searched for a `ugrep` **file**, found none,
and downgraded a true claim to `[UNVERIFIED]`. Every step was defensible. The composite was a
committed contradiction that propagated into two hardening sites and three worker briefs.

The trap is that a tool name is not a referent. On this host `grep` resolves to **BSD grep
2.6.0-FreeBSD** inside a script and to **ugrep 7.5.0 with `-I` hard-coded** when an agent types it
into the Bash tool — because the harness installs a `grep` **shell function** that re-execs the
`claude` binary with `argv[0]=ugrep`. The two have *opposite* mitigations: `LC_ALL=C` fixes one and
does nothing for the other; `-a` fixes the other and does nothing for the one. So a worker can
apply the right fix for the wrong reason, and the next worker can "disprove" the reason and be
tempted to remove the fix.

**The rule.** Before a tool-behaviour claim may be written down as fact, record all five of:

1. the **resolved binary** — `type -a X`, not `command -v X`. ~~`command` and `command -v`
   **deliberately bypass shell functions**, so they are~~ **[CORRECTED, F-T131-1 — see §1: `command X`
   bypasses the function when it runs the command, but `command -v X` **reports** the function. Read the
   clause as: `command -v X` is]** **the wrong instrument for this question** — on a function it returns a
   bare name that names no program, and a probe run **from a script** never sees the function at all — and
   an absent binary does not mean an absent tool;
2. the **version string**, from the thing that actually ran;
3. the **locale**, and — decisively — a locale **that is not the mitigation under test**. *A test of
   whether `LC_ALL=C` matters, run with `LC_ALL=C` in both arms, cannot answer the question;*
4. the **exact invocation**, including flags the harness injects that you did not type;
5. the **input bytes**, as a hexdump — and at least two **positions** of the interesting byte
   (before the match, after the match, on another line). Position was the entire disagreement here:
   the same file with the poison moved four bytes left flips the answer.

**And the corollary, which is P-22 wearing different clothes:** *N of N green cells are not a
refutation if the failing shape is not among the N.* "18 of 18 matched" was measured twice,
correctly, by two workers — and the one shape that fails was in neither of the eighteen. When a
result contradicts an earlier worker, the first question is not "who is right" but **"did we run
the same experiment?"** — and the cheapest way to answer it is to re-run *their* probe, from their
committed bytes, and then vary one dimension at a time.

**Standing consequence for this program:** every content assertion in a rig uses **`LC_ALL=C grep
-a`**, both tokens, always. Not because either failure mode is likely, but because the two tokens
cost nothing and each closes a hole the other leaves wide open — including in
`guard_no_float_in_vectors`, where the hole is a **silent pass on a float**.
