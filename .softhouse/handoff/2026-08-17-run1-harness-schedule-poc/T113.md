## 1. The defect (T106 F1, P1)

T97 replaced the guard's negative probe ("no failure was observed") with positive
evidence ("a token only a working process substitution could have produced"). It then
wrote, at `conformance.sh:96-99` and in four places in its own handoff, that

> every way of not running the probe (syntax error, refused redirection, killed
> subshell, a shell that never reached the line) yields an empty observation and
> **FAILS CLOSED**.

That enumeration omits a family: **the redirection is attempted and fails at RUN
TIME**, as opposed to failing to parse. The eval string still parses, `builtin read`
runs and never assigns, and the very next statement prints the variable — which T97
never initialised. It was the only probe variable that was neither defaulted nor unset
(`conformance_psub_seen` and `CONFORMANCE_PSUB_TOKEN` both are, and pre-seeding *those*
is correctly defeated).

So an **inherited** `_conformance_psub_line=conformance-psub-live` makes a shell whose
`< <(…)` genuinely cannot be opened admit itself.

**Why it is not cosmetic.** A wrongly admitted run on a psub-dead shell reaches the HARD
guards, and both are `while IFS= read -r f; do … done < <(find …)` loops that
`return "$bad"` after the loop. With psub dead the redirection fails, the body never
runs, `bad` stays `0`, and the function returns 0 **having inspected zero files** —
`guard_no_float_in_vectors` certifying "no floats" without opening a file. That is the
P-22 failure mode — *a guard that cannot fail is worse than none, because it is believed*
— and unlike the residual hijacks it can turn a red check green: a hijack **refuses**, and
a refusal cannot turn a red run green; a forged **admission** can.

**F-T113-2 — a false citation, caught by re-opening it (P-16).** T106's review, and the
rescued WIP's paragraph copying it, both say this vacuous-pass hazard is *"the P-22 failure
mode the harness's own comment at **line 53** cites"*. It is not. The block that line number
points at is `WHY IT EXISTS`, and it says the process substitution inside
`guard_no_float_in_vectors` **died** under `sh` and was mistaken for an oracle outage. That
is the opposite failure: dying loudly, not returning 0 over an **empty** file set. Checked
against T97's own pre-fix bytes as well (`f2813c8`), where the only P-22 sentence in the
whole file is the `--help` comment at line 872. Corrected in place at
`conformance.sh:123-136`, and the replacement names the block instead of numbering it,
because the number is precisely what drifted — the same block is line 51 in T97's bytes and
line 56 in today's.

## 2. The fix — one line

```diff
   conformance_psub_seen="$(
     builtin eval '
+      _conformance_psub_line=
       IFS= builtin read -r _conformance_psub_line \
            < <(builtin printf "%s\n" "$CONFORMANCE_PSUB_TOKEN")
       builtin printf "%s" "$_conformance_psub_line"
     ' 2>/dev/null
   )"
```

`.softhouse/conformance.sh:220-224`. A plain **assignment**, deliberately: it is not a
command word, so unlike `builtin unset -v …` nothing can shadow it. The observation now
starts from empty, so the token can reach the comparison only by the read succeeding —
which closes the whole "the probe did not run, or ran and failed" family, run-time
open() failure included.

Companion applied in the same edit, per T106: `_conformance_psub_line` added to the
trailing `unset` list at `conformance.sh:291`, **labelled as hygiene, not as a control**
(`unset` is itself a command word and shadowable; the variable is normally only ever set
inside a command-substitution subshell, so the parent has it *only* when the caller
exported it — i.e. exactly the forge).

## 7. NEW FINDING — F-T113-1. The probe's `IFS=` prefix is insurance, not a measured save

**Against T106, and by inheritance against T97's matrix.** T106's review says:

> `IFS=e` is worth naming: `e` occurs in the token, so without the `IFS=` prefix in the
> probe this would have been a false refusal — **that prefix earns its place**.

That is a derivation, not a measurement, and it does not survive one. `read` with a
**single** variable assigns the whole line and strips only leading/trailing IFS
**whitespace**; a non-whitespace delimiter is not removed, even when it is the token's
first or last character (`conformance-psub-live` begins with `c` and ends with `e`).

Measured with the prefix **deleted**, on bash 3.2.57 and bash 5.3.9, the probe returned
the token intact under `IFS` = `oc`, `' '`, `e`, `c`, `-`, `l`, `v`, `i` and newline —
and the whole harness was still **ADMITTED** in every case:

```
IFS=[oc]   no-prefix: EQ    with-prefix: EQ
IFS=[ ]    no-prefix: EQ    with-prefix: EQ
IFS=[e]    no-prefix: EQ    with-prefix: EQ
IFS=[c]    no-prefix: EQ    with-prefix: EQ
IFS=[-]    no-prefix: EQ    with-prefix: EQ
...
  no-prefix harness, IFS=[oc] -> exit=0
  no-prefix harness, IFS=[e]  -> exit=0
  no-prefix harness, IFS=[c]  -> exit=0
  no-prefix harness, IFS=[ ]  -> exit=0
```

**Disposition: keep the prefix, withdraw the claim.** It costs nothing and it is the
difference between "cannot break today" and "cannot break if someone later reads two
variables or puts whitespace in the token". But a guard credited with a save it never
made is P-22 in miniature, so the harness comment now says so and
`interpreter-matrix.sh` section [6] asserts the inertness **executably** (5 rows), with a
`cmp` guard so it cannot go inert if the probe's shape moves.
