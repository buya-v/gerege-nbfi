## What I built

### 1. `.softhouse/conformance.sh`

```
.softhouse/conformance.sh [CONTEXT]      grade the store, optionally one context
.softhouse/conformance.sh --self-test    grade the HARNESS via the replay implementation
.softhouse/conformance.sh --prove        the harness's own red/green mutation suite
```

Sources the repo-local toolchain (`$REPO/.softhouse/bin/go-env.sh`), runs three HARD
guards, probes the reference oracle, builds the grader to a temp binary and propagates its
exit code.

**Exit codes.** `0` every graded vector passed **and** at least one *parity* vector was
graded **and** the oracle was confirmed reachable · `1` a mismatch or a violated invariant ·
`2` harness/corpus/oracle unusable. FAIL (1) deliberately takes precedence over UNUSABLE
(2): a mismatch is a definite, actionable finding and unusability is the absence of one, so
the louder wins. Both are non-zero, which is the property that actually matters.

**The three HARD guards** (they prove absence of known-bad patterns, never correctness):

* no float-shaped JSON number in any vector file — string literals stripped first, so a
  `"112082.37"` wire text is fine and a bare `21.6` is not;
* no floating-point identifier in the loanschedule Go tree — comments stripped first;
* `gofmt -l` over the files the harness owns, **explicitly exempting**
  `contract/contract.go` with the reason in a comment, per gate **G-3**. The harness never
  runs `gofmt -w`, `go fmt ./...` or any format-all over that path.

**Oracle probe.** `curl -sk` against `actuator/health`, read-only. Result is passed to the
grader as `-oracle-probe=up|down|skipped`, and the flag **defaults to `down`**, so a caller
that forgets to probe cannot obtain exit 0. The live containers are never restarted,
recreated or reconfigured.

### The reasoning behind the schema's shape

**Money is a JSON string, not a JSON number.** `"amount_minor": "100000"`. Most JSON
readers — `jq` among them — decode every number into an IEEE-754 double, so an integral
JSON number can be corrupted by the *reader* rather than the file. Strings remove the
question and let the float guard state a rule with no exceptions: **no JSON number anywhere
in a vector may contain `.`, `e` or `E`.** Non-monetary counts stay integers.

**Probe-vs-parity is structural, not a label.** A parity vector must record
`threaded_mathcontext` **and** `ambient_mathcontext`, both must be `(19, HALF_UP)`, and
`request.rounding` must agree with the threaded one. Passes 1–2 ran at precision 12/8 —
*the numbers in them were produced at a precision the harness reads off the file*, so
relabelling a probe as parity fails on the numbers. Two dimensions are recorded rather than
one because which context scales a value to currency precision is decided by the
CONSTRUCTION, not by the arithmetic. `PIN.json` carries a `never_promotable` denylist of the
known probe/calibration ids as a second line, not the first.

**A parity vector must point at a capture that exists.** `capture_ref` must resolve to a
real file in the repo; `capture_case_id` must name the case *inside* it, because Path A
captures are bundles of up to 2,016 cases in one file and a path alone is not provenance.
`capture_sha256` is verified when present. A hand-authored number cannot become parity by
relabelling — it would have to point at a real capture artefact.

**Class and directory are locked in both directions.** `selftest` only under `_selftest/`;
nothing else under `_selftest/`; the `provenance.note` string is fixed text.
`contract-refusal` may carry **no periods at all**, so it has nowhere to put an unobserved
amount.

**Capability classes, not "does this involve charges?".** `capabilities_required` on the
vector; per-seam `status` in `capabilities.json`. Four statuses because "not exercised" has
different causes — `exercised` / `blind` / `aliased` / `partial` — plus **absent ⇒
default-deny**. `in_graded_domain` is a *separate* flag, because a seam can exercise a
capability nothing has promoted a vector for. Registry is **data**, so a third blind spot is
one row: every affected vector starts being refused with no vector file changing, no schema
migration and no code change.

**`unrecorded_fields`.** Path A pass 3 records `{type, dueDate, principal}` on a
DISBURSEMENT row and **not** that row's balance; pass 3b records it. Filling that cell from
the contract's rule "it equals the principal advanced" would be *deriving* a value and
storing it as an *observation*, and the port would then be graded against the harness's own
assumption. So a cell nobody observed is declared unrecorded, skipped, and counted — the
report prints graded vs ungraded cells, so coverage is a number rather than an impression.

**`*_major_text` transcription cross-check.** Three optional fields per row carry the
oracle's own emitted characters in major units; the harness re-derives the integer from them
by exact integer/string arithmetic and marks the vector INADMISSIBLE on disagreement. This
catches a promotion slip that no other check can see. Decimal text is **never** compared
against an implementation and **never** given a tolerance — T17-F6: a truncated 12-dp
transcription hides divergence in digits 13+.

**Refusal is a first-class outcome** with its own column, its own tally and a per-reason
"how this retires" line, because the reasons retire differently: `SEAM_BLIND` needs a
**re-capture** (promoting from that seam cannot help), `UNGRADED_CAPABILITY` needs a
**promotion**, `UNGRADED_REQUEST` needs the graded domain **widened**.

**The harness contains no schedule generation and no date stepping.** The graded domain's
window predicate needs the last repayment due date; the harness *reads* it from the expected
schedule, or from `expect.last_repayment_due_date` on a refusal vector. Computing it would
mean implementing the month-end rule — that is T10's, and a harness the port could borrow
from is not an independent harness. `impl_hook.go` is deliberately empty for the same
reason: a stub generator there to "make the harness runnable" is the first thing a later
task would borrow.

### Where I improved on the original spec, and why

| change | why |
|---|---|
| Money as integer **strings**, not ints | the spec allowed either; `jq` and most readers turn JSON numbers into doubles |
| added `unrecorded_fields` | pass 3 does not record the disbursement row's balance; without this the promotion task must fabricate or drop the row |
| added `*_major_text` + exact re-derivation | makes the promotion step's arithmetic mechanically auditable |
| added `capture_case_id` | Path A captures are bundles; a file path is not provenance |
| added the `contract-refusal` class | the spec had PASS/FAIL/refused as *harness* outcomes; making a mandated refusal a **gradeable vector** means the graded domain's boundary is itself graded, and it needs no oracle |
| capability registry as **data** with 4 statuses + default-deny | the task's core instruction: a third blind spot must slot in without a schema migration |
| store-level `PIN.json` with `contract_sha256` | the contract says a shape change invalidates the corpus; this is that sentence, mechanised, and re-stamping is one edit not N |
| `--prove` in the shell | T9 gets one command; a harness whose author never proved it can go red is not finished |
| `--self-test` + replay implementation | the only honest way to prove red/green with no port in existence |
| oracle probe **defaults to down** | a forgotten probe must not be able to produce exit 0 |

## Schema change forced by T55-N1

The driver's mid-task update said, correctly, that the intuitive filter for gradeability —
*"two captures differing only in that setting differ in some money cell"* — is **false in both
directions**, and asked for a `graded-against` shape instead.

**What my committed design already had right, and what it did not.** My schema never modelled
pair difference — there was no "pair" concept anywhere, and `capabilities_required` ×
per-seam status is orthogonal to it. So nothing had to be undone. But it also could not
**express** what the incoming corpus grades: it recorded *which capability a vector exercises*
and not *which wrong implementations its observed value kills*. On `LB-DEC31` those differ
sharply — the capability is exercised, the pair is identical, and the value still kills a
no-arm port by 6,015 minor units. That is a genuine expressive gap, and it is now closed.

### What changed

1. **`graded_against[]` on every vector** — `{id, capability, description, margin_minor,
   evidence}`. **Required and non-empty on a parity vector**: a parity vector that kills no
   named candidate defect is a capture, not a grader. Enforced further: the `capability` must
   exist in the registry *and* appear in `capabilities_required` (a vector cannot grade what
   it does not claim to exercise), and `margin_minor` must be an integer string **> 0** —
   a candidate separated by **zero** is a candidate the vector does **not** kill, and
   admitting one would reintroduce precisely the false confidence the field exists to remove.
2. **`ErrNoDiscriminatingVector` now keys off counterfactual coverage.**
   `CapabilityRegistry.CounterfactualCoverage` asks, for every capability marked
   `in_graded_domain`, whether some *admissible parity* vector names a wrong implementation it
   kills. **An `in_graded_domain` capability with no coverage is a fatal, reported, unbacked
   claim** (exit 2). Today that is `schedule.core` and `monthend.reanchor`, which is honest:
   nothing is promoted, so nothing is backed. The report prints the whole table.
3. **`retires_when_capability_graded` on refusal vectors**, so **nothing hard-codes ACT/ACT as
   refused**. `REFUSE-01` names `daycount.actual.actual`; flip
   `in_graded_domain` in `capabilities.json` and the harness reports
   `STALE REFUSAL VECTOR — retire it`, an *actionable* message, instead of a FAIL that sends a
   reader hunting for a defect in a port that is behaving correctly.
   `TestStaleRefusalVectorIsDetected` flips the flag in a copied store and asserts exactly
   that. `REFUSE-03` deliberately leaves the field **empty**, and says why in a `_note`:
   annual frequency on the fixed-30/360 arm makes the oracle **throw**, so that refusal stands
   on `ErrUnsupportedConfiguration` whatever the graded domain admits — what it grades is the
   error-*precedence* rule, which does not retire.
4. **The T48-N4 promotion condition is corrected** in `capabilities.json` to *"the period must
   **span two calendar years of differing length**"*, citing **T55-N1, driver-re-derived**, with
   the reason recorded (the PLAIN branch takes its single denominator from the *period-start*
   year, 366, while the ARM assigns days to the year they fall in, 365, so a zero-length first
   segment still moves the result) and an explicit note that **DEC-1's wording is under gate
   and was not touched.** The old wording appears nowhere in anything I wrote.
5. **The report gained a `WHAT THIS RUN DOES NOT GRADE` section.** Recording
   `(19, HALF_UP)` in both dimensions stays mandatory — comparability, and the probe guard —
   but T55 witnessed no shape separating precision 19 from 12 or HALF_UP from HALF_EVEN
   (29 of 36 periods agree at all of them; precision **8** does separate, 22 of 36). So the
   setting is **provenance, not a graded claim**, and the harness now says so on every run
   rather than letting a reader infer that a recorded setting was proven.
6. **`_note`** — free prose on a vector, never graded and never parsed, so a maintainer can
   record *why* a field is set the way it is next to the field.

**How the schema expresses each fact the task required:**

* **gradeability, which is NOT pair difference** — `graded_against[]` names the wrong
  implementations a vector kills with a minor-unit margin each, and
  `CounterfactualCoverage` is what decides whether a capability's `in_graded_domain` claim is
  backed. **Asked for explicitly, and adopted: the schema expresses it.** My committed design
  never modelled pair difference — there is no "pair" concept in it — but it also could not
  *name* what a vector kills, and on `LB-DEC31` the two come apart completely (capability
  exercised, pair identical, 6,015 minor units of grading power). That gap is closed, and
  `TestGradeabilityIsNotPairDifference` pins it.
* **probe vs parity** — `oracle.threaded_mathcontext` and `oracle.ambient_mathcontext`, both
  required to equal `(19, HALF_UP)` for `class: parity`, cross-checked against
  `request.rounding`, plus `PIN.json.never_promotable_capture_case_ids`. Structural: the
  check is on the settings the numbers were produced at. `TestProbeCannotMasqueradeAsParity`
  builds a precision-12 vector labelled `parity` and asserts it is INADMISSIBLE.
* **path / capability blindness, charges AND holidays** — `capabilities_required` on the
  vector × per-seam `status` in `capabilities.json`, default-deny.
  `TestSeamBlindnessRefuses` asserts: charges on Path A → `SEAM_BLIND`; holiday adjustment
  on Path A → `SEAM_BLIND`; working-day adjustment on Path A → `SEAM_BLIND`;
  `installmentAmountInMultiplesOf` on Path A → `SEAM_BLIND`; **holiday adjustment on Path B
  → also refused, because its status is `partial`** (finding D-2a, final period only);
  charges on Path B → `UNGRADED_CAPABILITY`; ACT/ACT on Path A → `UNGRADED_CAPABILITY`; an
  unaudited capability on Path A2 → `UNKNOWN_CAPABILITY`.
  **A charge-, holiday- or working-day-bearing case graded against a Path A capture is
  refused, not passed** — asked for explicitly in `## Corpus fit`, and it holds.
* **precision / mode in force** — recorded per vector in two dimensions and re-validated;
  a parity vector at any other setting is INADMISSIBLE, not FAIL.
* **the pinned commit** — `oracle.fineract_commit` per vector, checked against
  `PIN.json.fineract_commit` (`426a23544e8426a38ae43ae404670a0a7e85b9eb`); a capture from
  another build is INADMISSIBLE with "NOT COMPARABLE" in the message.

## Money-math notes

* Every monetary value in the store and in the harness is an `int64` count of minor units,
  reached only through canonical base-10 string parsing. No `float32`, `float64`,
  `big.Float`, decimal-float or `ParseFloat` anywhere in the loanschedule tree — asserted by
  `TestNoFloatInTheLoanScheduleTree`, which scans the **token stream** and inspects only
  identifiers.
  *That guard used to be a byte grep and it fired on `contract.go`, because the contract's
  doc comments NAME the forbidden types in order to forbid them. A guard that fires on the
  sentence prohibiting the thing is a guard somebody switches off — and switching that one
  off would remove the most important check in the repository. Hence tokens.*
* `MinorFromMajorText` converts the oracle's major-unit wire text to minor units with string
  and integer arithmetic only. Short fractions are zero-padded; trailing zeros beyond the
  currency scale are accepted (the corpus emits scale 0, 2 and 6 for the same kind of
  quantity); a **significant** digit beyond the scale is an **error, never rounded** —
  rounding a transcription would invent a value the oracle never emitted, and the rounding
  decision belongs to the calculation.
* Rates are exact rationals in lowest terms with a positive denominator. 21.6% is `27/125`,
  not `0.216` and not 2160 basis points.
* Direction is the row's `Kind`, never a sign bit. `principal_portions_sum_to_disbursed`
  compares two sums rather than summing one column, which is the discipline the contract's
  own comment demands of a consumer.
* No monetary value is ever compared with a tolerance. Every comparison is `int64 ==`.
* The invariants assert only what the ratified contract already states. `balance_roll_forward`
  deliberately **does not** assert the DOWN_PAYMENT rule: it is specified from source but
  UNGRADED (no capture has ever produced such a row), and asserting an ungraded rule as
  though it were established is the failure mode this program exists to prevent.
* `splits_sum_to_whole` reports **N/A** rather than passing when no observed total exists,
  because `p + i == p + i` is not a test. The contract has no total field on purpose, so the
  independent total comes from the capture.
