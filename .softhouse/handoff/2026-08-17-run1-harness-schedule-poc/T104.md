## Findings (none is a defect in shipped code)

* **F-T104-1 (P2).** T90's sweep says "`_test.go` files, for map ranges — none (the three `range` hits
  there are slice ranges)". **False**: `main`'s test corpus has 40 `range` hits, three of them over
  maps (`structural_test.go:116`, `:121`, `:954` `keysOf`). The sentence describes T90's *own new file*
  while scoping itself to all test files. Consequence is nil (test-only, failure-path-only, cannot
  reach the report), but it is a sweep-completeness claim inside a sweep-completeness section — P-21's
  exact shape. **Driver: amend that line at source on merge.**
* **F-T104-2 (P2).** The `vector.go` `path` tie-break **did not go red**. With T90's map fixes in and
  only that key reverted, a constructed duplicate-`case_id` store gave **40/40 byte-identical** runs:
  `os.ReadDir` is filename-sorted and pdqsort is deterministic, so a tie resolves identically each run
  on go1.26.6. T90's own wording is careful and correct and it shipped no guard for it, so nothing is
  believed on faith — recorded so nobody later promotes site 4 to "a fourth nondeterminism fixed". The
  key is still worth keeping.
* **F-T104-3 (P1).** A duplicate `case_id` is **silently graded**: my dup store reports
  `43 parity vectors / 5623 graded cells / VERDICT PASS / exit 0`, with no warning anywhere. Those are
  the two numbers this program quotes as its coverage evidence. T90 filed this as F-T90-1 and rightly
  declined to fix it inside a determinism task; I disagree only on severity. **Raise F-T90-1 to a
  task**, with rejection as a `LoadStore` fatal reason (exit 2), never a silent dedup. T90's change
  does not mask it — the counts move either way.
* **F-T104-4 (advisory).** The 30-run binary experiment is the weakest instrument here: at the low end
  of the observed minority frequencies a 30-run batch has ~1-in-8 odds of showing a single sha256 and
  falsely certifying `main` deterministic. Use N ≥ 100, or use the unit guard (12 keys, 200 renders),
  which is effectively certain.
* **F-T104-5 (nit).** `report.go`'s comment freezes "split 26/4" into source; the split is not
  reproducible. Comments do not move report bytes, so it is a safe edit if the driver wants it. Not
  raised to a MICRO-FIX.
