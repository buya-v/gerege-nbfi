## The positive probe — what value, why only a working psub produces it

The old probe asked **"did a process-substitution command FAIL?"** and admitted the shell when
the answer was no. `false` is the answer both when the construct works *and* when the command
never executed, so the guard could not tell those apart — and a shell in the second state is
exactly as unable to run this harness as one in the first.

The new probe asks **"did the string `conformance-psub-live` come back?"**

- The literal exists in exactly one place at probe time: on the **write side** of the process
  substitution, as the argument to `builtin printf` inside `<(…)`.
- It reaches `conformance_psub_seen` by exactly one route: the `< <(…)` redirection connecting
  that subprocess's stdout to `read`'s stdin, and `read` storing it.
- The guard proceeds only on `[ "$conformance_psub_seen" = "$CONFORMANCE_PSUB_TOKEN" ]`.

So every way of *not running the probe* — a syntax error at `<(`, a redirection the shell
refuses, a subshell killed by POSIX mode's special-builtin abort, a shell that never reached
the line — leaves `conformance_psub_seen` empty and **fails closed**. There is no "absence of
failure" for the guard to mistake for success.

Row [5] of the proof script is this property stated as a test: it rewrites the probe's
`< <(builtin printf …)` to `< /dev/null` in a copy of the harness — so the `read` succeeds,
`read`'s *status* is 0, and only the **value** is wrong — and requires exit 3. The old
negative test would have admitted that copy.

**Details that are load-bearing, and the one that broke T86's own first draft:**

- **`printf '%s\n'`, with the newline.** T86's replacement line falsely refused plain bash
  because it lacked one. The mechanism: `while read -r x; do …; done < <(printf %s value)`
  reads a final line with no terminator, `read` returns non-zero, the loop body never runs, and
  healthy bash is refused. This probe uses a single `read` and grades the **variable**, never
  `read`'s status, so it is immune either way — but the newline is there so nothing downstream
  inherits the trap.
- **`IFS=`** stops an inherited hostile `IFS` from splitting the token away
  [VERIFIED: `IFS=oc`, `IFS=' '`, `IFS=$'\n'` in the environment — all ADMITTED].
- **`builtin`** pins `eval`/`read`/`printf` to bash's own. Not decoration: with a bare `eval`,
  an exported `eval()` function made bash 5.2.37 **refuse**, and that would have been a false
  refusal. I measured it both ways [see the hostile-environment matrix below].
- **Command substitution, not a plain subshell.** A shell that aborts on a syntax error inside
  `eval` (POSIX mode's treatment of a special builtin) kills only the `$( … )` subshell; the
  outer script survives to print the refusal. That is what makes `/bin/sh` on macOS emit the
  banner and exit 3 rather than dying silently.
