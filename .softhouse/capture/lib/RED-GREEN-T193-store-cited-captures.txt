WHAT THIS ARM DOES NOT CLAIM, PRINTED ON EVERY RUN

  * Cells OUTSIDE a recorded-request block are READ AND COUNTED but do not decide the verdict.
    Measured on the clean tree: 2886 such tokens, of which 59 are not byte-preserved — all 59
    in .softhouse/capture/pathb/t149/out/gerege/T149-TIE-P9-raw.json (`1162502.50` ->
    `1162502.5`, `0.00` -> `0.0`). They are ORACLE OBSERVATIONS. T186 §7 A4 forbids rewriting,
    re-emitting or scale-normalising one — the scale is itself an observation — so byte
    fidelity is the wrong VERDICT property for them. The count is printed so the blind spot is
    stated rather than implied.
  * One cited record carries no recorded-request block at all
    (T149-TIE-P9-raw.json, a Path B response record). It is NAMED on every run. Its request
    body is a separate file, .softhouse/capture/pathb/t149/req/calc-t149-tie-p9.json, which is
    in the 320-body population above — so that vector's request IS graded, by the other arm.
  * The arm grades the RECORD of the request, not the Java that generated it. A
    `Capture3*.java` that computed a wrong number and then faithfully recorded it is invisible
    here. See the T193 handoff for what a source-level lint on that path would and would not
    be able to decide.
