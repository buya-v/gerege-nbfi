THIS VECTOR IS GRADED BY REPLAY AGAINST A PORT. THE RELATION IS WHAT IT ASSERTS, NOT THE CALENDAR. Given a tenant whose latest GLClosure for the entry's office has closing date C, whose business date is B, and a balanced manual journal entry dated T with C < T <= B: THE ORACLE ACCEPTS IT WITH HTTP 200 AND WRITES ONE JOURNAL ENTRY PER REQUEST LEG, no contra expansion, each carrying entry_date == T. Here C = 2026-08-26, T = 2026-08-27, B = 2026-08-28, all calendar dates in Asia/Ulaanbaatar (+08), the tenant zone. No calendar can falsify that relation and it is what a port is graded on; the LITERAL dates are the instance of it that was observed.

RE-DERIVATION RUNS THE RECIPE, NOT A RE-READ OF A TENANT. `bash .softhouse/capture/t327-closure-accepting-side/throwaway/run-all.sh` rebuilds a throwaway instance from the same image, replays the setup campaign, creates a GLClosure at (today in Asia/Ulaanbaatar) - 2, and fires the same body dated (today) - 1. It must reproduce every graded cell of this vector: HTTP 200, and THREE journal entries on one transaction in this order -- DEBIT 250000.250000 on T327-1000, DEBIT 100000.370000 on T327-1100, CREDIT 350000.620000 on T327-2000, i.e. 25000025 / 10000037 / 35000062 minor units, totals 35000062 and 35000062. WHAT IT CANNOT REPRODUCE BYTE-FOR-BYTE, DELIBERATELY: the transaction id (server-assigned, not a graded cell), the captured-at timestamp, and THE THREE DATES -- the recipe computes them relative to the day it runs, which is the only way an entry dated on the accepting side of a live closure can be produced at all. A re-run therefore reproduces the RELATION with different literals, and the rebuild of this vector from those bytes would carry the new literals. That is T289's date strategy (c) and it is why the relation above, not the literals, is the assertion.

THE INSTANCE IT WAS TAKEN ON NO LONGER EXISTS, BY DESIGN. An accepted journal entry is a posted journal entry; Fineract has no delete path for one and the only "undo" is posting more entries. The only reversible place to take an accepting-side observation is a place that can be destroyed. `docker compose down -v` ran in the same run with no named volume declared, and the standing reference oracle's counters were identical before, during and after.

THIS VECTOR MUST NEVER BE RE-FIRED AT THE STANDING REFERENCE ORACLE. Its body is a valid, balanced, postable manual journal entry against GL accounts that do not exist on tenant `gerege`; re-sending it would either 404 on the chart or, if a reader "helpfully" remapped the accounts, POST THREE UNDELETABLE JOURNAL ENTRIES INTO THE ORACLE THIS PROGRAM GRADES AGAINST.

IF A FUTURE FINERACT REFUSES AN ENTRY DATED STRICTLY AFTER THE LATEST CLOSING DATE, OR WRITES A NUMBER OF ENTRIES OTHER THAN ONE PER REQUEST LEG, THIS VECTOR IS FALSE AND MUST BE RETIRED, NOT EXEMPTED (P-8: re-observe rather than exempt).
