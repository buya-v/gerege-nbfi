# T164 — DECLARATION REGISTER for json.load/loads call sites that do not carry parse_float=.
#
# Read and ENFORCED by guard-parse-float-ast.py. This is not an allowlist.
#
# FORMAT (6 or 7 pipe-separated fields; `#` starts a comment; blank lines ignored):
#
#   file | line | category | pinned source text | detail | reason [| frozen-sha256]
#
# Field 7 (T270) is the DURABLE PIN — see FROZEN-T114 below. Six fields is still accepted,
# because T164's frozen red-driver appends 6-field records and its committed transcript
# must stay re-derivable under T114; a 6-field FROZEN record is graded and printed as
# `MANIFEST-ONLY -- WEAK` on every run rather than silently treated as equivalent.
#
# WHY A REGISTER EXISTS AT ALL
# ----------------------------
# T207 ruled that "add parse_float" is sometimes the WRONG repair. A script whose job is
# to REPRODUCE a target that loads without parse_float must keep loading the same way, or
# it stops reproducing and its published figure becomes a claim about a tool that does not
# exist. And T114 rules that a script which produced COMMITTED EVIDENCE is not edited in
# place at all. Both cases need a way to be DECLARED. Neither may become a silent skip.
#
# HOW IT IS KEPT HONEST — every one of these is checked on every run
# ------------------------------------------------------------------
#   DEFAULT-DENY   a site absent from this file with no parse_float is a FAIL. An
#                  unrecognised category is a REFUSAL (exit 2), not a skip.
#   ENUMERABLE     every record below is printed in full on every run, with its
#                  precondition outcome. There is no quiet entry.
#   PINNED         field 4 is the exact stripped source of the line. If the line moves or
#                  changes, the record stops matching and the guard REFUSES.
#   STALE = ERROR  a record naming a site that does not exist, or a site that NOW carries
#                  parse_float, is a REFUSAL. Records cannot rot into noise.
#   PRECONDITIONED
#     FROZEN-T114        detail = produced:<committed evidence path>. Valid ONLY while
#                        the evidence exists, is itself pinned in MANIFEST.sha256, the
#                        file is TRACKED IN GIT, and the file's sha256 still equals BOTH
#                        the digest MANIFEST.sha256 pins AND the digest in field 7.
#     REPRODUCTION-T207  detail = reproduces:<path>:<line>. Valid ONLY while that target
#                        still has a json.load/loads at that line and STILL LACKS
#                        parse_float. Fix the target and the exemption dies. The target
#                        MUST be repo-relative: an absolute path, or one that escapes the
#                        root after realpath normalisation, is REFUSED (T263 F-6 — an
#                        untracked out-of-tree file must not license an in-tree float).
#
# CORRECTION, T270 — THE PREVIOUS VERSION OF THIS FILE OVERSTATED ITS OWN GUARANTEE.
# --------------------------------------------------------------------------------
# It said, of FROZEN-T114: "Edit the file and the exemption dies with it." T263 MEASURED
# that end to end (ATTACK-REVIVE.txt) and the claim does not survive: the exemption dies,
# but it does not STAY dead. `MANIFEST.sha256` is not immutable — `manifest.py write`
# regenerates it, and T164's own task ran that command. Edit a frozen file, exit 2; run
# `manifest.py write`; exit 0 again, with the edit still in place. A death condition any
# worker undoes with one routine command is a speed bump, not a guard.
#
# WHAT T270 CHANGED, AND WHAT IS STILL ONLY A DIFF REVIEW:
#   * FIXED — field 7 pins the frozen digest IN THIS FILE. `manifest.py write` cannot
#     touch it, so reviving a dead exemption now needs a SECOND, deliberate edit here,
#     which shows up in `git diff` on the register rather than in a routine manifest churn.
#   * FIXED — `reproduces:` no longer accepts an absolute or root-escaping path.
#   * RAISED, NOT CLOSED — minting a brand-new exemption (T263 F-4 R2). The exempted file
#     must now be git-tracked and the named evidence must be MANIFEST-pinned, so it can no
#     longer be done with an untracked file. It can still be done by someone willing to
#     commit the file and cite evidence it did not produce. The remaining control is
#     review of the diff, and that is stated here rather than implied away.
#   * NOT FIXABLE MECHANICALLY, GRADED INSTEAD — `produced:` provenance. T263 F-5 proposed
#     requiring the exempted file's name to occur in the evidence it names, saying this
#     "holds for all six live records today". T270 RE-DERIVED THAT AND IT IS FALSE: it
#     holds for 3 of 6 (the RED-GREEN-A2-7-guards.txt records, whose line 3 reads
#     `Produced by:  python3 prove-mkreq7-guard-red.py`). It does NOT hold for
#     req/a2-7-loan-220-resolved.json (a request body) or PROVENANCE-A2-15.txt, and no
#     rewriting of those would make it hold, because a JSON request body has nowhere to
#     name its producer. So the check is not enforced; instead every record is GRADED
#     `evidence NAMES its producer` or `ASSERTED ONLY` and the grade is printed on every
#     run. An unverifiable field that says so is honest; one that reads as an audit trail
#     and is not one is the defect.
#
