WHAT WAS WRONG, AND IT WAS THE INSTRUMENT, NOT THE GUARD
--------------------------------------------------------
The first draft had no `setup_<arm>` hook, so every arm built its ENTIRE state inside
the attested window. Three damage arms therefore asked the guard a question to which 0
was the correct answer:

  D4  committed one commit and then `reset --hard HEAD~1` back to the BYTE-IDENTICAL
      starting state. Nothing had moved between the two snapshots. T318's A4 resets to a
      DIFFERENT non-descendant; mine returned to the origin.
  D8  created softhouse/T995-unmerged AND deleted it inside the window, so the ref is in
      NEITHER snapshot and no two-point differential can see it.
  D9  same shape: the branch was created and force-moved inside the window, so it read as
      a NEW ref (authorized by --allow-new-ref), not as a rewound one.
  M1  depended on L1's `git branch -d`, and L1 created that branch inside the window too.
  M4  is D8 under a different writ; it inherited D8's defect.

FIX: a `setup_<arm>` function that runs BEFORE the baseline snapshot, and the pre-existing
state moved into it. That is also the more faithful fixture — the branches a fire's prune
sweep deletes were created by EARLIER fires, not by the one being attested.

WHAT IT TAUGHT, WHICH IS NOW ARM R1: a ref created and destroyed entirely inside one
window is invisible to any two-point differential. That is a real residual gap; it is now
a declared, driven row that PASSES while the limitation reproduces and FAILS LOUDLY if a
term is ever added that sees it. Closing it would require the reflog or `git fsck`
dangling objects, both of which T318 excluded with reasons that still stand.
