=== T161 — the start-up and pin branches the seven interruption cases never execute
===================================================================================
P-22: a branch that has never been executed is a guard that cannot fail.  The seven
interruption classes in `F1-recovery-redgreen.txt` all take the same path through the
start-up block (no marker present) and the same path through the pin (the attester matches
the index).  Four branches are therefore never reached by them, and are driven here:

  A  the attester is LOCALLY MODIFIED when the window opens.  The pin must then be a NEW
     blob written with `git hash-object -w`, and the restore must give back the MODIFIED
     bytes — silently reverting a local edit to the index would be its own data loss.
  B  the marker names a blob that is not in the object store  -> refuse, touch nothing.
  C  the marker's recorded digest is already the file's digest -> the IDEMPOTENT no-op,
     i.e. running the restore twice is safe.
  D  the marker's blob does not hash to the recorded sha256   -> refuse, touch nothing.

B and D are the two ways the recovery could restore bytes it cannot identify.  Both must
fail closed and leave the attester exactly as found; both are checked for that, not merely
for a non-zero exit.

Sandbox: a throwaway `git clone --shared` of the T161 branch.  The real rig is never used.
Driver: /tmp scratch harness (not committed; it only plants a marker and reads digests).
