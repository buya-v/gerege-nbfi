  NOTE on m_pin_float — MEASURED, AND IT REFUTED MY OWN FIRST DRAFT.
  I wrote 'wanted PRE 0' on the reasoning that no store-root .json was decoded by Go, so a float
  in PIN.json could only be caught by the shell guard. The PRE binary refuses it at exit 2 saying
  FLOAT TOKEN "19.0" — because LoadPin (admit.go:58) and LoadCapabilityRegistry
  (capability.go:110) ALREADY call RejectFloatTokens on their own bytes. So M-5's sentence is true
  only for a store-root .json that is NEITHER of those two, which is exactly what the rows above
  it demonstrate and exactly what the census now refuses. The expectation was corrected to the
  measurement and the census comment was corrected too; the code was not adjusted to fit a guess.
  What the census adds for PIN.json and capabilities.json is therefore belt and braces: the check
  now also runs under LoadStore alone (how every test reaches the store), and it binds any file
  later added to the allowlist rather than depending on its loader remembering to check.
