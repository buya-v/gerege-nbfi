  LOOK FOR A ROW THAT IS NEITHER 'ORIG' NOR 'MARK'. If one is there, zsh did not
  swap cleanly at a line boundary: its read buffer ENDED IN THE MIDDLE OF A TOKEN,
  and it completed that token from the REWRITTEN file -- a SPLICE of old bytes and
  new. Here the splice fell inside a quoted string so it printed harmlessly. In a
  real script the same splice can fall inside a command name, a variable name, an
  `if`/`fi`, or a heredoc delimiter, and then it is a syntax error or a WRONG
  COMMAND. Note this happened on an EQUAL-LENGTH edit: nothing shifted at all.
